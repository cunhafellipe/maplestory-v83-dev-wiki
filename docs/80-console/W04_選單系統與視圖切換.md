### W04-001　用 `VBox` 當左側選單容器，逐顆把按鈕加進去

- **關鍵字**：`VBox` `menuVBox` `getChildren().add` `側邊欄` `垂直排列`
- **來源**：第四課 11:20–13:20、13:20–15:20｜`L04_第四课_教學筆記.md`
- **要點**：左側選單因為是垂直排列，容器選 `VBox`，命名 `menuVBox`。
  每顆選單按鈕建好之後 `menuVBox.getChildren().add(menuButton)` 逐顆掛進去。
  本課的實際演進是「原本裝載按鈕的容器是水平 `HBox`，後來改成垂直 `VBox`」。
- **程式碼**：

  ```java
  VBox menuVBox = new VBox();
  ...
      menuVBox.getChildren().add(menuButton);
  ```

- **坑**：⚠️ `getChildren().add(...)` **只接受一個子節點**，多個要用 `addAll`。
  本課口述明說「我們這裡報錯了，是因為我們沒有 `addAll`」。
  口述也提到 `stageBody` 內容不止選單，所以「我們這裡提前就 `addAll` 了」——
  `stageBody` 那時先只放 `menuVBox`，右側內容之後再一起 `addAll`。
- **相關**：見 W02-007

### W04-002　`setSpacing` 管元件之間、`setPadding` 管到四周，兩者是不同的事

- **關鍵字**：`setSpacing` `setPadding` `Insets` `menuVBox` `間距` `內距` `上右下左`
- **來源**：第四課 13:20–15:20｜`L04_第四课_教學筆記.md`
- **要點**：講者特別澄清過這兩者的差別，原話：「首先就把每一個菜單的間隔給它設置一下……
  **不是 `padding`，`setSpacing`。設置每一個子組件之間內部的間格為 5 個像素**……
  然後我們再設置一下 `padding`。就是設置子組件到四周的一個距離。」
  前者管按鈕與按鈕之間的垂直間距，後者管按鈕群到容器四邊的內距。
- **程式碼**：

  ```java
  VBox menuVBox = new VBox();
  menuVBox.setSpacing(5); // 設定按鈕之間的垂直間距
  menuVBox.setPadding(new Insets(10, 0, 0, 10)); // 設定上右下左的內邊距
  // ⚠️ 衝突未解決：口述為「四邊距離都設置為 10」（應為 new Insets(10)），
  //    此四參數非對稱值取自畫面 video_s02，兩者不一致。
  ```

- **坑**：⚠️ **`setPadding` 的值有未解決衝突，本筆記未裁定。**
  口述是「設置子組件到四周的一個距離。我們設置為 10」（即 `new Insets(10)`，四邊皆 10）；
  但程式碼三處（L04 第 188／363／486／549 行）與速查表採的是畫面讀到的
  **四參數非對稱值 `new Insets(10, 0, 0, 10)`**（上 10、右 0、下 0、左 10）。
  **兩邊都保留，引用時請註明出處，不要當成定論。**
- **相關**：見 W02-010

### W04-003　每個選單項做成 `ToggleButton`，全部收進同一個 `ToggleGroup`

- **關鍵字**：`ToggleButton` `ToggleGroup` `setToggleGroup` `menuGroup` `單選互斥`
- **來源**：第四課 00:40–03:40、11:20–13:20｜`L04_第四课_教學筆記.md`
- **要點**：選單按鈕用 `ToggleButton`（帶選中狀態的按鈕），並在迴圈外先建一個
  `ToggleGroup`，每顆按鈕都 `setToggleGroup(menuGroup)`。
  口述原理：「你單選一個，它會把其它的 Button 的選中狀態設置為未選中。」
  課堂一開始的示範就是在一個 `FlowPane` 裡用 for 迴圈生出 5 顆 `ToggleButton` 並綁同一組。
- **程式碼**：

  ```java
  ToggleGroup menuGroup = new ToggleGroup();

  for (MenuEnum menu : MenuEnum.values()) {
      ToggleButton menuButton = new ToggleButton(menu.getName());
      menuButton.setToggleGroup(menuGroup);
      menuVBox.getChildren().add(menuButton);
  }
  ```

  課堂示範版（`Console.java`）：

  ```java
  ToggleGroup toggleGroup = new ToggleGroup();
  for (int i = 1; i <= 5; i++) {
      ToggleButton toggleButton = new ToggleButton("toggleButton");
      // 稍後在 01:22 將上一行修改為，加上數字以利辨識：
      // ToggleButton toggleButton = new ToggleButton("toggleButton" + i);

      toggleButton.setToggleGroup(toggleGroup);
      root.getChildren().add(toggleButton);
  }
  ```

- **坑**：⚠️ 口述說「我們的 `ToggleButton` 其實和我們的普通 `Button` 沒有什麼很大的區別」，
  差別在於它是「配合這個 `ToggleGroup` 來使用的」——**單用 `ToggleButton` 不會有互斥效果**。
  ⚠️ 示範段的按鈕數量與命名有出入：口述先說「加了六個 `Button`……`ToggleButton0` 到
  `ToggleButton5`」隨即自我更正「小於 5」；畫面描述的迴圈是 `for (int i = 1; i <= 5; i++)`，
  命名 `toggleButton1`～`toggleButton5`。**索引從 0 或 1 起有出入。**
- **相關**：見 W04-004

### W04-004　`ToggleButton` 可以被反選：群組互斥不等於「一定有一顆被選中」

- **關鍵字**：反選 `ToggleButton` `未選中` `互斥` `提前告知`

  `selectedProperty()` 監聽換色處理，見 W04-010）

  ```java

  ```

- **坑**：⚠️ **本條本身就是本課明示的坑**：

### W04-005　用 `MenuEnum` ＋ `values()` 動態生成側邊欄按鈕

- **關鍵字**：`MenuEnum` `values()` `getName()` `constant` `動態生成` `for-each`
- **來源**：第四課 07:20–09:20、09:20–11:20、11:20–13:20｜`L04_第四课_教學筆記.md`
- **要點**：口述決定「建一個 `constant` 的包，裡面專門放常量」，在其中定義列舉 `MenuEnum`。
  列舉帶一個 `private final String name` 欄位、建構子與 getter，
  之後用 `MenuEnum.values()` 迴圈動態生出每一顆 `ToggleButton`——**取代先前寫死按鈕的做法**，
  這是本課最大的結構性改動。getter 可用 IDE 的 `Alt+Insert` → `Generate Getters` 產生。
- **程式碼**：

  ```java
  package constant;   // 口述：建一個 constant 的包，裡面專門放常量

  public enum MenuEnum {
      OPERATE("服起停"),
      CONFIG("服配置"),
      PLAYER("玩家管理"),
      MERCHANT("商城管理"),
      COMMAND("指令管理"),
      // 口述提到還有「WD 配置」一項，具體常數名未定
      ;

      // name
      private final String name;

      // name 的建構子
      MenuEnum(String name) {
          this.name = name;
      }

      // 透過 IDE（Alt+Insert → Generate Getters）自動產生的 getter
      public String getName() {
          return name;
      }
  }
  ```

- **坑**：⚠️ **`MenuEnum` 的列舉常數兩組對不上（重要）。**
  口述列出 `operate`（服起停）、`config`（服配置）、`player`（玩家管理）、
  `merchant`（商城管理）、`command`（指令管理）、WD 配置；
  畫面 `v002` 卻給出 `OPERATE("服务器操作")`、`PLAYER("玩家数据")`、`GAMEDATA("游戏数据")`、
  `ROBOTMATE("防脱机检测")`、`COMPARE("安全与黑名单")`、`ALL("全部")`。
  兩組幾乎不重疊且畫面那組為簡體中文。**以口述那組為本課教學內容**，
  畫面那組疑為後續版本或辨識誤植。
  ⚠️ 套件位置也衝突：畫面層記為 `src/main/java/v0/enumtest/MenuEnum.java` 與
  `package v2.constant`；口述說 `constant` 包，**以口述為準**。
- **相關**：見 W14-008

### W04-006　`stageBody` 用 `HBox`：左邊選單、中間豎線、右邊內容

- **關鍵字**：`HBox` `stageBody` `Separator` `Orientation.VERTICAL` `左菜單右內容`
- **來源**：第四課 07:20–09:20、13:20–15:20、28:00–30:00｜`L04_第四课_教學筆記.md`
- **要點**：講者逐一比較過佈局管理器（`BorderPane`、流式佈局、`GridPane`、`HBox`、
  錨點佈局、`VBox`、`StackPane`），結論是「我就直接用最簡單的 HBox 吧。簡單好用」，
  口述判定 `VBox`「用不上」、`StackPane`「也用不上」。
  `stageBody` 是水平的 `HBox`，左邊放 `menuVBox`，右邊放內容，中間用垂直 `Separator` 隔開。
- **程式碼**：

  ```java
  HBox stageBody = new HBox();

  // 根節點依序組裝：標題列(窗頭) → 水平分隔線 → 窗體

  ```


- **坑**：⚠️ **畫面層與口述不一致**：片尾畫面 `v007` 出現 `sideBox` 與 `stackPane`，

  **畫面層的 `stackPane` 應為後續版本或辨識誤植。**

### W04-007　讓 `stageBody` 撐滿剩餘空間用 `HBox.setHgrow`，不是 `VBox.setVgrow`

- **關鍵字**：`HBox.setHgrow` `Priority.ALWAYS` `VBox.setVgrow` `撐滿剩餘空間` `top-center`
- **來源**：第四課 25:40–28:00、28:00–30:00｜`L04_第四课_教學筆記.md`
- **要點**：本課花了一整段 debug「居中對齊為什麼沒生效」——根因是
  `menuVBox` 本身只佔很小一塊，`stageBody` 沒有撐滿剩餘空間。
  修法是讓 `stageBody` 填滿 `root` 的所有剩餘空間，右側空白區才會延展。
- **程式碼**：

  ```java
  HBox.setHgrow(stageBody, Priority.ALWAYS);
  ```

- **坑**：⚠️ **明確的教學口誤／陷阱**：口述說的是 `VBox.setVgrow`，
  但被填充的容器 `stageBody` 是 **`HBox`**。JavaFX 的 grow 屬性必須與父容器類型對應，
  **`HBox` 只能用 `HBox.setHgrow(..., Priority.ALWAYS)`**；
  對 `HBox` 的子節點呼叫 `VBox.setVgrow` 不會生效。本頁程式碼骨架以畫面層的
  `HBox.setHgrow` 為準。
  ⚠️ 附帶的 debug 手法：用 `-fx-border-color: red; -fx-border-width: 1` 畫紅框
  量測元件實際邊界（本課實際這樣做，之後再刪掉）；對齊從置中改成 **`top-center`**
  （口述：「居中對齊在這裡看上去還行……但是在這裡居中對齊的話好像並不太好看」）。
- **相關**：見 W02-008

### W04-008　選單按鈕的基礎 CSS：透明背景、字級 14、粗體、固定寬高

- **關鍵字**：`setStyle` `-fx-background-color` `-fx-font-size` `-fx-font-weight` `-fx-pref-width` `-fx-pref-height` `transparent`
- **來源**：第四課 15:20–18:20、20:30–22:40｜`L04_第四课_教學筆記.md`
- **要點**：在 `MenuEnum.values()` 的迴圈內為每顆 `menuButton` 注入同一份 CSS。
  演進順序：先把預設背景設成 `transparent`、字體大小設 **14**（口述：「我們之前那個窗頭的
  字體大小是 16，那我們菜單肯定不會搞那麼大」）→ 再加 `-fx-font-weight: bold` →
  再把寬高接進同一份字串。
- **程式碼**：

  ```java
  // 基礎樣式（預設態）
  String BASE = "-fx-background-color: transparent; -fx-font-size: 14; "
              + "-fx-font-weight: bold; -fx-pref-width: 150; -fx-pref-height: 30;";
  // 口述：先試 150 覺得太大 → 改 100 → 最後仍定 150。
  // 畫面層記為 -fx-pref-width: 130；選此處以口述為準。
  menuButton.setStyle(BASE);
  ```

  課堂中實際逐次修改的樣式字串：

  ```java
  menuButton.setStyle("-fx-background-color: transparent; -fx-font-size: 14;");
  // 修改後
  menuButton.setStyle("-fx-background-color: transparent; -fx-font-size: 14;-fx-font-weight: bold;");
  // 完整字串
  "-fx-background-color: transparent; -fx-font-size: 14; -fx-font-weight: bold; -fx-pref-width: 130; -fx-pref-height: 30;"
  ```

- **坑**：⚠️ **按鈕寬／高有未解決衝突**：口述 `-prefWidth` 150 → 100 → 最後又改回 150、
  `prefHeight` 30；畫面描述為 `-fx-pref-width: 130`、`-fx-pref-height: 30`（`v005`）
  與 `-fx-pref-width: 150`、`-fx-pref-height: 50`（`v006`）。
  **寬度以口述最終值 150 為準，高度以口述 30 為準**，但兩層仍不一致。
  ⚠️ 講者結尾自我提醒：「注意一下別改錯了啊，別把別的東西給改了」——
  改 CSS 長字串時容易誤傷其他屬性。
- **相關**：見 W05（`setStyle` 整串覆寫的問題在第五課被解決，見 W04-011）

### W04-009　Hover 用 `setOnMouseEntered`／`setOnMouseExited` 動態換色，移出時要 `isSelected()` 保護

- **關鍵字**：`setOnMouseEntered` `setOnMouseExited` `isSelected` `-fx-text-fill` `hover` `rgb(0, 153, 255)`
- **來源**：第四課 18:20–20:30、25:40–28:00｜`L04_第四课_教學筆記.md`
- **要點**：滑鼠移入時換成藍底白字，移出時恢復原狀。
  口述：「但是我們移入的時候給了事件，移出的時候是不是要把它恢復成原狀呀？
  在 `setOnMouseExited`，`set style`，恢復原狀我們直接就把這個給複製一下、copy 一下就行了。」
  但**直接複製回基礎樣式會把選中態洗掉**，本課最後補上的關鍵判斷是先看 `isSelected()`。

### W04-013　`resolve()` 兩段式解析 inline style：`;` 切宣告、`:` 切 key/value

- **關鍵字**：`resolve` `split` `SEMICOLON` `COLON` `trim` `continue` `防呆` `keyValArr.length`
- **來源**：第五課 03:48–07:36、07:36–11:24｜`L05_第五课_教學筆記.md`
- **要點**：先把 style 字串讀進來，空字串直接跳過不解析；
  用 `;` 切開每一條 style 宣告，再用 `:` 切 key/value；
  **若切出來的長度不等於 2 就 `continue` 跳過**（講者：「保護一下，
  萬一它真的出現了那種這種 style 呢，說不定是你手抖少寫了什麼東西」）；
  最後 `trim()` 吃掉空白再 `put`。
  之後把這段邏輯抽成帶參數的 `resolve(String style)`，迴圈呼叫它。
- **程式碼**：

  ```java
  private void resolve(String style) {
      String paneStyle = pane.getStyle();
      if (MapElementUtils.isEmpty(paneStyle)) {
          return;
      }

      String[] styleArr = paneStyle.split(MapPane.SEMICOLON);
      for (String style : styleArr) {
          String[] keyValArr = style.split(MapPane.COLON);
          if (keyValArr.length != 2) {
              continue;
          }

          styleMap.put(keyValArr[0].trim(), keyValArr[1].trim());
      }
  }
  ```

  Extract Method 後（參數化版本，迴圈變數改名避免與參數衝突）：

  ```java

              continue;
          }

          styleMap.put(keyValArr[0].trim(), keyValArr[1].trim());

  }
  ```

### W04-014　`update` 收整串、`remove` 只需傳一個 key（`remove(keyValue[0])`）

- **關鍵字**：`update` `remove` `remove(keyValue[0])` `只傳 key` `相容` `delegate resolve`
- **來源**：第五課 11:24–15:12、15:12–19:00、19:00–22:48｜`L05_第五课_教學筆記.md`
- **要點**：`update` 接收完整的一整串（可含多組 `key:value`），直接委派給 `resolve(style)`。
  `remove` 有**特殊契約**：`update` 一定要傳完整的鍵值對，但 `remove` **只需要傳一個 key**
  就能把對應的鍵與值都刪掉；口述強調「**當然他傳一整個我們也兼容**」。
  實作上 `remove` 自己也走一遍切割流程，再依切出來的長度取 `[0]` 來刪。
- **程式碼**：

  ```java
  public void update(String style) {
      resolve(style);
  }
  ```

  ```java
  public void remove(String style) {
      String[] styleArr = style.split(MapEnum.SEMICOLON);
      for (String keyStyle : styleArr) {
          String[] keyValueArr = keyStyle.split(MapEnum.COLON);
          if (keyValueArr.length == 1 || keyValueArr.length == 2) {
              styleMap.remove(keyValueArr[0].trim());  // 長度 1 或 2 都取 [0]
          }
          // 長度 0（開頭多打分號）或 >= 3（異常 style）不解析
      }
  }
  ```

  畫面層版本（單一條件 `>= 1`）：

  ```java
  public void remove(String style) {
      String[] styleArr = style.split(HAppPane.SEMICOLON);
      for (String keyStyle : styleArr) {
          String[] keyValueArr = keyStyle.split(HAppPane.COLON);
          if (keyValueArr.length >= 1) {
              styleMap.remove(keyValueArr[0].trim());
          }
      }
  }
  ```

- **坑**：⚠️ **`remove` 的長度判斷有三種版本，行為不同**：
  口述是 `length == 1 || == 2`（其餘跳過）；畫面 `v004` 是 `>= 1`；
  畫面 `v009` 是 `>= 2`。**`v009` 要求必須帶冒號，會讓「只傳 key」失效，與口述契約相反。**
  套用時要依實際傳入格式挑選。
  ⚠️ 另有 `public void add(String k, String v) { }` 的空實作**只出現在畫面**，
  口述全程只說把「新增」改名為 `update`，a005 更明確說「這個 `add` 方法確實，
  沒什麼卵用，刪了吧」。**此方法應已廢棄。**

### W04-015　改完 `Map` 一定要再 `setStyle` 回去：`updateAndSet`／`removeAndSet`／`modifyAndSet`

### W04-016　要讓文字色回到預設，就 `remove("-fx-text-fill")` 而不是再 `update` 一個顏色

- **關鍵字**：`remove("-fx-text-fill")` `預設色` `卡住` `isSelected` `hover 蓋掉選取`
- **來源**：第五課 22:48–26:36、26:36–30:24｜`L05_第五课_教學筆記.md`
- **要點**：`update` 改過的屬性若沒設回預設值就會「卡住」——講者一開始讓文字色
  永遠停在 `white`，後來改用 **`remove("-fx-text-fill")`** 讓它回落到 CSS 預設色才解決。
  口述：「不需要把整個 Style 都給傳進去，`remove` 一個鍵就行了。」
  實測結果：移開或取消選取時背景恢復透明，**因為加了 `.remove("-fx-text-fill")`，
  文字顏色成功恢復原本的黑色**。
  另外四個狀態處理器都要加 `if (!menuButton.isSelected())` 保護，
  否則 hover 效果會蓋掉選取效果。
- **程式碼**：

  ```java
  // Hover 移出：背景改回 transparent，文字色直接 remove 掉以恢復預設
  menuButton.setOnMouseExited(event -> {
      if (!menuButton.selectedProperty().get()) {
          menuButton.getResolutionStyle().update("-fx-background-color: transparent");
          menuButton.getResolutionStyle().remove("-fx-text-fill");
      }
  });

  // 選中狀態改變
  menuButton.selectedProperty().addListener((observable, oldValue, newValue) -> {
      if (newValue) {
          menuButton.getResolutionStyle().update("-fx-background-color: rgb(200, 200, 200)");
          menuButton.getResolutionStyle().update("-fx-text-fill: white");
      } else {
          menuButton.getResolutionStyle().update("-fx-background-color: transparent");
          menuButton.getResolutionStyle().remove("-fx-text-fill");
      }
  });
  ```

  取用按鈕的樣式物件（Getter）：

  ```java
  // MenuButton.java
  public NodeStyle getResolutionStyle() {
      return resolutionStyle;
  }
  ```

- **坑**：⚠️ **`update` 過的屬性若沒還原就會卡住**——只 `update` 不 `remove`／不設回預設值，
  樣式會停在最後一次的狀態。
  ⚠️ **Hover 效果會蓋掉選取效果**：四個處理器都要加

### W04-018　`MenuEnum` 掛上對應的 `Class`，點選時反射 `newInstance()` 產出視圖

- **關鍵字**：`MenuEnum` `Class<? extends MenuAbstract>` `getClz()` `newInstance()` `反射` `泛型` `try-catch`
- **來源**：第六課 04:00–08:00、08:00–12:00、36:00–40:00｜`L06_第六课_教學筆記.md`
- **要點**：第一版方案是「Enum 綁 Class ＋ 介面」——在 `MenuEnum` 的每個項目後面
  掛上對應的實作類別（`MenuOperate` 已實作、其餘全綁 `MenuDefault` 佔位），
  點擊時用反射 `menu.getClz().newInstance()` 產生物件。
  欄位型別用 `Class<? extends MenuAbstract>` 限定型別安全，
  整段用 `try { ... } catch (Exception e)` 包起來。
  口述動機是解耦：`start` 方法已經 100 多行，
  若把所有選單內容塞進同一個類會膨脹到幾千行。
- **程式碼**：

  ```java
  // MenuEnum.java（抽象類別版）
  public enum MenuEnum {
      OPERATE("服务启停", MenuOperate.class),
      CONFIG("服务配置", MenuDefault.class),
      PLAYER("玩家管理", MenuDefault.class),
      MARRIAGE("结婚管理", MenuDefault.class),
      COMMAND("指令管理", MenuDefault.class),
      ALL("所有", MenuDefault.class);

      private final String name;
      private final Class<? extends MenuAbstract> clz;

      MenuEnum(String name, Class<? extends MenuAbstract> clz) {
          this.name = name;
          this.clz = clz;
      }

      public String getName() { return name; }

      public Class<? extends MenuAbstract> getClz() { return clz; }
  }
  ```

  ```java
  // ServerApp.java —— 最終版調用
  try {
      MenuAbstract instance = (MenuAbstract) menu.getClz().newInstance();
      instance.init(primaryStage, stageBody);   // 掛載交給父類做
      menuMap.put(menu.getName(), instance);
  } catch (Exception e) {
      log.error("初始化面板失败: {}", e.getMessage(), e);
  }
  ```

- **坑**：⚠️ **`Class.newInstance()` 已被 deprecated。**

  本片用 `try { ... } catch (Exception e)` 捕捉剛好能兜住，但寫法本身已過時。
  ⚠️ **泛型寫法有過渡痕跡**：IDE 一度報「需要的是一個 menu interface，提供的是 menu operator」，
  畫面層記到 `private final Class<? extends MenuInterface<?>> clz;`（再補一層 `<?>` 消警告），
  但 v000／v004 的 `MenuInterface` 明顯**沒有**型別參數。L06 判定實際寫法應是 raw type。
  ⚠️ **列舉內容不要當定案**：`MenuEnum` 的項目在片中反覆改檔
  （v000 為 `BASIC/ROLE/PACKET/POSITION/COMMAND/FLY_HUNG`；v001 為
  `OPERATE/CONFIG/PLAYER/MARRIAGE/COMMAND/ALL`；v010 出現 `PLAYER/GUILD/SHOP`；
  v012 出現 `CONSOLE("控制台", MenuConsole.class)`）。**`BASIC` 與 `OPERATE` 是兩代命名。**

  ```java
  selectedProperty().addListener((obs, oldValue, newValue) -> {
  ```

### W04-020　從 `MenuInterface` 改用 `MenuAbstract`：父類收攏生命週期，子類只寫 `show()`

- **關鍵字**：`MenuInterface` `MenuAbstract` `abstract show()` `init` `destroy` `setRoot` `Safe Delete` `樣板碼`
- **來源**：第六課 24:00–28:00、28:00–32:00、32:00–36:00、36:00–40:00｜`L06_第六课_教學筆記.md`
- **要點**：介面版被推翻的直接原因是**每個子類都要重寫相同的樣板碼**——
  所有子類的 `getRoot()` 都只是 `return root;`、`destroy()` 都只是 `root = null;`。
  改用抽象類別後，`init`／`destroy`／`setRoot` 收攏到父類，
  **子類只需實作抽象方法 `show()`**，把原本寫在 `init()` 裡的 UI 建立邏輯整段搬進 `show()`，
  結尾呼叫 `setRoot(root)` 交給父類管理。
  介面檔最後用 IDE 的 **Safe Delete** 強制刪除，`MenuEnum` 的欄位型別同步改綁 `MenuAbstract`。
  講者的權衡理由：「選單頁共用大量 `root`／生命週期邏輯，用抽象類別收攏，子類只寫 `show()`」。
- **程式碼**：

  ```java
  // MenuAbstract.java（分段演進）
  public abstract class MenuAbstract {
      private Region root;

      public void init() {
      }

      void destroy() {
      }

      Region getRoot() {
          return null; // 稍後補充
      }
  }
  ```

  ```java
  // init 加上參數（預留後期的副窗口綁定與父容器）
  public abstract class MenuAbstract {

      private Region root;
      private Stage primarystage; // 新增欄位

      public void init(Stage primarystage, HBox s) {
      }
      // ... 省略 destroy 與 getRoot
  }
  ```

  ```java
  // MenuOperate.java：implements → extends，UI 建立邏輯整段搬進 show()
  public class MenuOperate extends MenuAbstract {
      @Override
      public void show() {
          // BorderPane, HBox, Button, TextArea ...（原本寫在 init() 裡）
          setRoot(root);
      }
      // destroy() 與 getRoot() 已刪除，交由父類處理
  }
  ```

  ```java
  // MenuEnum.java —— 型別改綁抽象類別
  private Class<? extends MenuAbstract> clz;

  MenuEnum(String name, Class<? extends MenuAbstract> clz) { /* ... */ }
  public Class<? extends MenuAbstract> getClz() { /* ... */ }
  ```

- **坑**：⚠️ **`protected Region root` 會讓子類失去版面 API**——
  父類 `root` 若是 `protected` 且型別是 `Region`，子類呼叫 `setTop()`／`setCenter()`
  會「沒有這個方法」，強轉 `BorderPane` 又「好像不行」。
  最終解法是**父類 `root` 設 `private` 禁止子類訪問，子類自己再宣告一個 `root`，
  在 `show()` 結尾呼叫 `setRoot()` 交出去**——代價是 `root` 名稱重複。
  ⚠️ **不要把所有東西都寫成 `public`**（講者原話：「該用 protected 用 protected，
  該用 private 還是 private」）。本片的模範分工是：
  `init`／`destroy` 為 `public`（給 `ServerApp` 呼叫）、`setRoot` 為 `protected`（只給子類）、
  `root` 為 `private`。
  ⚠️ **不要對未使用的欄位聽從 IDE 的移除建議**：`primaryStage` 目前沒用到（會有 unused 警告），
  但後期開彈窗要用來設定父子視窗綁定，講者特別交代不要把它刪掉。
  ⚠️ **命名不一致（正文採畫面／程式碼語境的正確寫法，逐字稿保留原轉錄）**：
  口述出現 `ManualOperator`（a003）、「menu operator」、「menu defense」（疑為 `MenuInterface`）、
  `MenuMeta`（a004，疑為 `MenuMap`），畫面層記為 `MenuOperate`／`MenuMap`。
  ⚠️ **package 路徑在畫面層自身就不一致**：`MenuInterface`／`MenuAbstract` 被記為
  `ui/menu/`、`ut/menu/`、`ui/scene/` 三處；同一個 `MenuEnum` 先後被記為
  `ui/constant/MenuEnum.java`、`ui/enums/MenuEnum.java`、甚至 `package ui.menu;`。
  **本頁不做統一，以 `ui.menu` 為主，引用時請註明出處。**

### W04-021　掛載與卸載：父類 `init` 收 `Stage` 與 `HBox parent`，`setRoot` 負責 add 與撐滿

- **關鍵字**：`init(Stage primaryStage, HBox parent)` `setRoot` `HBox.setHgrow` `Priority.ALWAYS` `destroy` `root = null` `stageBody`
- **來源**：第六課 28:00–32:00、32:00–36:00、36:00–40:00、40:00–44:00｜`L06_第六课_教學筆記.md`
- **要點**：`init` 要多收 `Stage primaryStage`（預留後期彈窗綁定），
  也把 `stageBody`（`HBox`）一併傳入、命名取短叫 `parent`。
  掛載順序是 **`show()` → `setRoot(root)`**——
  把 `parent.getChildren().add(root)` 與 `HBox.setHgrow` 搬進 `setRoot`，
  **放在 `show()` 之後才 add，`root` 就永遠不可能是 null**（放在前面有 null 風險）。
  `destroy()` 則 `parent.getChildren().remove(root)` 後 `root = null`。
- **程式碼**：

  ```java
  // MenuAbstract.java
  package ui.menu;

  import javafx.scene.layout.HBox;
  import javafx.scene.layout.Priority;
  import javafx.scene.layout.Region;
  import javafx.stage.Stage;

  public abstract class MenuAbstract {

      private Region root;                 // private：禁止子類直接操作
      private Stage primaryStage;          // 預留給後期的副窗口（彈窗）綁定
      protected HBox parent;               // 主畫面的父容器（原本的 stageBody）

      /** 由 ServerApp 呼叫：賦值 → 讓子類畫 → 掛到父容器 → 撐滿剩餘空間 */
      public void init(Stage primaryStage, HBox parent) {
          this.primaryStage = primaryStage;
          this.parent = parent;
          show();
          setRoot(root);
      }

      /** 由 ServerApp 呼叫：從父容器移除並釋放參考 */
      public void destroy() {
          if (root == null) {
              return;
          }
          parent.getChildren().remove(root);
          root = null;
      }

      /** 只給子類用：交出畫好的根節點 */
      protected void setRoot(Region root) {
          this.root = root;
          parent.getChildren().add(root);
          HBox.setHgrow(root, Priority.ALWAYS);
      }

      /** 子類一定要實作：只負責把 UI 畫出來 */
      protected abstract void show();
  }
  ```

  子類只要交出根節點：

  ```java
  public class MenuDefault extends MenuAbstract {
      @Override
      protected void show() {
          HBox root = new HBox();
          root.setAlignment(Pos.CENTER);
          Label label = new Label("功能正在开发中，敬请期待！");
          label.setStyle("-fx-font-size: 24px; -fx-font-weight: bold; -fx-text-fill: #999999;");
          root.getChildren().add(label);
          setRoot(root);
      }
  }
  ```

- **坑**：⚠️ **忘了 `setRoot` 就是「點其他菜單沒反應」的直接原因**——
  講者實測後追查才發現，補上後即成功。
  ⚠️ **`getChildren().add(null)` 會直接拋例外**，畫面原文：`Children collection cannot contain null`。
  這是介面版最關鍵的坑：`getRoot()` 若在區域變數賦值完成前就 `return`，
  主程式 `stageBody.getChildren().add(instance.getRoot())` 立刻爆。
  講者的解法（先賦欄位再 return）正確，**但更穩的做法是在 add 前先判斷 null**。
  ⚠️ **`HBox.setHgrow()` 只出現在口述、沒有出現在任何一份畫面報告**——
  L06 的骨架是依口述描述補上的（口述在 20:00–24:00 與 40:00–44:00 兩次提到）。
  ⚠️ **方法名不一致**：v013 最後一段的 `show()` 骨架呼叫的是 `setNode(root)`
  而非 `setRoot(root)`，L06 註明應以全片一致的 `setRoot` 為準。
  ⚠️ 口述提到但無法確認的 `listener consume`（見 W04-017）。
- **相關**：見 W04-007、見 W14-010
