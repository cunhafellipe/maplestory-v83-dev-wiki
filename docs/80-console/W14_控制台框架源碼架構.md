## 條目

### W14-001　切入點是 `ServerApp`，只重寫 `start()`

- **關鍵字**：`ServerApp` `Application` `start()` `init()` `stop()` `launch` `file.encoding` `prism.lcdtext`
- **來源**：S6 00:00–05:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：控制台類是 **`ServerApp`**，位於 `ui` 套件下（`src` → `ui` → `ServerApp`）。
  講者特別對照 **`NetServer`**：「這兩個，一個是有 UI 的，一個是沒 UI 的啟動」。
  `Application` 共有三個方法：`init`（初始化）、`start`（啟動）、`stop`（停止），
  **本專案只繼承 `start`**，理由是控制台的初始化與停止邏輯已在 `start` 內全部控制好。
  `main` 開頭先設 `file.encoding`（編碼格式），再設 **LCD text 屬性**關閉 JavaFX 的 LCD 文本渲染——
  理由是「開啟以後它有些文字就會很糊，很糊，所以我們就選擇關閉」。
- **程式碼**：

  ```java
  public static void main(String[] args) {
      // 編碼格式
      System.setProperty("file.encoding", "GBK");
      // 針對 JavaFX 關閉 LCD 文本渲染（否則文字會很糊）
      System.setProperty("prism.lcdtext", "false");
      launch(args);
  }
  ```

- **坑**：⚠️ **`prism.lcdtext` 是依 JavaFX 慣例推斷的屬性名，畫面未證實**——
  口述只說「LCD.test」。屬筆記推補，實作時請以自己環境的 JavaFX 屬性為準。
- **相關**：見 W01-008（最小可執行視窗）、W13（打包）

### W14-002　`TRANSPARENT` 藏邊框，`scene.setFill(null)` 讓畫布透明

- **關鍵字**：`initStyle` `StageStyle` `TRANSPARENT` `UNDECORATED` `scene` `setFill(null)` `Stage` `Scene`
- **來源**：S6 00:00–05:00、55:00–60:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：`initStyle` 是**枚舉類**，講者逐一代數（默認的、與默認差不多的、透明的、`UTILITY`、`UNDECORATED`），
  自認 `UNDECORATED` 講不清楚。當場把程式碼註解掉重跑，展示**預設樣式會多出 Windows 系統邊框**
  （以正在錄影的 OBS 為例）。`TRANSPARENT` 的作用是把系統邊框**藏起來**——
  「框架仍存在但看不到」、「也點不上、點不到，看不上也點不到」。
  講者用玻璃窗比喻：**`stage` 是框架／骨架，`scene` 是畫布（鑲嵌的那片玻璃）**，
  剛拿到 `stage` 時是「空有其殼」。結尾用 `scene.setFill(null)` 把畫布設為透明，讓背景透出來。
- **程式碼**：

  ```java
  primaryStage.initStyle(StageStyle.TRANSPARENT);
  // ...
  primaryStage.getScene().setFill(null);
  ```

- **坑**：⚠️ **`setTitle` 講者直言「這個是沒有意義的」**，但仍設定，
  目的只是讓窗口標題也顯示為「`Server … 控制台`」。別誤以為標題有功能價值。

### W14-003　置中必須先設寬高再算

- **關鍵字**：`Screen.getPrimary().getBounds()` `setX` `setY` `1024` `768` `setResizable` `置中`
- **來源**：S6 05:00–10:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：初始寬高 **1024 × 768**。置中算法：取 **`Screen.getPrimary().getBounds()`** 的寬高
  （多螢幕只取得**主螢幕**），減去視窗寬高後**再除以 2**。
  講者強調順序：**一定要先把主窗口寬高設定好，再置中**。
- **程式碼**：

  ```java
  primaryStage.setWidth(1024);
  primaryStage.setHeight(768);
  // ★ 必須先把寬高設定好再置中：stage 的 x/y 從「左上角」算起，不是中心點
  primaryStage.setX((Screen.getPrimary().getBounds().getWidth()  - 1024) / 2);
  primaryStage.setY((Screen.getPrimary().getBounds().getHeight() - 768)  / 2);
  primaryStage.setResizable(true);
  ```

- **坑**：⚠️ **為什麼不能直接除以 2**——螢幕中心點是視窗的**中心**，
  但 `stage` 的 x/y 座標是從**左上角第一個點**算起。直接除以 2 會讓視窗跑到右下角。
  ⚠️ `Screen.getPrimary()` **在多螢幕下只取得主螢幕**，跨螢幕置中要另外處理。

### W14-004　關閉視窗不等於殺程序，否則會掉檔

- **關鍵字**：`close` `掉檔` `channel` `大區` `System.exit` `優雅關閉` `存檔`
- **來源**：S6 15:00–20:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：close 事件的處理是——**若服務已啟動，關閉窗口不等於直接殺程序**，
  而是要在後台把服務關掉。**理由是「掉檔」**：後台正在做的事包括把**頻道**、**大區**逐個關閉、
  關閉後台事件與後台任務，並**把檔存進資料庫**。強殺很可能導致存檔沒存成。
  對照組是 **`System.exit`**——直接退出。
- **程式碼**：

  ```java
  closeBtn.setOnMouseClicked(e -> {
      // ★ 服務已啟動時，不可直接殺，否則會「掉檔」
      // 必須逐個關 channel／大區、關後台事件與任務，並把檔存進資料庫
      onClose(primaryStage);   // 優雅關閉
      primaryStage.close();
      // System.exit(0);  ← 直接退出的對照組
  });
  ```

- **坑**：⚠️ **這是本片最貴的一條實務教訓**——`System.exit` 與「先關服務再關窗」只差一行，
  後果是玩家存檔損毀。
- **相關**：見 W15（伺服器遊戲機制）

### W14-005　為什麼要自訂標題列

- **關鍵字**：`head` `HeadBaseView` `setHgrow` `Priority.ALWAYS` `自訂標題列` `最小化` `最大化` `關閉`
- **來源**：S6 10:00–20:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：`head` 就是所有軟體（OBS、IDEA）上方那一條——最小化、最大化、關閉、標題。
  **為什麼不用系統默認頭**：默認樣式無法滿足個性化需求，而且像 IDEA 有 `File / Edit / View` 這些東西，
  **JavaFX 預設元件不會自帶**——必須把默認的藏掉，自己做一個。
  `head` 內部建立 icon、title、最小化、最大化、關閉四到五個元件，用 **`HBox`** 接收，
  設 `setPadding`（子元件間隔 **10 像素**）並置中。
  **靠 `HBox` 的 `setHgrow` 讓 `title` 撐滿剩餘空間**——不是均分，
  icon／最小化／最大化／關閉各佔一列，title 佔一大片。
- **程式碼**：

  ```java
  title = new Label("Server 控制台");
  // ★ title 靠 setHgrow 撐滿剩餘空間，不是均分
  HBox.setHgrow(title, Priority.ALWAYS);
  ```

- **坑**：⚠️⚠️ **講者在此處把 VBox 與 HBox 講反了**——他說「這是我們的 VBox，它是行式排列；
  那我們的 HBox……列式排」。依 JavaFX 定義應為 **VBox 垂直堆疊、HBox 水平排列**。
  **以 JavaFX 定義為準，不要照口述寫反。**（與 W02-007、W02-008 對照）

### W14-006　主佈局 VBox（head＋body），body 是 HBox（左 menu｜右 show）

- **關鍵字**：`VBox` `HBox` `BodyBaseView` `root` `填充剩餘空間` `menu` `show`
- **來源**：S6 10:00–15:00、20:00–30:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：主佈局用 **`VBox`**，因為上面是 `head`、下面是 `body`，各佔一行。
  `body` 的容器 `BodyBaseView` 本身是 **`HBox`**，左邊右邊兩塊。
  **口述中途自己更正命名**：講者最初取名 **`title`（標題區）** 與 **`show`（展示區）**，
  後來說「左邊應該叫 **menu**，不應該叫 title，橡皮擦給它擦掉」——
  最終定名：**左邊 `menu`、右邊 `show`**。
  初始化左邊用 **`VBox`**（所有標題按鈕一行一行排），設寬高、置中、依當前樣式套 style。
  **填充剩餘空間**用 `show` 填掉 menu 之外的部分——講者以最大化後解析度改變為例；
  同理 `HBox` 裡的 title 也是靠填剩餘空間撐滿。
- **程式碼**：

  ```java
  VBox root = new VBox(); // ★ head 一行 + body 一行
  HeadBaseView head = new HeadBaseView();
  head.init(primaryStage);
  BodyBaseView body = new BodyBaseView();
  createMenuRelation(body);
  root.getChildren().addAll(head, body);
  ```

- **坑**：⚠️ 講者強調 `head`／`body`／`button`／`content`／`menu`／`show`
  **全是他自己在心裡取的名字，不是 JavaFX 原生組件**。看到這些名字別去查 JavaFX 文件。
- **相關**：見 W02（W02-007 VBox、W02-008 HBox）

### W14-007　`show` 用 BorderPane，填了哪幾格就顯示哪幾格

- **關鍵字**：`BorderPane` `top` `center` `left` `right` `bottom` `content` `自動隱藏`
- **來源**：S6 20:00–25:00、35:00–40:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：右邊 `show` 用 **`BorderPane`**，講者用繪圖軟體逐格畫出五區：
  `top`（頂）、`left`（左）、`center`（中間）、`right`（右）、`bottom`（底）。
  現場把 IDEA 視窗拉來對照：「**IDEA 可以認為就是一個 BorderPane 類似的佈局**」——
  但強調 **IDEA 不是用 JavaFX 寫的，用的是 Swing，是另一個 GUI 組件**。
  每個功能頁的 `show` 結構都一樣：**`top` = 按鈕部分**（所有按鈕都放最上面）、
  **`center` = 實際內容部分**（命名 `content`）。
  **關鍵設計**：`BorderPane` 最多只填兩個區域，`left`／`right`／`bottom` 不給值就會**自動隱藏**。
- **程式碼**：

  ```java
  show = new BorderPane();
  // ★ BorderPane 填了哪幾格就顯示哪幾格，其餘自動隱藏
  //   top    = button 區（所有按鈕都放最上面）
  //   center = content 區（實際內容 / 表格）
  //   left / right / bottom 不給值 → 隱藏
  ```

- **坑**：（本條未發現坑）
- **相關**：見 W02-003（BorderPane）

### W14-008　選單要加就在 `menuList` 加字串

- **關鍵字**：`menuList` `createMenuRelation` `menuButton` `新增選單`
- **來源**：S6 25:00–30:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：`menuList` 是左邊選單的預設清單。**要新增選單就在 `menuList` 裡加字串**；
  要放第一位就插在第一位。講者當場示範在「商城管理」之後、「WZ 配置」之前加一個 **`test`**，
  重啟後左邊真的多出 `test` 按鈕。
  接著 `createMenuRelation` 方法**把左邊與右邊的 body 傳進來**，依 `menuList` 建立 menu 的 button。
  **但光有按鈕沒用——必須建立左邊 menu 與右邊 show 的關係，否則點了什麼都不觸發。**
- **坑**：⚠️ **加完字串還不夠**，一定要同時在 `bodyShowDefenderList` 補上對應的展示內容
  （見 W14-010），否則按鈕會出現但點擊無反應。

### W14-009　自寫的 `Combine` 四元組撐起 menu↔show 綁定

- **關鍵字**：`combine` `四元組` `MenuString` `menuButton` `third view` `fourth view` `三元組`
- **來源**：S6 30:00–35:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：講者說明二元組可以用 **`Map` 或 `Pair`**；
  **三元／四元的元組他自寫了一個 `combine`**（原話：「`combine` 這裡是我自己寫的」）。
  用途是建立三元或四元的關係。**目前只寫到四元，因為沒用到五元**；要五元就在後面加。
  `combine` 的四個位置（口述原文順序）：
  1. **`menuString`** —— `menuList` 裡的選單名稱（菜單叫什麼）
  2. **`menuButton`** —— 建立出來的 button 物件
  3. **`control`（`third view`）** —— 預設要加進去的 control 組件，**暫時不實作**
  4. **`control`（`fourth view`）** —— 另一個 control，**同樣暫時不實作**

  後續在核心綁定程式碼把左邊 menu 與右邊 show 綁起來，參數依序傳入
  **bodyRight（show 部分）→ menuString → menuButton → 整個 `combine` 元組**。
- **坑**：⚠️ **`combine` 是講者自寫的類別，不是 JDK 內建的 tuple**。
  `third`／`fourth` 對應 `BorderPane` 的 `top`／`center`。
  **因為 `combine` 是四元素，所以一個 `show` 只會用到 `third` 與 `fourth`——
  這個「四元素對應 BorderPane 兩格」的設計是刻意的，不是巧合。**

### W14-010　`bodyShowDefenderList` ＋ `Consumer.accept` 兩段式匹配

- **關鍵字**：`bodyShowDefenderList` `Consumer` `Function` `BiConsumer` `accept` `precedete` `predicate` `Optional`
- **來源**：S6 35:00–50:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：因為 `menuList` 要能自由擴充，**必須在初始化時就預先定義好每個菜單對應要展示的內容**，
  這個清單就是 **`bodyShowDefenderList`**。實作方式用 **`Consumer`**（Java 1.8）——
  講者回憶 Java 8 常用函式：**`Consumer`、`Function`、`Optional`**。
  對應關係是「**左邊 = 菜單列表（`menuList`）／右邊 = 展示列表（`defenderList`）**」，成對出現。
  點擊 menu 觸發**菜單事件**後，迴圈拿當前 `menuString` 去呼叫 `accept` 匹配，看它對應哪一個 defender。
  `accept` **第一步**：判斷當前菜單是否與 `consumer` 裡的條件相符（不符就直接走）。
  **第二步**：判斷 `third` 與 `fourth` 是否已被初始化。
  進入 `onMenuAction` 後，**先把其他菜單的資源釋放掉**（用的是 `Function` 與 `BiConsumer`）。
- **坑**：⚠️ 講者口述的欄位名是 **`precedete`（筆誤，應為 `predicate`）**。
  抄程式碼時若要對齊原檔，請注意這是原碼的拼字錯誤。
  ⚠️ **資料載入的時間點錯了就不會有 defender**——
  綁定表必須在初始化階段就先填好，不能等點擊時才建。

### W14-011　延遲初始化：判斷 `null` 就不重複初始化

- **關鍵字**：`延遲初始化` `null` `不重複初始化` `onServerAction` `置灰` `setAllButtonsGrey`
- **來源**：S6 40:00–45:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：`accept` 第二步判斷 `third` 與 `fourth` 是否已被初始化。
  講者強調「**如果已經初始化過就不會重複初始化**」：點過「服務啟停」後切去別的菜單再切回來，
  **這些 text 還保留著**；在線玩家那邊也一樣。所以要**判斷是否為 `null`**，未初始化才走初始化方法。
  「服務起停」`show` 的初始化內容：**啟動按鈕、停止按鈕、重啟按鈕 → 一個空格 → 重載事件按鈕、發送全服按鈕**，
  並把結果**設回 `combine`**。**`onServerAction`** 提前定義點擊事件：
  點「啟動」→ **先把所有按鈕全部置灰** → 再到後台進 `server init` 啟動服務 →
  服務起來後**再把對應按鈕的可點狀態改回來**。啟動按鈕維持灰色（不能重複點），其他按鈕才可點。

### W14-014　為什麼需要 loading 條：JavaFX 單執行緒會卡死

- **關鍵字**：`loadingBox` `loading` `單執行緒` `thread` `未響應` `JavaFX`
- **來源**：S6 45:00–50:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：`loadingBox`／loading 條在資料庫載入快時幾乎看不到，**配置載入慢時才會看到**。
  存在的原因是 **JavaFX 與 JS 相同都是單執行緒**——耗時動作必須丟到另一個 `thread`；
  若主執行緒在跑耗時操作時使用者還一直點介面，**主執行緒會卡死、程式變成「未響應」**。
  加了 loading 條就能吸收點擊、避免這種情況。
- **坑**：⚠️ **這是 JavaFX 架構性限制，不是寫法問題**——
  任何會打資料庫或跑網路的操作都要丟 thread，否則整個 UI 凍結。
  這一條在後續的發放物品、封包分析都會再遇到。

### W14-015　資源釋放靠設 `null` 交給 GC，但「服務啟停」永不釋放

- **關鍵字**：`資源釋放` `設成 null` `GC` `out.log` `事件初始化完成` `遞歸釋放`
- **來源**：S6 50:00–60:00｜`S6_控制台框架源码讲解_教學筆記.md`
- **要點**：切換菜單時會**遞歸地釋放資源**，做法就是**設成 `null`，交給 Java 的 GC 去回收**。
  **重要例外：「服務啟動」這個 `show` 的資源永遠不會被釋放**——
  原因是它的內容是日誌，**所有日誌不只寫進 `logs` 資料夾的 `out.log`（程式根目錄下），
  還要同時打印到界面上**。實測：等待後台初始化完成，介面會多出「**事件初始化完成**」字樣。
  釋放順序實測：**服務配置 → 在線玩家**（切走時釋放服務配置的資源）→ **商城管理**（再釋放在線玩家的資源）。
- **坑**：⚠️ **「設成 null 就會被 GC」是個假設**——
  如果還有其他引用（事件監聽器、`Consumer` 清單裡的殘留）指向該物件，記憶體不會釋放。
  這是本片講得最簡略、也最容易踩雷的一段，實作時務必確認沒有其他持有者。
  ⚠️ 日誌「寫檔 ＋ 顯示介面」雙寫是這個例外的成因，改動日誌機制時要連動改。
