## 條目

### W11-001　註冊指令管理模組：加一個 `MenuCommand` 類別

- **關鍵字**：`MenuCommand` `MenuAbstract` `MenuEnum` `show()` `COMMAND` `v2.menu`
- **來源**：L23 00:00–04:00｜`L23_第二十三课_教學筆記.md`
- **要點**：要新增一個選單模組，做法固定兩步：**新增 `MenuCommand extends MenuAbstract`**（覆寫 `protected void show()` 決定右側內容），
  然後**在 `MenuEnum` 枚舉註冊**一筆，左側導覽列就會自動長出「指令管理」按鈕。
  講者明說「介面相關的東西都是一樣的，直接抄一下就行了」——上一課的玩家管理 `MenuPlayer` 就是同一副骨架。
  註冊前點擊會顯示「功能在开发中，敬请期待！」，註冊後按鈕才真正可切換。
- **程式碼**：

  ```java
  package v2.menu;

  public class MenuCommand extends MenuAbstract {
      @Override
      protected void show() {
          VBox root = new VBox();
          // 後續將貼上佈局代碼
      }
  }
  ```
  ```java
  // MenuEnum.java
  COMMAND("指令管理", MenuCommand.class),
  ```

- **坑**：⚠️ 筆記的畫面理解層對類別名辨識有明顯失真（同一個角色被記成 `MenuCommand`／`StoreCommand`／`ServerCommand`／`ServerGUI` 等），
  **以口述為準**；畫面讀到的檔名照錄但不採信。
- **相關**：見 W10（玩家管理）、見 W14-008（`menuList` 加字串就長出選單按鈕，機制同型）

### W11-002　切換介面時務必把定時任務 `cancel` 掉

- **關鍵字**：`Timer` `destroy()` `timer.cancel()` `timer = null` `銷毀` `背景任務殘留`
- **來源**：L23 00:00–04:00｜`L23_第二十三课_教學筆記.md`
- **要點**：上一課留了一個定時刷新任務，**銷毀的時候沒把它銷毀掉、切換介面時也沒銷毀**，導致背景任務殘留。
  本課第一件事就是**重寫 `destroy()`**：`timer` 不為 null 時先 `cancel()`，再 `timer = null`。
  口述理由是「切換介面以後不需要刷新了」——資源要跟著介面的生命週期走，不要跨頁殘留。
- **程式碼**：

  ```java
  @Override
  public void destroy() {
      if (timer != null) {
          timer.cancel();
          timer = null;
      }
      super.destroy();
  }
  ```

- **坑**：⚠️ **漏掉 `cancel` 的症狀是「表面正常、背景一直在跑」**——
  介面切走了但定時任務仍持有資源，久了會以非預期的方式干擾新頁面。本課開頭就在修這個。
  ⚠️ 筆記註明這段是**上一課的遺留 bug**，不是本課新功能。

### W11-003　`center` 改用 `Pagination` 並抽出 `createTableView()`

- **關鍵字**：`Pagination` `setPageFactory` `createTableView` `setEditable` `PAGE_SIZE` `分頁`
- **來源**：L23 04:00–08:00、32:00–36:00、36:00–40:00｜`L23_第二十三课_教學筆記.md`
- **要點**：**指令資料來自資料庫，不能像玩家管理那樣直接把 `TableView` 放進 `center`，要改用 `Pagination`**。
  講者給的兩個理由是：「不會說我全查，查得慢」＋「既然原來就不在內存裡面去，我們就沒必要把內存弄得很大」，
  沿用的是**配置管理**的分頁查詢模板。`setPageFactory` 傳進來的 `index` 就是頁碼，裡面 `create TableView` 放進 Pagination。
  另外**必須 `setEditable(true)`**——後續「改／保存」兩步都建立在儲存格可編輯之上。
- **程式碼**：

  ```java
  Pagination center = new Pagination();
  center.setPageFactory(index -> {
      // 先建立「空表格」，資料在背景 Task 完成後回填
      TableView<GmCommand> tableView = createTableView();
      // ... searchLoading.execute() ...
      return tableView;
  });

  private TableView<GmCommand> createTableView() {
      TableView<GmCommand> tableView = new TableView<>();
      tableView.setEditable(true);   // 口述：後續「改／保存」需要
      // ...
      return tableView;
  }
  ```

- **坑**：⚠️ **忘記 `setEditable(true)`，後續「改／保存」功能會直接不能用**（`setOnEditCommit` 不會觸發）。
  ⚠️ `setPageFactory` 的 `index` 基準在筆記裡**畫面與口述直接矛盾**（見 W11-009 的 offset 坑），實作前必須自行驗證。

### W11-004　把查詢抽成可複用的 `onSearch`

- **關鍵字**：`onSearch` `setOnAction` `searchInput` `searchButton` `levelComboBox` `回車查詢` `Platform.runLater`
- **來源**：L23 20:00–24:00｜`L23_第二十三课_教學筆記.md`
- **要點**：查詢要**抽成一個方法**，因為「這個查詢是可以**複用**的」。
  綁定時 `searchInput.setOnAction` 與 `searchButton.setOnAction` **都指向同一個 `onSearch`**，
  也就是「在這裡輸入完以後敲一下回車會查詢」，同時點按鈕也可以。
  方法簽章要把 `Pagination` 與**所有查詢條件**一起傳進去；本頁比別的介面多一個條件，就是等級的 `comboBox`。
- **程式碼**：

  ```java
  searchInput.setOnAction(event -> onSearch(center, searchInput, levelComboBox));   // 敲回車也能查
  searchButton.setOnAction(event -> onSearch(center, searchInput, levelComboBox));

  private void onSearch(Pagination center, TextField searchInput, ComboBox<Integer> levelComboBox) {
      String searchText = searchInput.getText();
      int selectedIndex = levelComboBox.getSelectionModel().getSelectedIndex();
      // ... 非同步 Task ...
  }
  ```

- **坑**：⚠️ 查詢在 `Task` 背景執行緒跑完後，**必須 `Platform.runLater(...)` 切回 JavaFX Application Thread 更新 UI**，
  漏了就會在非 FX 執行緒改動元件。筆記另記錄畫面與口述在 `StrUtil.isNotEmpty`／`CharSequenceUtil.isNotBlank`、
  `ToolUtils.isArrEmpty`／`CollUtil.isNotEmpty` 上有差異，兩者都保留。

### W11-005　等級下拉的位偏移：要 `> 0` 且減 1

- **關鍵字**：`selectedIndex` `gm_level` `位偏移` `indexOf` `gmLevel` `0 開始`
- **來源**：L23 44:00–47:00｜`L23_第二十三课_教學筆記.md`
- **要點**：UI 下拉選單的第 0 項是「所有」，第 1 項才對應資料庫的 `gm_level = 0`；
  但 `getSelectedIndex()` 本身是 **0 開始**，`ComboBox` 一開始沒選時回 `-1`。
  因此條件必須寫成 `if (selectedIndex > 0)` 並用 **`selectedIndex - 1`**，
  否則會出現「想查等級 1，卻把等級 3 也查出來」的現象。
- **程式碼**：

  ```java
  // 修改前
  if (selectedIndex != -1) {
      conditions.add("gm_level = " + selectedIndex);
  }
  ```
  ```java
  // 修改後（下拉選單第一項 Index 0 是「所有」，第二項 Index 1 才是對應 gm_level = 0 的玩家指令）
  if (selectedIndex > 0) {
      conditions.add("gm_level = " + (selectedIndex - 1));
  }
  ```

- **坑**：⚠️ **用 `!= -1` 判斷會把「所有」誤當成 `gm_level = 0`**，這是本課實測才抓到的偏移。
  ⚠️ 筆記記錄這是**逐步修正的過程**（`!= -1` → `> 0` → `> 0` ＋ `selectedIndex - 1`），不是三個並存版本。
  ⚠️ 下拉選單的畫面讀值（`1000, 1, 2, 3, 4, 5, 12`）與口述（GM 0～6 級，最高 6 級）不符，**以口述為準**。

### W11-006　用 `conditions` 動態組 `WHERE`，`or` 片段必須加括號

- **關鍵字**：`List<String> conditions` `String.join` `like` `CollUtil.isNotEmpty` `or` `and` `括號`
- **來源**：L23 24:00–32:00、47:00–50:00｜`L23_第二十三课_教學筆記.md`
- **要點**：查詢條件用 `List<String> conditions` 逐條收集，最後以 **`String.join(" and ", conditions)`** 一次組裝。
  講者選這個寫法是因為「我們的 `String` 它有一個 `join` 方法……所以我就懶得自己手動拼了」。
  關鍵字條件是 `command like '%…%' or description like '%…%'`。
  ⚠️ **這裡的 `or` 片段一定要用括號包起來**：`or` 的查詢優先級比 `and` 低，
  不括起來會變成 `command like … OR (description like … AND gm_level = x)`，混查時結果全錯。
  講者自評之前沒踩到是因為「之前所有的界面都是只有一個查詢條件」，**條件從一個變成兩個就會出問題**。
- **程式碼**：

  ```java
  List<String> conditions = new ArrayList<>();
  if (StrUtil.isNotEmpty(searchText)) {
      // ⚠️ 括號不可省：or 的優先級比 and 低，否則混查會出錯（本課 47:00 段的關鍵修正）
      conditions.add(" (command like '%" + searchText + "%' or description like '%" + searchText + "%') ");
  }
  if (CollUtil.isNotEmpty(conditions)) {
      sql += " where " + String.join(" and ", conditions);
  }
  ```

- **坑**：⚠️ **SQL 注入風險**：`conditions.add(" (command like '%" + searchText + "%' …)")` 是**字串直接拼接**，
  使用者輸入的單引號會破壞 SQL 語法（筆記標明本片未提及，但程式碼本身是示範）。
  ⚠️ SQL 欄位名以資料庫語法為準：口述明講「**一定要看我們表裡面是怎麼寫的……千萬不要按照我們 Java 的語法來查**」，
  欄位是 `gm_level` 而非 `level`。
  ⚠️ 括號修正的**實際發生時點存疑**：口述 47:00 才當新發現講解，但 36:00–40:00 的畫面截錄已帶括號。

### W11-007　算頁數與填資料是兩條路，漏回填就「9 頁但沒資料」

- **關鍵字**：`selectCountByCondition` `selectPageByCondition` `setPageCount` `Math.ceil` `setItems` `回填`
- **來源**：L23 32:00–36:00、36:00–40:00、40:00–44:00｜`L23_第二十三课_教學筆記.md`
- **要點**：分頁有兩個查詢：**先 `selectCountByCondition` 查總筆數算總頁數**（`setPageCount`），
  **再 `selectPageByCondition` 依頁碼查資料並回填表格**。
  頁數用一行搞定：`center.setPageCount((int) Math.ceil((double) count / PAGE_SIZE))`，
  `PAGE_SIZE` 為 **20**；`MapUtil.getInt(selectOne, "count", 0)` 在取不到值時預設回 **0**。
  查完資料**一定要 `commands.addAll(...)` 再 `setItems(commands)` 回填**——本課實測卡在這裡。
- **程式碼**：

  ```java
  private static final int PAGE_SIZE = 20;

  private List<GmCommand> originalCommands = new ArrayList<>();   // 查詢時的原始資料
  private List<GmCommand> changeCommands   = new ArrayList<>();   // 使用者改動後的資料

  searchLoading.setOnSucceeded(e -> {

      int count = GmCommandDao.selectCountByCondition(searchText, selectedIndex);
      Platform.runLater(() -> {
          center.setPageCount((int) Math.ceil((double) count / PAGE_SIZE));
      });

      // 切頁時的取資料流程（在 setPageFactory 內）
      originalCommands.clear();                                   // 每次查完先 clear 舊資料
      originalCommands.addAll(
          GmCommandDao.selectPageByCondition(index, PAGE_SIZE, searchText, selectedIndex));
      commands.clear();
      commands.addAll(originalCommands);
      Platform.runLater(() -> tableView.setItems(commands));      // ← 這行「回填」不能漏
  });
  ```

- **坑**：⚠️ **`setPageCount` 算出 9 頁不代表有資料**；`selectList` 查出 20 條也可能忘記 `addAll` 再 `setItems`。
  分頁查詢必須「算頁數」與「填資料」兩條路都打通。
  ⚠️ **每次查完要先把 `originalCommands.clear()`**，否則舊查詢結果會累積。
  ⚠️ offset 計算**畫面與口述直接矛盾**（見 W11-009）。

### W11-008　服務沒起時 SQLite 數據源還沒 `init()`，查詢前要防呆

- **關鍵字**：`SqliteConnection` `isInitialized` `init` `防呆` `MySQLConnection` `不需要初始化`
- **來源**：L23 28:00–32:00｜`L23_第二十三课_教學筆記.md`
- **要點**：口述點出一個環境陷阱：可能一進來沒起服務、沒初始化任何東西就**直接查指令**，
  這時 **SQLite 數據源是沒有被初始化的**。解法是 `if` 判斷後補 `init()`。
  效果是「**即便不起服務的情況下，也能從我們的數據庫裡面去查到這些 GM 指令**」。
  對照組是 **MySQL 不用初始化**——講者說「像這種的話，就很依賴服務，一定要啟動」。
- **程式碼**：

  ```java
  if (!SqliteConnection.isInitialized()) {
      SqliteConnection.init();
  }
  ```

- **坑**：⚠️ **SQLite 未初始化會直接炸**；反過來，MySQL 連線**不需要**初始化（依賴服務已啟動）。
  ⚠️ 這條與「重載指令必須服務啟動」是**兩件不同的事**（見 W11-016）：**查詢**可以在服務沒起時做，**重載**不行。

### W11-009　指令有兩份：記憶體註冊表 vs 儲存檔

- **關鍵字**：`registeredCommands` `nameDescribe` `config_gmcommand` `CommandExecutor` `持久化` `getGMCommands` `commands.js`
- **來源**：L24 24:00–28:00、36:00–40:00｜`L24_第二十四课_教學筆記.md`；L23 36:00–40:00｜`L23_第二十三课_教學筆記.md`
- **要點**：**這是 L23→L24→L25 三課的貫通主軸：同一條 GM 指令同時活在兩個地方，改動必須兩邊都動。**

  | 位置 | 內容 | 誰在讀 | 改了會怎樣 |
  |---|---|---|---|
  | **儲存檔**（SQLite `config_gmcommand`） | 指令設定本體：`command`、`gm_level`、`is_work`、`gm_level_primitive` 等 | 查詢（分頁）、保存、恢復默認 | 重啟後才會反映 |
  | **記憶體** `registeredCommands` | 指令碼（小寫）→ `Command` 實例 | 指令派發（輸入這串字要執行哪個類別） | 改了不會自動生效 |
  | **記憶體** `nameDescribe` | 依等級分桶的名稱／描述清單，bucket index = 等級 | `getGMCommands()` → `commands.js` → 遊戲內 `@help` | 改了不會自動生效 |

  指令管理頁的所有按鈕都是**寫儲存檔 + 重載記憶體**的組合：查詢／重置只碰儲存檔與畫面，
  保存／恢復默認才動記憶體。
- **程式碼**：

  ```java
  public static List<GmCommand> selectPageByCondition(int pageNo, int pageSize,
                                                      String searchText, int selectedIndex) {
      String sql = "select * from gm_command";
      // ...
      sql += " order by id asc limit ?, ?";
      int offset = (pageNo - 1) * pageSize;   // ⚠️ 口述稱 index 從 0 開始「不需要減 1」，與此矛盾
      List<Map<String, Object>> selectList = SqliteConnection.selectList(sql, offset, pageSize);
      // ...
  }
  ```

- **坑**：⚠️ **`offset` 計算畫面／口述直接矛盾**：畫面是 `(pageNo - 1) * pageSize`（減 1），
  口述說「我們的 `index` 是從 0 開始的，所以我們這裡就不需要減 1」。兩者不可能同時正確。

### W11-011　`addAll` 是淺拷貝，要逐筆 `clone()` 才不會污染原始值

- **要點**：原本 `originalCommands.addAll(commands)` 再 `setItems`，
  **兩個 List 對象不同，但裡面的子元素是同一批參考**——在 UI 上改一格會同時污染原始值。
  口述的完整因果鏈：「我們改變其中一個元素的話，這兩個值都變了。所以我們還不能這麼弄。」
  解法是**逐筆 `clone()` 後再 `addAll`**；因此要讓實體 `implements Cloneable`、override `clone()`、
  把回傳型別收窄，並**改丟自己封裝的 `RuntimeException`（`AppExit`）**以免每次都要 `try`。
- **程式碼**：

  ```java
  // OnCommand.java
  public class OnCommand implements Cloneable {          // 1) implements Cloneable

      @Override
      public OnCommand clone() {                        // 2) 改成 public、收窄回傳型別
          try {
              return (OnCommand) super.clone();
          } catch (CloneNotSupportedException e) {
              throw new AppExit(e.getMessage());         // 3) 丟自封裝的 RuntimeException，免 try
          }
      }
  }
  ```
  ```java
  // MenuCommand.java：不要用 addAll（淺拷貝，會污染原始值），要逐筆 clone
  // ❌ 錯誤：commands.addAll(originalCommands);  → 兩個 List 共用同一批元素參考
  // ✅ 正確：
  originalCommands.forEach(command -> commands.add(command.clone()));
  ```

- **坑**：⚠️ **`clone()` 回傳型別不一致**：`OnCommand.clone()` 收窄成 `OnCommand`（協變返回型別），
  但畫面另記 `GmCommand.clone()` 回傳 `Object` 且**未加 `@Override`**。建議統一。
  ⚠️ 上一課的 `MenuConfig` 也踩過同一個坑，但**因為它有 `clone` 所以沒事**——口述確認
  「它在 `onSearch` 裡面……是 `clone` 了以後加進去的，所以這個是沒有問題的」。

### W11-014　保存流程：沒異動就 return → 落庫 → 回填 → 重載 → clear

- **關鍵字**：`saveAction` `onSave` `changeCommands.isEmpty` `回填` `originalCommands` `Task` `try/catch`
- **來源**：L24 16:00–20:00、20:00–24:00、32:00–36:00｜`L24_第二十四课_教學筆記.md`
- **要點**：保存是四步：**①** 先確認提示框、`changeCommands.isEmpty()` 就直接 `return`；
  **②** 寫 SQL 落庫（`GmCommandDao.update`）；**③ 把新值回填 `originalCommands`**；**④ 重載指令** 然後 `changeCommands.clear()`。
  **回填這步是全課關鍵**，理由講得很透：「我們**注册成功**以後，就把我們的**原始的值，變成我們新的值**啦……
  這樣我們在後面再繼續做更改的話，這個更改**才會被承認**啊，才會繼續添加到那個 `change` 裡面去啊。」
  回填刻意「**全部取**」：`gmLevel` 與 `isWork` 都從 `change` 覆蓋到 `ori`。
- **程式碼**：

  ```java
  private void saveAction(ProgressLoading loading) {
      // ① 沒有異動就直接結束
      if (changeCommands.isEmpty()) {
          return;
      }
      // ② 寫 SQL 落庫
      GmCommandDao.update(changeCommands);

      // ③ 回填 originalCommands：承認這次變更，之後再改才能被重新偵測
      originalCommands.forEach(oriGmCommand ->
          changeCommands.stream()
              .filter(change -> equals(change.getId(), oriGmCommand.getId()))
              .findFirst()
              .ifPresent(change -> {
                  oriGmCommand.setGmLevel(change.getGmLevel());
                  oriGmCommand.setIsWork(change.getIsWork());
              })
      );

      // ④ 重載記憶體指令 + 清空異動清單
      try {
          CommandExecutor.getInstance().reloadGMCommand(changeCommands);
          changeCommands.clear();
      } catch (Exception e) {
          Log.error("重載指令失敗，請檢查指令是否正確");
      }
  }
  ```

  > ⚠️ 上述 `reloadGMCommand(changeCommands)` 的**方法名是筆記依口述語意所取的重建名稱**，
  > 素材中並未逐字出現該名稱；畫面層實際記到的是 `reloadCommands(List<GoCommand>)` 與 `reloadCommands(List<GvCommand>)`。
  > 出處：L24 4.1 表格標為「口述語意重建（a005）＋ 畫面 v008–v009 對照」。

- **坑**：⚠️ **漏掉回填就會「改了兩次第二次偵測不到」**——`originalCommands` 還是舊值時，整列會被判成未修改而 `remove` 掉。
  ⚠️ 畫面 v010 的「重新加載」**成功路徑卻用 `Log.error("重新加载指令...")`**，疑為沿用錯誤分支寫法。

  ```java
          // ① 取出「改動前」它原本在記憶體的樣子
          String commandName = gmCommand.getCommand().toLowerCase();   // 註冊時一律小寫

          Pair<List<String>, List<String>> nameDesc = nameDescribe.get(originalLevel);
          int oriIndex = nameDesc.getLeft().indexOf(gmCommand.getCommand());
          nameDesc.getRight().remove(oriIndex);
          nameDesc.getLeft().remove(oriIndex);

          // ③ 從 registeredCommands 刪掉舊對應
          registeredCommands.remove(commandName);

          // ④ 新值無效就到此為止

          }

      }
  }
  ```

  > 素材中並未逐字出現，不是畫面逐字記錄的原始碼；本方法體整段標為**【口述重建】**。
  > 畫面層記到的是 `reloadCommands(List<GoCommand>)`／`reloadCommands(List<GvCommand>)`（見 W11-015）。

- **坑**：⚠️ **必須用小寫的 `commandName` 查**——口述：「它注册進來的 `commandName` 都是一個小寫的，我們也要弄一個小寫的過來。」
  ⚠️ **刪舊的定位依賴「舊等級」**，若此時 `registeredCommands` 已被改動或已被清空（`getRank` 取不到）就會出錯。
  ⚠️ 這段的「`nameDescribe`／`ORIIndex`／`ORIDescription`」**在畫面層完全沒有出現**，整段為口述重建。

- **要點**：**重置的是「查詢條件」不是「指令資料」**，口述逐項列舉：

### W11-020　恢復默認：全表 `update` ＋ 記憶體重置，先刷 UI 再判斷在線

- **關鍵字**：`resetCommandButton` `resetAll` `config_gmcommand` `gm_level_primitive` `is_warn` `ConfirmBox` `isOnline` `onSearch`
- **來源**：L25 03:39–07:18、07:18–10:57｜`L25_第二十五课_教學筆記.md`
- **要點**：「恢復默認」是四個按鈕裡最重的：**DAO 層**一次全表 update 把全部指令還原，
  **`CommandExecutor` 層**再把記憶體清掉重新初始化與註冊，**兩者必須成對呼叫**。
  為什麼是全表 update：「重置默認以後，肯定所有的指令都能變成啟用了，然後我們的 `gmlevel` 啊，就設置成我們默認的……
  我們之前是不是把默認的給存下來了？我們把默認的給存到這個字段了，那我們就把它設成我們默認的 `gmlevel` 就好了。」
  **順序**是講者自己修正出來的：「**不管服務啟沒啟動，我們應該都把介面給刷新一下**」——
  **先 `onSearch` 重畫 UI，再判斷服務是否在線，最後才 `resetAll`**。
- **程式碼**：

  ```java
  // OnCommandDao.java：資料庫層，全表 update（畫面 v001 原文）
  public static void resetAll() {
      SqliteConnection.updateSql("update config_gmcommand set is_warn = 'true', gm_level = gm_level_primitive;");
  }
  ```
  ```java
  // CommandExecutor.java：記憶體層，清空後重新註冊（畫面 v001 記錄為 reload）
  public void reload() {
      registeredCommands.clear();
      registerCommands();
  }
  ```
  ```java
  // ⚠ 以下為依口述 a001 整理的示意，非畫面原文
  public void resetAll() {
      commandNameDescribe.clear();      // 清掉腳本上暫存的指令描述
      list.clear();                     // 清掉指令清單
      registeredCommands.clear();       // 清掉已註冊的指令
      init();                           // 再執行一次初始化方法
      registerCommands();               // 再重新註冊
  }
  ```
  ```java
  // 畫面 v003 版按鈕：先 onSearch 刷新介面，再判斷在線，最後 resetAll（與口述的順序修正一致）
  resetCommandButton.setOnAction(event -> {
      if ("".equals(searchInput.getText()) || "-请选择指令类型-".equals(listComboBox.getValue())) {
          return;
      }

  });
  ```

- **坑**：⚠️ **`resetAll` 名字被用在兩層**（DAO 的 SQL 全表 update 與 Executor 的記憶體重置），
  **只做其一會造成 DB 與記憶體不一致**。
  ⚠️ **UI 刷新與後端重置的順序**：畫面 v002 記錄的完成版順序恰好相反（`resetAll()` 在前），**勿照抄**；口述 a001／a002 都支持 v003 版。
  ⚠️ **恢復默設是全表 update，不可逆且粒度太粗**——無法只還原單筆；
  若 `gm_level_primitive` 本身已被錯誤寫入，恢復默設會把錯誤值當成「預設」再寫一次。
  ⚠️ **`gm_level_primitive` 必須在「保存修改」時同步維護**，否則恢復默設還原不到真正的出廠值。
  ⚠️ **SQLite 沒有 boolean**，`is_warn = 'true'` 依賴欄位型別容錯；口述特別提醒「**這裡注意是單引號啊，注意我們 SQL 的語法**」。
  ⚠️ **前置條件檢查語意很怪**：v003 開頭要求「搜尋框為空或類型仍是 `-请选择指令类型-` 就 `return`」，
  但這是「恢復默認（全部）」的按鈕，較像是從搜尋按鈕複製過來的殘留條件。
  ⚠️ 口述的 `resetAll` 記憶體流程（清 `commandNameDescribe` → 清 `list` → 清已註冊 → `init()` → `registerCommands()`）
  **明顯多於畫面 v001 的 `reload()`**，素材無法判定是兩個方法還是同一個。
