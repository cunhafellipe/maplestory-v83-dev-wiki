## 條目

### W01-001　GUI 框架選型結論是 JavaFX

- **關鍵字**：`JavaFX` `選型` `AWT` `Swing` `SWT` `預設樣式`
- **來源**：第一課 02:00–20:00｜`第一課_教學筆記.md`
- **要點**：講者依序評比 AWT、Swing、JavaFX、SWT 四個候選，最終選 JavaFX。
  關鍵理由不是效能，而是**預設樣式已能滿足需求、能現成就不必重寫**，
  再加上官方推薦、面向未來、符合當代開發模式（頁面與程式碼分離）、開箱即用。
  講者明講：Swing 社群還很大、強的人也能用，只是介面美化要自己花很多功夫；
  這個控制台（含已完成的 2.x 版）確定用 JavaFX。
- **坑**：講者談 Swing 時說「整合在 JDK 內直到 JDK 17」；但同一段也說 JavaFX 在 JDK 9 起被移出。
  兩者不衝突（指不同框架），但讀的時候容易誤以為「JDK 17 還有 GUI」。

### W01-002　AWT：最貼近作業系統，但組件極少

- **關鍵字**：`AWT` `JDK 1.0` `組件極少` `依賴作業系統`
- **來源**：第一課 02:00–05:00｜`第一課_教學筆記.md`
- **要點**：AWT 是 Java 最早的 GUI，JDK 1.0 就引入。特性是更貼近作業系統底層做互動，
  效能最好、佔用記憶體最小，所以 API 命名都很底層化。
  三個缺點：難學不夠封裝、組件極少（按鈕／視窗／樣式／文字這類幾乎都沒有）、
  依賴作業系統（同一功能在不同 OS 長相不同甚至不支援，講者舉例任務管理器 Windows 有、Linux 沒有）。
  結論是只適合嵌入式或跟底層打交道的簡單圖形介面。
- **坑**：（本條未發現坑）

### W01-003　Swing：開箱即用，但 1.8 之後停更且樣式醜

- **關鍵字**：`Swing` `JDK 1.2` `JDK 17` `停更` `IntelliJ IDEA`
- **來源**：第一課 05:00–08:00｜`第一課_教學筆記.md`
- **要點**：Swing 在 JDK 1.2 引入，整合在 JDK 內直到 JDK 17。優點是開箱即用（裝了 JDK 就能用，
  不需額外 GUI 相依）、沉澱久文件多、記憶體比 AWT 稍小、社群強（IntelliJ IDEA 本身就是 Swing 寫的，
  JetBrains 全家桶基本都用 Swing）。缺點是 1.8 之後 Oracle 官方不再更新、預設樣式非常醜，
  想好看得自己重寫或引入第三方套件。講者另提到 JDK 21 當時剛發布，暫不納入討論。
- **坑**：講者說 JDK 21 當時剛發布，JavaFX 跟到 20（見 W01-004）。
  這是拍攝當下的版本狀態，不代表現況，引用時請標明時點。

### W01-004　JavaFX 的由來：Sun 時代為未來設計的框架

- **關鍵字**：`JavaFX` `Sun` `CSS` `FXML` `動畫` `頁面與程式碼分離`
- **來源**：第一課 08:00–12:00｜`第一課_教學筆記.md`
- **要點**：JavaFX 是 Sun 公司在還沒被 Oracle 收購時、為未來規劃的 GUI 框架，
  所以從設計開始就現代化，**預設樣式就很好看**。優點：社群仍在維護、組件更多且支援動畫效果、
  支援 CSS 樣式、佈局與客製更靈活、支援圖形與媒體等進階功能、設計與寫碼方式符合當代開發模式（頁面與程式碼分離）。
  版本背景：Java 1.0～1.8 是 Sun 時代，Oracle 收購後才改成 Java 9、10、11、17 這種命名。
- **坑**：（本條未發現坑）

### W01-005　JavaFX 為什麼在 JDK 9 起被移出

- **關鍵字**：`JDK 9` `移除` `相依套件` `Spring` `前後端分離`
- **來源**：第一課 12:00–15:00｜`第一課_教學筆記.md`
- **要點**：**Java 8（含）的 JDK 自帶 JavaFX，Java 9 起被移出 JDK，必須靠相依套件引入。**
  講者給的解釋鏈：開發模式轉為前後端分離 → UI 被 JavaScript／HTML 掌控 →
  Java 做 GUI 沒有明顯優勢（效能比不過 C++ 的 Qt、Flutter，受歡迎度比不過 Web 前端框架）→
  Spring 框架推出後 Java 整體轉向後台，就把 GUI 砍掉改引入服務相關的東西。
  但對「已經是 Java 程式」的人，用 Java 做 GUI 仍是最順的選擇，不需改變技術棧。
  其他缺點：沒有名案例（不像 Swing 有 IDEA）、使用人數與社群不如 Swing。
- **坑**：**JDK 9 起 JavaFX 不再內建**。本課程指定 JDK 1.8，所以可以直接 `extends Application`（見 W01-008）；
  換到 JDK 9 以上就必須自己把 JavaFX 加進相依，否則 JDK 裡根本沒有這個類別可用。
  這個前提條件在課程後段（KOOK 整合、部署）仍會反過來咬人，換環境時務必先確認。

### W01-006　SWT：背靠 Eclipse，但社群近乎斷層

- **關鍵字**：`SWT` `IBM` `Eclipse` `NetBeans` `社群`
- **來源**：第一課 15:00–20:00｜`第一課_教學筆記.md`
- **要點**：SWT 由 IBM 開發。優點是記憶體佔用小（和 Swing 同級）、官方 API 比 Swing 更豐富、
  背靠 Eclipse（早期學 Java 最常用的 IDE，學校與企業都在用，另有 NetBeans），且 Eclipse 至今仍在更新 SWT。
  缺點是被 IDEA 超越後連帶落寞，巔峰時期使用量就沒超過 Swing，現在更少；社群不活躍、國內文件極難找；
  除了 Eclipse 沒有出名案例。
- **坑**：（本條未發現坑）

### W01-008　最小可執行視窗：extends Application → start → show

- **關鍵字**：`Application` `start(Stage primaryStage)` `primaryStage.show()` `Scene` `UI 包`
- **來源**：第一課 20:00–24:00｜`第一課_教學筆記.md`
- **要點**：先建一個 **UI 包**把 UI 與其他邏輯分開，在下面建一個 App 類（講者口述叫 `ServerApp`，
  說「叫什麼都行，我個人習慣叫 ServerApp」）。JDK 1.8 自帶 JavaFX，所以直接 `extends Application`；
  `Application` 是抽象類、`start` 是抽象方法，必須實作。實作完執行會**視窗起來了但一直不結束**，
  因為介面已喚起卻什麼都沒顯示——在 `start` 傳入的 `primaryStage`（主視窗）上呼叫 `show()` 就會出來。
  建檔動作：`src/main/java/gui` 右鍵 `New` → `Java Class`；IDEA 會跳出 `Add File to Git` 詢問是否加入版控。
- **程式碼**：

  ```java
  package gui;

  import javafx.application.Application;
  import javafx.stage.Stage;

  public class GameApp extends Application {
      @Override
      public void start(Stage primaryStage) throws Exception {
          AnchorPane root = new AnchorPane();

          Button btn = new Button("test");
          root.getChildren().add(btn);
          AnchorPane.setBottomAnchor(btn, 10.0);
          AnchorPane.setRightAnchor(btn, 10.0);

          primaryStage.setTitle("冒险岛");
          Scene scene = new Scene(root, 500, 500);
          primaryStage.setScene(scene);
          primaryStage.show();
      }

      public static void main(String[] args) {
          launch(args);
      }
  }
  ```

- **指令**：IDEA 快速產生 Override 骨架：`Alt+Enter` → `Implement methods` → 勾選 `start(Stage primaryStage)` → OK。
- **坑**：**口述與畫面的類名不一致**——口述說 UI 類取名 `ServerApp`，
  畫面上實際的檔案是 `src/main/java/gui/GameApp.java`（另有 `UI.java`）。
  照抄時以畫面檔名為準。舊的 `GameApp.java` 是先全選複製到 VS Code 的 `Untitled-1` 備份再刪掉重寫的。

### W01-009　課堂環境與四個必會快捷鍵

- **關鍵字**：`IntelliJ IDEA` `JDK 1.8` `Shift + F10` `Alt+Enter` `Ctrl + Q` `Ctrl + /`
- **來源**：第一課「Environment 與資源」章｜`第一課_教學筆記.md`
- **要點**：課堂指定環境為 IntelliJ IDEA 2023.3.3 Ultimate（Build #IU-233.14015.106）＋ JDK 1.8。
  四個反覆出現的快捷鍵：`Shift + F10` 執行；`Alt+Enter` → `Implement methods` 產生 Override 骨架；
  `Ctrl + Q` 查看 JavaDoc；`Ctrl + /` 註解／取消註解。執行成功時 Run 面板顯示
  `Process finished with exit code 0`。上游專案為 `HeavenMS`、`HeavenMS-Vue`、`HeavenMS-Nap`。
- **坑**：JDK 1.8 是為了讓 JavaFX 免相依（見 W01-005）。若你的專案被迫升 JDK，W01-008 的骨架會直接編譯不過。

### W01-010　成品控制台的介面藍圖：左選單＋右內容

- **關鍵字**：`控制面板` `在线玩家` `游戏配置` `公告管理` `发包工具` `关于程序` `channelCount` `expRate`
- **來源**：第一課 00:20–00:46（成品視窗預覽）｜`第一課_教學筆記.md`
- **要點**：講者開場彈出成品視窗預覽，作為後面 26 課的目標藍圖。結構是**左側選單＋右側內容區**，
  背景為營火插圖。左側選單六項：`控制面板`、`在线玩家`、`游戏配置`、`公告管理`、`发包工具`、`关于程序`。
  `控制面板` 內有按鈕 `启动服务端` 與文字提示 `服务端未启动`；
  `游戏配置` 是資料表格，欄位為 `编号`、`英文名`、`中文名`、`数值`、`提示`、`相关方法`，
  內容可見 `channelCount`、`expRate`、`mesoRate`、`dropRate`、`bossDropRate`、`petExpRate`、
  `userLimit`、`maxCharacters`、`gmLevel`、`allowConnect`。
  `在线玩家`／`公告管理`／`发包工具` 在預覽時右側空白。
- **相關**：見 W04（選單系統）、W08（配置管理）
- **坑**：這張 `游戏配置` 表格的欄位設計直接決定了 W08 配置管理的資料結構（英文名 ↔ 中文名 ↔ 相關方法 的三欄對應）。
  `在线玩家`／`公告管理`／`发包工具` 三項在成品預覽中尚無內容，但後續課程並未全部實作，
  不要預設每項都有對應課次。
