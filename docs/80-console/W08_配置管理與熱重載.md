## 條目

### W08-001　用 `clone()` 保住原始值，`changeList` 才分得出「改過」與「沒改過」

- **關鍵字**：`changeList` `clone()` `Cloneable` `removeIf` `原始值` `setConfigData`
- **來源**：第十二課 36:00–42:00｜`L12_第十二课_教學筆記.md`
- **要點**：配置是「預先定義好的既有資料」，使用者改一個欄位時如果把整張表拿去存，
  會產生大量無謂的資料庫 IO。要維護一份全域 `List<ConfigServer> changeList`，
  **只放真的被改過的那幾筆**。加入前先 `clone()` 一份存新值，
  這樣記憶體中的「原始值」不會跟著被改掉，之後每次比對都拿新值去對原始值。
  講者的原話是「**你的原始值一定不要變**」。
  改回原值時要 `removeIf` 拿掉，否則清單會殘留髒資料、批次存檔時把沒改過的東西也寫回去。
- **程式碼**：

  ```java
  // 監聽器：沒改動就 return，改了才 clone 一份存進 changeList
  if (readOnlyData.equals(newValue) || newValue.equals(configServer.getConfigData())) {
      return;
  }
  ConfigServer c1one = configServer.clone();
  c1one.setConfigData(newValue);
  changeList.add(c1one);
  ```

  ```java
  // 實體類別實作 Cloneable 才有 clone()
  public class ConfigServer implements Cloneable {
      // ... (欄位定義) ...

      @Override
      public ConfigServer clone() {
          try {
              return (ConfigServer) super.clone();
          } catch (CloneNotSupportedException e) {
              throw new RuntimeException(e.getMessage());
          }
      }
  }
  ```

  ```java
  // 改回原值時要把項目移出來（開關欄位的修正版）
  changeList.removeIf(tmp -> tmp.getId().equals(configServer.getId()));
  ```

- **坑**：
  ⚠️ 上段程式碼的 **`readOnlyData` 這個變數無法確認真實存在**——只在單一切片出現，
  同課其他片段都是直接跟 `configServer.getConfigData()` 比對或用 `getId()` 比對。筆記已標為素材疑點。
  ⚠️ 變數名 `c1one` 疑為畫面上把小寫 L 打成數字 1 的手誤。
  ⚠️ 講者自評 `removeIf` 是必要的：「我們 `changeList` **只有 `add`，沒有 `remove`** 是不是？」

- **相關**：見 W08-008（存檔後回填原始值）

### W08-002　存檔必須是 `update` 不是 `insert`

- **關鍵字**：`insert` `insertList` `batchInsert` `update` `config_server` `DAO`
- **來源**：第十二課 30:00–36:00、54:00–60:00｜`L12_第十二课_教學筆記.md`
- **要點**：這是本頁最重要的一個判斷。控制台裡的配置**全部都是事先在 SQL 裡定義好的**，
  存檔時資料本來就存在，寫 `insert` 只會灌重複資料。
  講者的診斷原話：「**所有的配置都不需要 insert，因為所有的配置都是我們提前定義好的**。我們應該封裝一個 `update`呀。」
  本課前 30:00–36:00 先做完整的 `insert`／`insertList`／`batchInsert`，到 54:00 才翻案。
- **程式碼**（本課中途才被推翻的路，筆記保留供對照）：

  ```java
  public static void insertList(List<ConfigServer> configServerList) {
      if (ObjectUtils.isEmpty(configServerList)) {
          return;
      }
      Object[][] configServerArr = new Object[configServerList.size()][];
      for (int i = 0; i < configServerList.size(); i++) {
          ConfigServer configServer = configServerList.get(i);
          Object[] paramArr = new Object[6];
          paramArr[0] = configServer.getConfigWorld();
          paramArr[1] = configServer.getConfigType();
          paramArr[2] = configServer.getConfigName();
          paramArr[3] = configServer.getConfigData();
          paramArr[4] = configServer.getConfigDataType();
          paramArr[5] = configServer.getConfigDesc();
          configServerArr[i] = paramArr;
      }
      SqliteConnection.batchInsert(
          "insert into config_server (config_world, config_type, config_name, config_data, config_data_type, config_desc) values (?, ?, ?, ?, ?, ?)",
          configServerArr
      );
  }

  public static void insert(ConfigServer configServer) {
      insertList(Collections.singletonList(configServer));
  }
  ```

- **坑**：
  ⚠️ **存檔一開始就寫錯了**，講者自評「我真的是服了我自己」。已存在的設定資料，DAO 只能給 `update`。
  ⚠️ 該課有一段 insert SQL 的畫面解析讀成
  `insert into config_server (listConfigName, host, port, username, password, popular) values (?, ?, ?, ?, ?, ?)`，
  欄位與本專案 `config_server` 表完全不相干且與同課其他片段矛盾，**筆記已判定為解析誤讀，勿照抄**。
  ⚠️ 空集合檢查工具類名 v008 寫 `ObjectUtil.isEmpty`、v009 寫 `ObjectUtils.isEmpty`，兩說並存。

- **相關**：見 W08-003、W08-009

### W08-003　單筆 `update` 只准改 `config_data`，主鍵不可為空；批次版用 `forEach`

- **關鍵字**：`update` `MapInfoException` `forEach` `config_data` `where id = ?` `主鍵`
- **來源**：第十二課 54:00–60:00｜`L12_第十二课_教學筆記.md`
- **要點**：UI 只開放編輯 `config_data` 這一個欄位，所以 SQL 也只 `set` 一欄，條件用主鍵。
  傳進來的物件若為 `null` 或主鍵為 `null` 必須直接拋例外，否則會更新到不確定的列。
  批次版不另外寫 SQL，而是 `forEach` 迴圈呼叫單筆 `update`。
- **程式碼**：

  ```java
  // UI 端
  saveButton.setOnMouseClicked(e -> {
      if (changeList.isEmpty()) {
          return;
      }
      ConfigServerDao.update(changeList);
  });
  ```

  ```java
  // DAO 端：只允許改 config_data，條件是主鍵
  public static void update(ConfigServer configServer) {
      if (configServer == null || configServer.getId() == null) {
          throw new MapInfoException(DataType.SQLITE.getValue(), "更新对象为空");
      }

      SqlLiteConnection.update(
          "update config_server set config_data = ? where id = ?",
          configServer.getConfigData(),
          configServer.getId()
      );
  }

  public static void update(List<ConfigServer> configServerList) {
      configServerList.forEach(ConfigServerDao::update);
  }
  ```

- **坑**：
  ⚠️ **例外訊息文字口述與畫面衝突**：口述說 message 是「**主鍵不能為空**」，
  畫面程式碼是「**更新对象为空**」；例外類別口述是 `netDbEx` + `DbExType.DEFAULT.getCode`，
  畫面是 `MapInfoException(DataType.SQLITE.getValue(), ...)`。兩說並存。
  ⚠️ **連線類名與檔名在素材中反覆跳動**：v015 寫 `SqlLiteConnection` 且方法放在 `Test0x08.java`，
  v016 又把呼叫端寫成 `SqliteConnection.update(...)`。另有 v016 把 `update(configServers)`
  直接傳 `List` 的寫法（口述說是 `forEach` 遞迴呼叫單筆），兩者不能同時成立。

- **相關**：見 W08-001

### W08-004　變更監聽：文字欄用 `textProperty`，開關必須改用 JavaFX `BooleanProperty`

- **關鍵字**：`textProperty` `addListener` `selectedProperty` `String.valueOf` `changeList`
- **來源**：第十二課 36:00–42:00、48:00–54:00｜`L12_第十二课_教學筆記.md`
- **要點**：`TextField` 本身就有 `textProperty()`（回傳 `StringProperty`）可以直接 `addListener`，
  但自製的開關元件一開始沒辦法監聽。兩種元件的監聽邏輯要分開寫：
  **文字欄**比 `newValue` 與 `oldValue`、再比 `configServer.getConfigData()`；
  **開關**拿到的是 `Boolean`，必須先用 `String.valueOf(newValue)` 轉成字串再比，
  存回 `changeList` 時也要轉回字串 `"true"`／`"false"`。
  兩者都要判斷 `newValue == null` 就直接 `return`。
- **程式碼**：

  ```java
  textInput.textProperty().addListener((observable, oldValue, newValue) -> {
      if (newValue.equals(oldValue)) {
          return;
      }
      if (newValue.equals(configServer.getConfigData())) {
          // MapItemList.oldViewData... (此行舊程式碼被註解)
          changeList.removeIf(tmp -> tmp.getId().equals(configServer.getId()));
          return;
      }

      ConfigServer clone = configServer.clone();
      clone.setConfigData(newValue);
      changeList.add(clone);
  });
  ```

  ```java
  textSwitch.selectedProperty().addListener((observable, oldValue, newValue) -> {
      if (newValue == null) {
          return;
      }
      // 修正：將 Boolean 轉為 String 再進行比較，若與原設定相同則從變更清單移除
      if (String.valueOf(newValue).equals(configServer.getConfigData())) {
          changeList.removeIf(tmp -> tmp.getId().equals(configServer.getId()));
          return;
      }

      ConfigServer clone = configServer.clone();
      clone.setConfigData(newValue ? "true" : "false");
      changeList.add(clone);
  });
  ```

- **坑**：
  ⚠️ **`AtomicBoolean` 不能 `addListener`**，自製的 `SwitchButton` 用 `AtomicBoolean` 存狀態時外層沒辦法監聽。
  ⚠️ 背景執行緒不能直接改 UI 綁定的 `ObservableList`，`addAll` 從背景執行緒（`ForkJoinPool`）呼叫 UI 操作
  會拋 `IllegalStateException: Not on FX application thread`，要丟回 `Platform.runLater`。
  ⚠️ `groupingBy` 不接受 null key：資料庫只要有一筆 `config_type` 是 null，
  整個畫面就卡住並拋 `NullPointerException: element cannot be mapped to a null key`。

- **相關**：見 W08-005

### W08-005　`AtomicBoolean` 不能 `addListener`，`SwitchButton` 要自帶 `switchedProperty()`

- **關鍵字**：`BooleanProperty` `SimpleBooleanProperty` `BooleanPropertyBase` `getBean` `getName` `switchedProperty`
- **來源**：第十二課 42:00–48:00｜`L12_第十二课_教學筆記.md`
- **要點**：要讓自製開關能被外部 `addListener`，狀態欄位就不能用 `AtomicBoolean`，
  要換成 JavaFX 的 `BooleanProperty`。講者的取捨過程是：
  先照 `RadioButton.selectedProperty` 試著自 `new BooleanPropertyBase()`，被要求覆寫一堆方法；
  轉去參考 `ToggleButton`，發現**只要覆寫 `getBean()` 與 `getName()`**，
  `get`／`set`／`addListener` 父類都實作好了。中間也試過最省事的 `SimpleBooleanProperty`。
  最後還要把原本的 `private boolean state;` 拿掉，改用屬性本身取狀態。
- **程式碼**：

  ```java
  private final BooleanPropertyBase switched = new BooleanPropertyBase() {
      @Override
      public Object getBean() {
          return SwitchButton.this;
      }

      @Override
      public String getName() {
          return "switched";
      }
  };
  ```

  ```java
  setOnMouseClicked(event -> {
      switched.set(!switched.get());   // 原本是 state = !state;
      initStyle();
  });

  private void initStyle() {
      if (switched.get()) {            // 原本是 if(state)
          // ...繪製開啟狀態的 UI
      } else {
          // ...繪製關閉狀態的 UI
      }
  }

  public BooleanProperty switchedProperty() {
      return switched;
  }
  ```

  ```java
  // 中間版本，最省事的現成實作
  private final BooleanProperty on = new SimpleBooleanProperty(true);
  ```

- **坑**：
  ⚠️ **Property 最終選型衝突**：口述與 v012 停在 `BooleanPropertyBase`，v011 說最後改用 `SimpleBooleanProperty`。
  ⚠️ **`getBean()`／`getName()` 回傳值衝突**：口述說「返回的就是 this」「返回的是 `switched`」，
  v011 的 `SimpleBooleanProperty` 版本裡兩者都回傳 `null`。
  ⚠️ **命名衝突**：口述說自訂方法叫「`onOffProperty`」，v011／v012 說方法叫 `switchedProperty()`。

- **相關**：見 W08-004

### W08-007　存檔要有成功／失敗提示，`try-catch` 要包住整個存檔動作

- **關鍵字**：`MessageBox` `showInfo` `showError` `log.error` `保存成功` `try-catch`
- **來源**：第十三課 40:00–45:00｜`L13_第十三课_教學筆記.md`
- **要點**：上一課留下的未解問題之一就是「點保存按鈐一點提示都沒有」。
  `ConfirmBox` 是存檔前的確認框，`MessageBox` 是存檔後的結果提示——
  update 沒問題就 `showInfo` 傳「保存成功」，catch 到例外就 `showError` 傳「保存失敗」並 `log.error`。

### W08-011　真分頁：每翻一頁才丟一次 `limit/offset` SQL，不是全撈進記憶體

- **關鍵字**：`setPageCount` `setPageFactory` `limit` `offset` `selectSql` `MapToEntity` `真分頁` `PAGE_SIZE`
- **來源**：第十四課 40:00–50:00、50:00–55:00｜`L14_第十四课_教學筆記.md`
- **要點**：原來是把所有配置一次全查出來塞進記憶體，切頁只是換視圖（「假分頁」）。
  真分頁的做法是：先 `selectCount` 算總筆數交給 `Pagination.setPageCount`，
  然後在 `setPageFactory` 的 lambda 裡**每翻一頁才丟一次 SQL**。
  講者的理由是記憶體：「**有可能就會把內存乾爆**」，本課實測 270 MB。
  SQL 的 offset 直接用 `pageNum * pageSize`（不要 `- 1`），結果再用 `MapToEntity` 轉成實體。
- **程式碼**：

  ```java
  button.setPageFactory(index -> {
      ProgressLoading searchLoading = new ProgressLoading(primaryStage);
      ObservableList<ConfigServer> configServers = FXCollections.observableArrayList();

      searchLoading.add("查询数据中...", () -> {
          // 根據目前的頁碼 (index) 與分頁大小 (PAGE_SIZE) 查詢資料列表
          configServers.addAll(ConfigServerDao.selectList(searchText, index, PAGE_SIZE));
      });
      searchLoading.execute();

      // 建立資料表視圖並綁定查詢到的資料集
      TableView<ConfigServer> tableView = createTableView();
      tableView.setItems(configServers);

      return tableView;
  });
  ```

  ```java
  public static List<ConfigServer> selectConfigServers(int pageNum, int pageSize) {
      List<Map<String, Object>> resultList = SqliteConnection.selectSql("select * from config_server limit " + pageSize + " offset " + pageNum * pageSize);
      return resultList.stream().map(map -> (ConfigServer)MapToEntity.mapToEntity(map, ConfigServer.class)).collect(Collectors.toList());
  }

  public static List<ConfigServer> selectConfigServers(String text, int pageNum, int pageSize) {
      List<Map<String, Object>> resultList = SqliteConnection.selectSql("select * from config_server where config_name like '%" + text + "%' or config_desc like '%" + text + "%' limit " + pageSize + " offset " + pageNum * pageSize);
      return resultList.stream().map(map -> (ConfigServer)MapToEntity.mapToEntity(map, ConfigServer.class)).collect(Collectors.toList());
  }
  ```

  ```java
  // 查總筆數：count 一定要取別名 as count，否則回傳的欄名是 count1
  public static int selectCount(String text) {
      if (StrUtil.isBlank(text)) {
          return selectCount();
      }

      List<Map<String, Object>> resList = SqliteConnection.selectList("select count(1) as count from config_server where config_name like '%" + text + "%' or config_desc like '%" + text + "%'");
      return MapUtil.getInt(resList.get(0), "count", 0);
  }
  ```

- **坑**：
  ⚠️ **`limit` 與 `offset` 之間少一個空格**，直接炸出
  `java.sql.SQLSyntaxErrorException: (conn=8007) You have an error in your SQL syntax; ... near 'LIMIT 20offset 0' at line 1`。
  講者靠「把 SQL 印出來看」定位，是本課最好的除錯示範。
  ⚠️ **JavaFX 執行緒紀律**：背景執行緒拿到 `pageCount` 後直接 `button.setPageCount(...)`
  會報「不在 JavaFX 線程」，必須包 `Platform.runLater`。
  ⚠️ **SQL 字串拼接是注入風險**：所有 LIKE 條件都是字串拼接，`text` 直接來自
  `searchTextField.getText()` 且未跳脫。教學本身示範如此，實際專案應改用參數化查詢。
  ⚠️ **每頁筆數在同課內有三個值**：口述定為 `final int pageSize = 20`、
  畫面某一版硬編碼 `3`、另一版改用常數 `PAGE_SIZE`。
  ⚠️ **資料庫引擎衝突**：多數切片寫 `SqliteConnection`，但該課某個錯誤訊息原文寫
  `check the manual that corresponds to your MariaDB server version`。不可能同時成立，必有一方為誤讀。
  ⚠️ **查總筆數的方法有三種並存記法**：`selectCountServer(String)` + `selectInt`／
  `selectCount(String)` 多載 + `selectList` + `MapUtil.getInt`／口述先稱 `selectUICount` 後改口稱 `selectCount`。

  ```java
      switch (text) {
          case "区名称":
              return ConfigServer::getServerName;
          case "区推荐":
              return ConfigServer::getPopuler;
          case "区人数":
              return ConfigServer::getUserLimit;
          // ...其他 case
          default:
              return null;
      }
  }
  ```

- **坑**：
  ⚠️ **區域變數與同名方法互相遮蔽**：

  會讓區域變數遮住同名方法，雖在該片段未報錯但屬高風險寫法，不建議照抄。

### W08-016　`changeList` 要可加也可減；`FXCollections` 建立的 List 才會自動刷新

- **關鍵字**：`changeList` `removeIf` `FXCollections.observableArrayList` `setItems` `refresh` `ArrayList`
- **來源**：第十五課 25:00–35:00｜`L15_第十五课_教學筆記.md`
- **要點**：`changeList` 必須**可加也可減**——值被改回原樣時要 `removeIf` 拿掉，

  ⚠️ **`ArrayList` 與 `FXCollections.observableArrayList()` 的差別是本課最容易踩的坑**。

### W08-018　切換頁面＝`destroy()` 後 `show()`，`destroy()` 內先 `super.destroy()` 再清自己的資料

- **關鍵字**：`destroy` `show` `MenuAbstract` `super.destroy` `changeList.clear` `isPopular` `AtomicBoolean`
- **來源**：第十六課 15:00–25:00｜`L16_第十六课_教學筆記.md`
- **要點**：把 `show()` 與 `destroy()` 抽到 `MenuAbstract` 父類別統一管理，
  切換按鈕就是「銷毀舊畫面再依新狀態重繪」：`isPopular.set(!isPopular.get())` → `destroy()` → `show()`。
  子類別覆寫 `destroy()` 時**必須先 `super.destroy()` 再清自己的資料**。
  講者對「要不要在 `destroy()` 裡清值」有明確取捨判斷：
  `changeList` 是 `final` **但不是 `static`**，所以 `new instance` 時本來就會重新初始化，
  理論上不用清；但因為可以在介面上切換配置、實務上「求穩一下」還是 `clear()`。
  ⚠️ **只切換畫面不一定會重載資料**——`isPopular` 是 `AtomicBoolean` 且欄位狀態不會在切換時被清掉，
  必須 `destroy()` 後 `show()` 才會重新載入。
- **程式碼**：

  ```java
  // v004 記錄：MenuAbstract
  protected final AtomicBoolean isPopular = new AtomicBoolean(true);
  protected final List<ConfigServer> changeList = new ArrayList<>();

  public void destroy() {
      root.getChildren().clear();
  }

  // v004 記錄：MenuConfigServer 覆寫
  @Override
  public void destroy() {
      super.destroy();
      changeList.clear();
  }

  // v004 記錄：切換按鈕 = 銷毀 + 重繪
  changeButton.setOnAction(event -> {
      isPopular.set(!isPopular.get());
      destroy();
      show();
  });
  ```

- **坑**：
  ⚠️ **只切換畫面不一定會重載資料**：某個版本開頭的 Bug 就是切了按鈕但表格空白
  （畫面只出現 `loading...`），必須 `destroy()` 後 `show()` 才會重新載入。
  ⚠️ 講者實測發現 `destroy()` 這樣寫「好像有問題」，因為清完再重繪會影響後續狀態，
  一度考慮「只調 `super.destroy`」、「這個值應該就不用清」甚至「`destroy` 應該是，不應該有」——
  **這個取捨在素材裡沒有定論**。
  ⚠️ 本課的 `MenuAbstract`／`MenuConfigServer` 檔名來自畫面層，該課檔名與套件路徑高度不穩定，待確認。

- **相關**：見 W08-017；資源釋放的架構層版本見 W14-015

  ```java
  public void reloadServerConfig(ConfigServers configServers) {
      Loading.send("正在重新加載伺服器配置...", () -> {
          CommonConfig.io.reloadServerConfig(configServers);
      });
      changeList.clear();
  }
  ```

- **坑**：
  ⚠️ **重載目標是 `ServerConfig` 還是 `Server` 實例不一致**：
  口述一律以 `ServerConfig` 的欄位為反射目標；畫面某一版記的卻是 `server.getClass().getDeclaredField(...)`。

### W08-020　反射熱重載：`getDeclaredField` → `setAccessible` → `set`，值要先做型別轉換

- **關鍵字**：`getDeclaredField` `setAccessible` `declaredField.set` `convertValueToType` `valueOf` `IllegalArgumentException`
- **來源**：第十六課 35:00–45:00｜`L16_第十六课_教學筆記.md`
- **要點**：資料庫裡的 `config_name` 與 `ServerConfig` 的欄位名**是一對一的**，
  所以可以用反射把新值寫回執行中的物件。
  因為欄位**全部是 `public`、沒有 setter**，只能走 `getDeclaredField` → `setAccessible(true)` → `set()`
  （講者自述 `setAccessible(true)` 其實多餘但仍照寫）。
  最大的坑是**型別**：資料庫存的全 是 `String`，目標欄位卻有 `int`／`long`／`float`／`boolean`／`Date`，
  不轉換會炸出 `java.lang.IllegalArgumentException`。
  要用 `DataType.convertValueToType(...)` 做 `switch` 轉換，且**用 `valueOf` 不用 `parseInt`**
  ——`parseInt` 會把 `null` 變成 `0`（靜默塞錯值），`valueOf` 才會得到 `null`。
- **程式碼**：

  ```java
  // v009 記錄：第二版（移除 try-catch，改為往外拋）
  public void reloadServerConfig(List<ConfigServer> configServers) throws Exception {
      for (ConfigServer configServer : configServers) {
          Field declaredField = server.getClass().getDeclaredField(configServer.getConfigName());
          declaredField.setAccessible(true);
          declaredField.set(server, configServer.getConfigData());
      }
  }
  ```

  ```java
  // v010 + v011 記錄：convertValueToType(String dataType, String value)
  public static Object convertValueToType(String dataType, String value) {
      switch (dataType) {
          case "Integer":
              return Integer.valueOf(value);   // 不用 parseInt：null 會被轉成 0
          case "String":
              return value;
          case "Boolean":
              return Boolean.valueOf(value);
          case "Long":
              return Long.valueOf(value);
          case "Double":
              return Double.valueOf(value);
          case "Float":
              return Float.valueOf(value);
          case "Date":
              return Map32Utils.toDate(value);
          case "Byte":
              return Byte.valueOf(value);
          case "Short":
              return Short.valueOf(value);
          case "Character":
              return value.charAt(0);
          default:
              return value;
      }
  }
  ```

  ```java
  // v011 記錄：套用點（ServerConfigParser 的反射寫入迴圈）
  declaredField.set(server, DataType.convertValueToType(configServer.getDataType(), configServer.getDataValue()));
  ```

- **坑**：
  ⚠️ **原始報錯**：`java.lang.IllegalArgumentException: Can not set boolean field server.ServerConfig.yms1Delay to java.lang.String`
  ——`set` 的值是 `Object`，但目標欄位有具體型別。
  ⚠️ **`convertValueToType` 的命名與簽章有分歧**：一版記為
  `DataType.convertValueToType(dataType, value)`（入參兩個字串），另一版記為
  `DataType.convertToDataType(declaredField.getType(), propertyData)`（**入參是 `Class` 而非字串**），
  口述又說方法名是 `convert to data value`／`data type value`。**三種寫法並存。**
  ⚠️ **`setAccessible(true)` 在此處其實多餘**：目標欄位「全部是 `public`，根本沒有 `private`」，
  講者自己承認這行「其實沒什麼必要」，但仍照寫。
  ⚠️ **`ConfigServer` 的 getter 名稱混亂**：SQL 綁定用 `getOptionUpdate()` 取 `config_data`，
  UI 側用 `getConfigData()`，反射寫入用 `getDataValue()`。**至少兩個 getter 名字不屬於同一套命名。**
  ⚠️ 口述同一處引數有三種讀法：`getConfigValue()`／`getConfigData()`／`getConfigDataType()`。

- **相關**：見 W08-019

### W08-022　非同步 `execute()` 之後不要立刻 `changeList.clear()`，要放進子執行緒

- **關鍵字**：`loading.execute` `changeList.clear` `子線程` `時序` `finally` `非同步`
- **來源**：第十六課 45:00–55:00｜`L16_第十六课_教學筆記.md`
- **要點**：這是本課最貴的坑。`loading.execute()` 是**非同步**的，
  主執行緒會立刻往下走到 `changeList.clear()`，**子執行緒因此拿到空清單，重載靜默失效**。
  講者的診斷原話：「**你不要 `clear` 得太早了**」——正解是把 `clear()` 放進子執行緒，等重載完成再執行。
  講者明講「**照抄本課前 5 段寫的 `try/finally + loading.execute()` 一定會踩**」。
- **程式碼**：

  ```java
  ProgressLoading loading = new ProgressLoading(currentStage);
  loading.update(0.1, "重新加载配置...");
  try {
      ServerConfig.getInstance().reloadServerConfig(changeList);
  } catch (Exception e1) {
      ConfServer.getInstance().log("重新加载配置失败，请检查配置格式是否正确: " + e1);
  } finally {
      changeList.clear();
  }
  loading.update(1);
  ```

- **坑**：
  ⚠️ **這一段在畫面上被刪掉了**——畫面記錄作者框選刪除，但刪除後的最終形態未出現在任何切片中，
  **這一版程式碼無法從素材還原**。上段是刪除前記錄的版本。
  ⚠️ `loading.update(...)` 搭配 try-catch 的那整段被精簡時，可能正是為了處理這個非同步時序問題。

- **相關**：見 W08-008、W08-019
