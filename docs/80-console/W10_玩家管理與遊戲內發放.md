### W10-001　建立玩家管理頁並在 `MenuEnum` 註冊路由

- **關鍵字**：`MenuPlayer` `MenuAbstract` `MenuEnum` `PLAYER` `VBox` `HBox` `Separator` `setBoot` `setSpacing`
- **來源**：第二十課 00:00–04:00、04:00–08:00｜`L20_第二十课_教學筆記.md`
- **要點**：要開一個新的功能頁「玩家管理」，先建 `MenuPlayer` 讓它 `extends MenuAbstract`，
  再到枚舉類（口述：「枚舉類在 `constant`」）把 `PLAYER` 指向 `MenuPlayer.class`。
  版面是外層 `VBox root`、頂部一列 `HBox top`（搜尋框＋刷新＋重置）、中間一條
  `new Separator(Orientation.HORIZONTAL)`、下方留給中央表格，並用
  `VBox.setVgrow(center, Priority.ALWAYS)` 讓表格吃掉剩餘空間。
- **程式碼**：

  ```java
  public class MenuPlayer extends MenuAbstract {
      @Override
      protected void show() {
          HBox top = new HBox();
          top.setSpacing(5);

          TableCharacters center = new TableCharacters();

          root.getChildren().addAll(top, new Separator(Orientation.HORIZONTAL), center);
          setBoot(root);
      }
  }
  ```

  ```java
  TextField searchInput = new TextField();
  searchInput.setPromptText("角色ID/角色名/帳號ID");
  Button refreshButton = ButtonUtil.createRoundButton("刷新數據");
  Button resetButton = ButtonUtil.createRoundButton("重置");
  top.getChildren().addAll(searchInput, refreshButton, resetButton);
  ```

  ```java
  // MenuEnum.java
  // 修改前 (推測): PLAYER(name:"玩家管理", MenuDefault.class),
  PLAYER(name:"玩家管理", MenuPlayer.class),
  ```

- **坑**：口述說「佈局用 **VBox**」，畫面程式碼是 `HBox top = new HBox()`（只有 `root`
  隱含是 `VBox`）；講者自己也動搖（「VBox 這個好像也是 VBox」）。推測是外層 `root` 用 `VBox`、
  `top` 用 `HBox`。另外入口方法名不一致：`show()`（v000、v006）vs `init()`（v001、v007）；
  `setBoot(root)` 只在畫面出現、口述沒提。**本課素材的 `HBox` 只有 `top.setSpacing(5)`**，
  不要憑印象補 `setAlignment`／`Pos.`／`Insets`。
  套件／路徑在素材中有六種互斥寫法（`v2_M04G.menu`、`top.mxd.components.view`、`ui.menu`、
  `client`、`server/app/menu`、`src/main/java/server/ui/menu/`，另有一條推測路徑
  `src/main/java/com/xiao/ms/ui/menu/`），其中 `top.mxd.components/view/MenuPlayer.java`
  本身就標為「推測路徑」。主檔名也有四種寫法（`MenuPlayer.java`／`ViewsManager.java`／
  `MenuRoot.java`／`MenuRolePane.java`）。**相對路徑唯一可採信的線索是口述的「枚舉類在 `constant`」。**
- **相關**：見 W14-007、W14-012

### W10-002　放棄 `PropertyValueFactory` 反射，改用 Lambda 綁定每一欄

- **關鍵字**：`PropertyValueFactory` `setCellValueFactory` `SimpleIntegerProperty` `SimpleStringProperty` `MapleCharacter` `MaplaCharacter` `MapieCharacter` `CellDataFeatures`
- **來源**：第二十課 08:00–12:00、12:00–16:00｜`L20_第二十课_教學筆記.md`
- **要點**：遊戲玩家類不是純 POJO，getter 命名跟欄位對不上、甚至沒有 setter，
  反射式綁定會「映射不到」、整欄顯示不出來。要改成每一欄手寫
  `setCellValueFactory(param -> new SimpleXxxProperty(param.getValue().getYyy()))`。
- **程式碼**：

  ```java
  TableView<MapleCharacter> tableView = new TableView<>();

  TableColumn<MapleCharacter, Number> accountColumn = new TableColumn<>("账号ID");
  accountColumn.prefWidthProperty().bind(tableView.widthProperty().multiply(0.1));
  // 使用 Lambda 表達式取得 accountid
  accountColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getAccountid()));
  tableView.getColumns().add(accountColumn);

  TableColumn<MapleCharacter, String> nameColumn = new TableColumn<>("角色名");
  nameColumn.prefWidthProperty().bind(tableView.widthProperty().multiply(0.12));
  // 使用 Lambda 表達式取得 name
  nameColumn.setCellValueFactory(param -> new SimpleStringProperty(param.getValue().getName()));
  tableView.getColumns().add(nameColumn);
  ```

  ```java
  // 巢狀取值：先 getCashShop() 再 getCash(型別)
  TableColumn<MapleCharacter, Number> nxColumn = new TableColumn<>("点券");         // 型別 1 = 點券
  nxColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getCashShop().getCash(1)));

  TableColumn<MapleCharacter, Number> maplePointColumn = new TableColumn<>("抵用券");  // 型別 2 = 抵用券
  maplePointColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getCashShop().getCash(2)));

  TableColumn<MapleCharacter, Number> mesoColumn = new TableColumn<>("金币");
  mesoColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getMeso()));
  ```

  ```java
  // 資料模型需要補的 Getter（MapleCharacter）
  public int getAccountid() {
      return accountid;
  }
  ```

- **坑**：講者反對反射的三個理由逐字是：character「並不是一個純粹的一個實體類」「它的 `get` 方法
  有可能和它的字段名稱又對不上」「它的 `accountID` 和這個 `accountID` 的駝峰又不一樣，
  所以它可能就映射不到」，而且「它還不一定有 `set` 方法」。實際後果是「有可能這個列就顯示不出來」。
  實體類名在畫面層有三種拼法：`MapleCharacter`（v003–v005 與口述）、`MaplaCharacter`（v002，缺 `e`）、
  `MapieCharacter`（v006），Getter 名也有 `getAccountid()`（小寫 d）與 `getAccountID()`（大寫 D）兩種。
  ⚠ 筆記把 `CellDataFeatures` 列為**作者自行補上的通用 JavaFX 事實，素材零依據**；引用時須標明為通用事實。
- **相關**：見 W10-003

### W10-003　數字欄泛型必須是 `Number`，改成數字要補 `.asObject()`

- **關鍵字**：`TableColumn` `Number` `SimpleIntegerProperty` `asObject` `setCellValueFactory` 泛型不變性
- **來源**：第二十課 04:00–08:00、12:00–16:00｜`L20_第二十课_教學筆記.md`
- **要點**：數字欄的泛型要寫 `Number` 而不是 `Integer`，原因是 `TableView<T>` 的泛型不變性。
  從 `String` 改成數字綁定時，除了改泛型宣告，`setCellValueFactory` 也必須整個重寫，
  並在 `SimpleIntegerProperty` 後面補 `.asObject()` 包成 `ObservableValue<Number>`。
- **程式碼**：

  ```java
  TableColumn<MapleCharacter, Number> levelColumn = new TableColumn<>("等级");
  levelColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getLevel()).asObject());

  TableColumn<MapleCharacter, Number> mapColumn = new TableColumn<>("当前地图");
  mapColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getMapId()).asObject());

  TableColumn<MapleCharacter, Number> faceColumn = new TableColumn<>("脸型");
  faceColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getFace()).asObject());

  // 原變數名為 popuColumn，後改為 fameColumn
  TableColumn<MapleCharacter, Number> fameColumn = new TableColumn<>("人气");
  fameColumn.setCellValueFactory(param -> new SimpleIntegerProperty(param.getValue().getFame()).asObject());
  ```

- **坑**：`.asObject()` 的必要性在素材裡自相矛盾——v003 的數字欄全部寫 `new SimpleIntegerProperty(...).asObject()`，
  但 v002／v004 的 `setCellValueFactory` **沒有** `.asObject()`。筆記以 v003 為準。
  另外「人气」欄在口述完全沒提，可能是解析器從舊畫面殘留字樣誤判。
- **相關**：見 W10-002

### W10-004　欄寬依表格寬度按比例綁定

- **關鍵字**：`prefWidthProperty` `widthProperty` `multiply` `setPrefWidth` `PropertyUtil` `bindTableColumn`
- **來源**：第二十課 12:00–16:00、16:00–20:00、20:00–24:00｜`L20_第二十课_教學筆記.md`
- **要點**：欄寬不寫死數字，而是綁到表格寬度的一個比例，視窗拉大拉小欄位會等比跟著變。
  比例由講者現場心算分配，總和要接近 1。
- **程式碼**：

  ```java
  accountColumn.prefWidthProperty().bind(tableView.widthProperty().multiply(0.1));
  nameColumn.prefWidthProperty().bind(tableView.widthProperty().multiply(0.12));
  mapColumn.prefWidthProperty().bind(tableView.widthProperty().multiply(0.12));
  faceColumn.prefWidthProperty().bind(tableView.widthProperty().multiply(0.05));
  ```

  ```java
  // v004 的另一種寫法：用一個全域的 bindTableColumn 參考欄位
  mesoColumn.setPrefWidth(PropertyUtil.bindTableColumn.widthProperty().multiply(0.12));
  ```

- **坑**：口述只說「先暫時都給 0.1」，畫面卻是 `v002`／`v003` 用
  `accountColumn.prefWidthProperty().bind(...)`、`v004` 改用
  `mesoColumn.setPrefWidth(PropertyUtil.bindTableColumn.widthProperty().multiply(0.12))`，
  兩種 API 並存。比例總和若不等於 1，會有欄位被壓扁或留白——講者原話是「這個來個 0.2，
  **正好就是 1**」。
- **相關**：見 W10-003

### W10-005　用 `ContextMenu` + `MenuItem` 做表格右鍵選單

- **關鍵字**：`ContextMenu` `MenuItem` `setContextMenu` `getItems` `addAll` `Wip` `踢下线`
- **來源**：第二十課 00:00–04:00、16:00–20:00、34:00–36:00｜`L20_第二十课_教學筆記.md`
- **要點**：右鍵選單由 `ContextMenu` 容器加若干 `MenuItem` 組成，用 `contextMenu.getItems().addAll(...)`
  一次加完，最後 `tableView.setContextMenu(contextMenu)` 直接掛到表格上即可，
  **不需要自己另外綁右鍵事件**。項目文字可帶 `(Wip)` 表示尚未完成。
- **程式碼**：

  ```java
  // === 測試版（GameApp.java，最小可用） ===
  ContextMenu menu = new ContextMenu();
  MenuItem hello = new MenuItem("hello");
  hello.setOnAction(event -> System.out.println("hello"));
  MenuItem t2 = new MenuItem("t2");
  t2.setOnAction(event -> System.out.println("t2"));
  menu.getItems().addAll(hello, t2);
  // ... 將 menu 綁定到視窗事件中
  ```

  ```java
  // === 正式版（v004） ===
  ContextMenu contextMenu = new ContextMenu();
  MenuItem addItem = new MenuItem("踢下线");
  MenuItem sendItem = new MenuItem("发送弹窗(Wip)");
  MenuItem msgItem = new MenuItem("发送消息(Wip)");
  MenuItem pItem = new MenuItem("封停");
  MenuItem unPItem = new MenuItem("解封");
  MenuItem timeItem = new MenuItem("修改在线时长");
  MenuItem equipItem = new MenuItem("查看装备(Wip)");

  contextMenu.getItems().addAll(addItem, sendItem, msgItem, pItem, unPItem, timeItem, equipItem);
  tableView.setContextMenu(contextMenu);   // ★ TableView 直接內建，不需要額外事件綁定
  ```

- **坑**：右鍵選單的內容在素材裡有**四套完全不同的版本，且互無重疊項目**，不可能是同一個
  `ContextMenu`：
  - 口述 `a003`（講者當場逐項命名，筆記以此為準）：`发送点券 / 发送经验 / 发送金币 / 设置GM等级 / 发送道具 / 发送装备`；
  - 畫面 `v004`：`踢下线 / 发送弹窗(Wip) / 发送消息(Wip) / 封停 / 解封 / 修改在线时长 / 查看装备(Wip)`；
  - 畫面 `v008`：`踢下线 / 封号 / 解除封号 / 禁言 / 解除禁言 / 发送全服喇叭`（含 L21 才實作的功能，疑為誤讀後續影片畫面）；

### W10-006　右鍵選單只作用於「已選中那一列」

- **關鍵字**：`getSelectionModel` `getSelectedItem` `character == null` `ConfirmBox.red` `請選中一個玩家`
- **來源**：第二十課 34:00–36:00｜`L20_第二十课_教學筆記.md`；第二十一課 00:00–04:00｜`L21_第二十一课_教學筆記.md`
- **要點**：`ContextMenu` 掛在 `TableView` 上，右鍵位置在哪裡不影響作用對象——
  最終操作的永遠是「目前被選中的那一列」。所以選單事件的第一件事是取選取列，
  並在 `null` 時提示後 `return`。講者自述的 UX 結論是「最好還是在選中這行裡面右鍵」。
- **程式碼**：

  ```java
  private void sendItem(TableView<MapleCharacter> tableView, int type) {
      MapleCharacter character = tableView.getSelectionModel().getSelectedItem();
      if (character == null) {
          ConfirmBox.red("请选择一位玩家", "错误");
          return;
      }
      // ...後續邏輯...
  }
  ```

- **坑**：講者原話是「**我們只能獲取到這一行已經選中了**。但是**我們鼠標可以在任何位置**
  去點擊這個右鍵菜單啊。**最終操作的還是這個選中的數據**」——在空白處右鍵也會作用到已選中那列，
  「可能就看的不是那麼清楚」。不先做 `null` 檢查就會對著 `null` 操作。
  ⚠ 提示框 API 名稱在素材中並存：`ConfirmBox.red(msg, title)`（畫面 v000）、
  `ConfirmBox.show(primaryStage, msg)`（口述）。
- **相關**：見 W10-005、W10-011

### W10-007　從 `Server` 遍歷所有頻道取出在線玩家

- **關鍵字**：`Server.getInstance` `getChannels` `getPlayerStorage` `getAllCharacters` `FXCollections.observableArrayList` `ObservableList`
- **來源**：第二十課 20:00–24:00、24:00–28:00｜`L20_第二十课_教學筆記.md`；第二十一課 68:00–72:00｜`L21_第二十一课_教學筆記.md`
- **要點**：線上玩家清單的資料來源固定是雙層迴圈——外層取所有頻道，內層取該頻道的所有角色。
  結果放進 `FXCollections.observableArrayList()`，再 `center.setItems(...)` 餵給 `TableView`。
- **程式碼**：

  ```java
  private void onRefresh(TableView<MapleCharacter> center, TextField searchInput) {
      String inputText = searchInput.getText();
      ObservableList<MapleCharacter> characters = FXCollections.observableArrayList();

      for (Channel channel : Server.getInstance().getChannels()) {
          for (MapleCharacter character : channel.getPlayerStorage().getAllCharacters()) {
              if (inputText == null || inputText.isEmpty()) {          // 查詢條件為空 → 全部收錄
                  characters.add(character);
              } else if (String.valueOf(character.getAccountID()).contains(inputText)
                      || (character.getName() != null && character.getName().contains(inputText))) {
                  // 帳號 ID 或角色名「包含」查詢字串就收錄（模糊比對，非完全相等）
                  characters.add(character);
              }
          }
      }
      center.setItems(characters);
  }
  ```

- **坑**：口述寫的是 `server.getInstance().getAllChannels().for`（`getAllChannels` + `forEach`），
  畫面是 `Server.getInstance().getChannels()` + `for` 迴圈，後者與 L19 完全一致、可信度較高。
  查詢條件為空時另有 `MapleStringUtils.isEmpty(inputText)` 版本（v006）。
- **相關**：見 W10-008、W10-009

### W10-008　搜尋過濾與重置：帳號 ID 或角色名的模糊比對

- **關鍵字**：`searchInput` `getText` `contains` `setOnKeyReleased` `setOnAction` `重置` `setText("")` 不需要分頁
- **來源**：第二十課 20:00–24:00、24:00–28:00、28:00–32:00｜`L20_第二十课_教學筆記.md`
- **要點**：搜尋框的文字拿來做 `contains` 模糊比對，比對對象是帳號 ID 與角色名任一者。
  重置按鈕清空輸入框再重新載入。這張表**不需要分頁元件**——資料是直接從記憶體取得在線玩家。
- **程式碼**：

  ```java
  // 綁定搜尋框的鍵盤輸入事件
  searchInput.setOnKeyReleased(event -> onRefresh(center, searchInput));

  // 綁定重置按鈕的點擊事件
  resetButton.setOnAction(event -> {
      searchInput.setText("");
      onRefresh(center, searchInput);
  });
  ```

  ```java
  // v006 的過濾寫法（MapieStringUtils.isEmpty 版本）
  private void onRefresh(TableView<MapieCharacter> center, TextField searchInput) {
      String inputText = searchInput.getText();
      ObservableList<MapieCharacter> characters = FXCollections.observableArrayList();
      for (Channel channel : Server.getInstance().getChannels()) {
          for (MapieCharacter character : channel.getPlayerStorage().getAllCharacters()) {
              if (MapieStringUtils.isEmpty(inputText)) {
                  characters.add(character);
              } else if (String.valueOf(character.getId()).contains(inputText) || (character.getName() != null && character.getName().contains(inputText))) {
                  // 如果 ID 或 名字 包含搜尋字串，則加入列表
                  characters.add(character);
              }
          }
      }
      center.setItems(characters);
  }
  ```

- **坑**：四組衝突必須兩邊都留著：
  (a) 搜尋觸發事件——口述 `setOnAction`（敲 Enter）、畫面 `setOnKeyReleased`（邊打邊刷），

### W10-009　`Timer` 延遲 1 秒、每 30 秒自動刷新

- **關鍵字**：`Timer` `TimerTask` `schedule` `cancel` `regRefresh` `doRefreshCenter` `30000` `1000` 自動刷新不能太快
- **來源**：第二十課 28:00–32:00、32:00–34:00、34:00–36:00｜`L20_第二十课_教學筆記.md`
- **要點**：自動刷新刻意做慢——講者理由是刷新太快會讓玩家列的**順序跳動**（「這個人先是在第一行，
  然後他一下子又變到第二行……很不方便我們去操作這個玩家」）。做法是 `Timer` 延遲 1 秒開始、
  之後每 30 秒一次；`regRefresh` 重新註冊前務必 `timer.cancel()`，否則 Timer 會累積。
  職責拆成兩支：`doRefreshCenter` 負責拉資料，`regRefresh` 負責排程。
- **程式碼**：

  ```java
  import java.util.Timer;
  import java.util.TimerTask;

  public class MenuPlayer extends MenuAbstract {

      private Timer timer;      // ★ 必須是「類別層級」欄位，才能被 TimerTask 的內部類存取

      /** 拉資料並更新 UI（不含排程邏輯） */
      private void doRefreshCenter(TableView<MapleCharacter> center, TextField searchInput) {
          if (!Server.getInstance().isOnline()) {
              center.setPlaceholder(new Label("服务器未启动"));
              return;
          }
          onRefresh(center, searchInput);
      }

      // 注册定时刷新
      private void regRefresh(TableView<MapleCharacter> center, TextField searchInput) {
          // ★ 后台刷新時服務沒開就直接靜默結束，不要跳提示
          if (!Server.getInstance().isOnline()) {
              return;
          }

          // ★ 重新註冊前務必取消舊的，否則會累積多個 Timer
          if (timer != null) {
              timer.cancel();
          }

          timer = new Timer();
          timer.schedule(new TimerTask() {
              @Override
              public void run() {
                  if (!Server.getInstance().isOnline()) {
                      timer.cancel();
                  }
                  doRefreshCenter(center, searchInput);
              }
          }, 1000, 30000);      // ← 延遲 1 秒開始，之後每隔 30 秒
      }
  }
  ```

- **坑**：(a) **定時週期衝突**——口述與 v007 都是 30 秒（`30000` 毫秒），v008 是
  `timer.schedule(new TimerTask() { ... }, 1000, 2000)`（**2 秒**），且方法名寫成
  `doRefreshTable`；筆記以 30 秒為準。(b) **離線時的行為落差**——口述說「不在線就不刷新」，
  畫面 `run()` 裡先 `timer.cancel()` 再**無條件**呼叫 `doRefreshCenter(...)`，等於離線後仍會再刷最後一次。
  (c) `timer` 必須是類別層級欄位，`TimerTask` 的匿名內部類才存得到。
  (d) 講者自述重置按鈕**不取消 Timer**（「這個不需要重置」），但 `regRefresh()` 又會立刻重建 Timer，
  離開頁面時應自行 `cancel()`，本課沒做。
- **相關**：見 W10-010

### W10-012　發放數量要防 `int` 溢位

- **關鍵字**：`NumberFormatException` `Integer.MAX_VALUE` `Long.parseLong` `input.length` `NumberUtils.isNumber` `2147483647`
- **來源**：第二十一課 08:00–12:00、12:00–16:00｜`L21_第二十一课_教學筆記.md`

  ```java

      MessageBox.showError(serverstage, messages[type][1]);
      return;

  if (input.length() >= 11 || Long.parseLong(input) > Integer.MAX_VALUE) {
      MessageBox.showError(errorStage, "输入的数字过大, 最大值为: " + Integer.MAX_VALUE);
      return;
  }
  int inputNum = Integer.parseInt(input);
  ```

  ```text
  Exception in thread "JavaFX Application Thread" java.lang.NumberFormatException: For input string: "9999999999999"
      at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:65)
      at java.base/java.lang.Integer.parseInt(Integer.java:652)
      at java.base/java.lang.Integer.
  ```

- **坑**：⚠ `v016` 的畫面解析把 `NumberFormatException: For input string: "1231231231"`

### W10-016　`getEquipById` 永遠不回傳 `null`

- **關鍵字**：`MapleItemInformationProvider` `getEquipById` `getEquipStats` `Equip` `setQuantity((short)1)` `equipStatsCache` `short` 不能為 null
- **來源**：第二十一課 44:00–48:00、48:00–52:00、52:00–56:00｜`L21_第二十一课_教學筆記.md`
- **要點**：要拿一個裝備實體時不能靠 `getEquipById` 回傳值判斷成不成功——它先 `new Equip(...)`、
  再 `nEquip.setQuantity((short)1)`，然後才從 WZ 讀屬性；讀不到也照樣回傳一個 `Item`。

  或自己再包一層。
- **程式碼**：

  ```java
  private Item getEquipById(int equipId, int ringId) {
      Equip nEquip = new Equip(equipId, (byte) 0, ringId);
      nEquip.setQuantity((short) 1);
      Map<String, Integer> stats = this.getEquipStats(equipId);
      if (stats != null) {

                  nEquip.setStr(stat.getValue().shortValue());
              } else if (stat.getKey().equals("DEX")) {
                  nEquip.setDex(stat.getValue().shortValue());
              }
              // ... 下方包含 INT, LUK, WATK, MATK 等各項能力值的賦值邏輯
          }
      }
      return nEquip;
  }
  ```

  ```java
  // MapleItemInformationProvider：既有方法（第 511 行左右）
  public Map<String, Integer> getEquipStats(int itemId) {
      return equipStatsCache.get(itemId);
  }
  ```


- **坑**：(a) ⚠ 素材中的類別是 **`MapleItemInformationProvider`（14 次）**，

  (e) ⚠ 效能疑慮與回答（口述）：「它如果已經從 WZ 讀到了數據的話，它會放到緩存裡面去，

### W10-017　表格不會自己更新：補 `refresh()` 並用 `synchronized` 加鎖

- **關鍵字**：`TableView.refresh` `setItems` `synchronized` `doRefreshTableItem` 刷新衝突
- **來源**：第二十一課 20:00–24:00、68:00–72:00｜`L21_第二十一课_教學筆記.md`
- **要點**：改了角色的資料後，表格畫面不會跟著變。原因是「它雖然是獲取到最新的 Character，
  然後給它 `set item`，按理說它應該是會自動刷新的，但是它沒有」，只能強制 `refresh()`。
  另外手動刷新與定時任務自動刷新會撞在一起，必須加鎖。
- **程式碼**：

  ```java
  center.setItems(characters);
  center.refresh();
  ```

  ```java
  private synchronized void doRefreshTableItem(MapleCharacter center, TextField searchInput) {
      String inputText = searchInput.getText();
      ObservableList<MapleCharacter> characters = FXCollections.observableArrayList();
      for (Channel channel : Server.getInstance().getChannels()) {
          for (MapleCharacter character : channel.getPlayerStorage().getAllCharacters()) {
              if (inputText.isEmpty()) {
                  characters.add(character);
              } else if (String.valueOf(character.getAccountID()).contains(inputText) || character.getName().contains(inputText)) {
                  characters.add(character);
              }
          }
      }
      center.setItems(characters);
      center.refresh();
  }
  ```

- **坑**：口述對加鎖的理由是「如果我們點手動刷新的時候，這個時候定時任務正好也在執行這個刷新，
  它就會衝突嘛……所以我們加一個鎖啊，讓它不管是先手動刷新還是先自動刷新，
  **要等上一次刷新完了，你才能繼續執行**」。
  ⚠ 這支方法已是 `synchronized`，但它同時是方法參數與區域變數名都叫 `center`（型別是
  `MapleCharacter`）——照抄時別誤以為是 `TableView`。
- **相關**：見 W10-007、W10-009

### W10-018　關掉控制台視窗不等於結束程式，`closeButton` 一定要補 `System.exit(0)`

- **關鍵字**：`System.exit(0)` `closeButton` `setOnAction` `shutdown(false)` `isShutdown` `Runnable` 行程殘留 埠號被佔用
- **來源**：第二十二課 00:00–04:00、04:00–08:00｜`L22_第二十二课_教學筆記.md`
- **要點**：JavaFX 視窗關掉**不會**結束 JVM——只要還有非 daemon 的後台定時任務在跑，
  進程就會留著，下次啟動就報埠號被佔用。`closeButton` 的事件裡必須先關服務再強制結束 JVM。
- **程式碼**：

  ```java

      Server.getInstance().shutdown(false);
      System.exit(0);

      Stage window = (Stage) closeButton.getScene().getWindow();
      if (window != null) {
          window.close();
      }
  });
  ```

  ```java

      // ... 前方的 UI 視覺變更邏輯 ...

      // 新增的程式碼區塊：安全關閉伺服器
      if (!Server.getInstance().isShutdown()) {
          Server.getInstance().shutdown(false);
      }

      System.exit(0);
  });
  ```

  ```java

  // 关闭所有进程，由于不知名原因，端口号没有释放
  ```

  ```text
  Disconnected from the target VM, address: '127.0.0.1:XXXX', transport: 'socket'
  Process finished with exit code 0
  ```

- **坑**：(a) 講者原話：「我們在這個界面，然後我們直接退出的話……它沒有、並沒有退出。
  是因為有一個定時任務，因為我們沒有切窗口嘛，所以有個定時任務在後台刷新」；
  「如果我們 `system.exit` 的話，它就會把這個進程都給幹掉。所以它的子線程都會被幹掉」。
  (b) ⚠ **在線判斷的 API 名稱衝突**——畫面 v000 寫 `if (!Server.getInstance().isShutdown())`，
  口述說的是判斷 `is online`，且口述自己修正為「`shutdown` 裡面其實是會判斷 `is online`……
  所以我們好像 `is online` 也不需要判斷，直接 `shutdown` 就好了」；
  較晚的 v001 定稿畫面**確實沒有**這層判斷。
  (c) ⚠ **曾宣告 `Runnable r = new Runnable() { ... }` 但最終未採用**；講者釐清
  「它這只是一個 `runnable` 啊，它並不是真的的一個 `run`，所以我們要手動調它的 `run` 它才會去停」。
  **最終版程式碼裡沒有 `Runnable`。**
  (d) `Server.shutdownInternal(boolean restart)` 是 `synchronized` 的內部實作。
  (e) IDE 停止（紅色 Stop）會留下 `Process finished with exit code 130` 的殘留行程；
  需到工作管理員確認 `Java(TM) Platform SE binary` / `javaw.exe` 已清乾淨。
  (f) 埠號：畫面日誌是 `注册服务端端口号:8484`，口述卻說「8080 端口被佔用了」——
  **不要把 8080 當成遊戲伺服器埠**。
