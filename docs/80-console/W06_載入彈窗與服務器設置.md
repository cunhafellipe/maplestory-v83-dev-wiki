## 條目

### W06-001　先讀 sqlite 期間用 Loading 彈窗擋住主視窗

- **關鍵字**：`Loading` `sqlite` `server.db` `未響應` `服務配置` `menu_config`
- **來源**：第九課 05:00–08:00｜`L09_第九课_教學筆記.md`
- **要點**：進入「服務配置」時會去讀 sqlite 資料庫（`server.db`），放在固態以外的機器上啟動會有點卡，介面會卡一會兒。若不加保護，使用者在讀庫時亂點會出現「程序未響應」，一直未響應 Windows 可能就會殺掉程序。所以要讓 Loading 以「彈窗」形式出現來保護主介面。路由端先建一個空類別 `MenuConfig extends MenuAbstract` 覆寫 `show()`，並把枚舉類裡面的服務配置改成 `menu_config`。
- **程式碼**：

  ```java
  public class MenuConfig extends MenuAbstract {
      @Override
      protected void show() {
      }
  }
  ```

- **坑**：**Loading 為什麼必須是「子彈窗」而不能直接動主 `Stage`**——口述說「我們就不能用我們的 `primary Stage` 了……要弄一個子窗口出來」，因此自訂元件繼承 `Stage`。另：先用空類別跑一次確認點擊後右側變空白（而非「功能还在开发中，敬请期待！」）才證明路由通，這是本課的自我驗證步驟。`FaterLive` / `ListCellBuilder` 與 `ListView` / `ComboBox` 註解是畫面層竄入，不採信。
- **相關**：見 W14-016；見 W05

### W06-002　只用 `ProgressIndicator` 的 `-1` Indeterminate 轉圈狀態

- **關鍵字**：`ProgressIndicator` `setProgress` `Indeterminate` `-1` `轉圈`
- **來源**：第九課 00:00–05:00｜`L09_第九课_教學筆記.md`
- **要點**：`ProgressIndicator` 是 JavaFX 自帶的進度指示器，預設進度就是 `-1`，代表一直轉圈。`0` 顯示 0%、`0`–`0.999` 是百分比進度條、`1` 顯示完成。本課只使用「一直轉圈」那個樣態，其餘一律不用。
- **程式碼**：

  ```java
  VBox root = new VBox();
  root.setAlignment(Pos.CENTER);
  ProgressIndicator indicator = new ProgressIndicator();
  Button button = new Button("增加进度");
  root.getChildren().addAll(indicator, button);

  button.setOnAction(event -> {
      if (indicator.getProgress() <= -1) {
          indicator.setProgress(indicator.getProgress() - 0.2);
      } else {
          indicator.setProgress(indicator.getProgress() + 0.2);
      }
      System.out.println(indicator.getProgress());
  });
  ```

- **坑**：講者口述自嘲是「在 JavaFX 自帶的話，我們就把它給嫖了……去了它一半的功能」，因此不要以為本課的 Loading 有百分比進度。真要百分比進度條才需要 `setProgress(0.0f–1.0f)`。
- **相關**：見 W02

### W06-003　用 `initOwner` + `Modality.WINDOW_MODAL` 把主視窗鎖住

- **關鍵字**：`initOwner` `Modality.WINDOW_MODAL` `IllegalStateException` `primaryStage` `show()`
- **來源**：第九課 16:00–20:00、20:00–24:00｜`L09_第九课_教學筆記.md`
- **要點**：`MenuAbstract` 裡的 `primaryStage` 原本是 `private`，要改成 `protected` 才能讓同包的子類使用。Loading 建構子收 `primaryStage` 入參後，依序做 `initOwner(primaryStage)`（讓子視窗歸主視窗管，任務列不會出現兩個視窗 icon）與 `initModality(Modality.WINDOW_MODAL)`（子視窗開著時主視窗點不動）。
- **程式碼**：

  ```java
  initOwner(primaryStage);
  initModality(Modality.WINDOW_MODAL); // 設定為視窗級別的模態
  ```

  ```java
  // src/.../ui/menu/MenuAbstract.java
  public abstract class MenuAbstract {
      protected Stage primaryStage;   // 原本是 private，後來改成 protected

      protected abstract void show();
  }
  ```

  ```text
  Exception in thread "JavaFX Application Thread" java.lang.IllegalStateException: Cannot set owner once stage has been set visible
  at javafx.graphics/javafx.stage.Stage.initOwner(Stage.java:298)
  at ui.component.ProgressLoading.<init>(ProgressLoading.java:28)
  ...
  ```

- **坑**：**`initOwner` / `initModality` / 置中 / `show()` 的順序不能換**，換了就會噴 `Cannot set owner once stage has been set visible`。`Modality` 三個值中口述把 `APPLICATION_MODAL` 說成「不影響窗口點擊」，與 JavaFX 定義相反（講者自己也說「啊，沒，沒說反」），本課只用 `WINDOW_MODAL`。
- **相關**：見 W03

### W06-004　透明化要清掉 `VBox` 的預設背景樣式

- **關鍵字**：`StageStyle.TRANSPARENT` `scene.setFill` `root.setStyle` `-fx-background-color: transparent` `Color.TRANSPARENT`
- **來源**：第九課 20:00–24:00｜`L09_第九课_教學筆記.md`
- **要點**：要做出無邊框的 Loading，透明化分三層且缺一不可：`initStyle(StageStyle.TRANSPARENT)` 去掉邊框；`scene.setFill(Color.TRANSPARENT)` 去掉場景背景；真正解決灰色矩形的是佈局容器 `VBox` 的預設樣式，要用 `root.setStyle("-fx-background-color: transparent;")`。本課為了長文字顯示把 Scene 由 `300` 收到 `150` 再放回 `200`、高度 `100`。
- **程式碼**：

  | 次序 | 程式碼 | 結果 |
  | --- | --- | --- |
  | 第一次 | `scene.setFill(null);` | 無效 |
  | 第二次 | `scene.setFill(Color.TRANSPARENT);`（自動匯入 `import javafx.scene.paint.Color;`） | 仍無效 |
  | **最終解法** | `root.setStyle("-fx-background-color: transparent;");` | 灰色矩形消失 |

  ```java
  root.setStyle("-fx-background-color: transparent;");
  Scene scene = new Scene(root, 200, 100);
  scene.setFill(Color.TRANSPARENT);
  ```

- **坑**：`scene.setFill(...)` 兩次都無效，因為灰色背景不是 `Scene` 造成的而是 `VBox` 的預設樣式——這一點口述只說「還要把 root 透明化」，根因是畫面層補上的。另：口述說「`root.transparent` 打錯了嗎？……確實是打錯了」。
- **相關**：見 W02

### W06-005　`centerOnParent` 算座標把子視窗置中於主視窗

- **關鍵字**：`centerOnParent` `setX` `setY` `getWidth` `getHeight` `ViewUtil` `spacer`
- **來源**：第九課 24:00–28:00、28:00–32:00｜`L09_第九课_教學筆記.md`
- **要點**：所有視窗的 `x`／`y` 座標都指左上角。子視窗置中 = 父視窗座標 + 父視窗寬高的一半 − 子視窗寬高的一半。這個方法不只 Loading 會用到，所以放進工具類（口述定名 `ViewUtil`，在 `util` 包）。簡化寫法為「父寬減子寬再除以 2」，但畫面上未見。
- **程式碼**：

  ```java
  public class ViewUtil {

      /** 讓子視窗置中於父視窗（出處：v007 公式 / a005-a006 口述推導） */
      public static void centerOnParent(Stage primaryStage, Stage stage) {
          stage.setX(primaryStage.getX() + (primaryStage.getWidth() / 2) - (stage.getWidth() / 2));
          stage.setY(primaryStage.getY() + (primaryStage.getHeight() / 2) - (stage.getHeight() / 2));
      }
  }
  ```

- **坑**：**前置條件是子視窗必須先有寬高**（先 `setWidth`／`setHeight` 或建 `Scene(root, w, h)`），所以在 `ProgressLoading` 裡「設寬高」必須排在「置中」之前——這正是本課引入任務佇列保證順序的原始動機。工具類名在畫面層有 `FlowUtil.centerAndShowParent`（v006）→ `PlowUI.centerOnParent`（v007）→ `ViewUtil.centerOnParent`（v008）四種寫法，**以口述為準 = `ViewUtil.centerOnParent`**。
- **相關**：見 W14-014

### W06-006　任務用 `LinkedBlockingQueue<Pair<String, Runnable>>` 收以保證執行順序

- **關鍵字**：`LinkedBlockingQueue` `Pair` `Runnable` `先進先出` `offer` `poll` `Integer.MAX_VALUE`
- **來源**：第九課 32:00–36:00、00:00–05:00｜`L09_第九课_教學筆記.md`
- **要點**：某些程式碼必須按順序執行（例如「先設定子視窗寬高，再把子視窗置中」，反過來寫就算不出寬高），因此用佇列保證先進先出。`Pair` 是 HeavenMS 專案自寫的泛型鍵值對，`getLeft()` 放顯示文字 `String`、`getRight()` 放要執行的 `Runnable`——因為後台執行任務時要同步更新 `label`。選 `LinkedBlockingQueue` 而非 `ArrayList` 的另一個理由是它執行緒安全、預設容量 `Integer.MAX_VALUE`，不需要煩惱擴容。
- **程式碼**：

  ```java
  /** 任務佇列：先加進來的先執行（出處：v008 / v013） */
  private final LinkedBlockingQueue<Pair<String, Runnable>> queue = new LinkedBlockingQueue<>();
  ```

  ```java
  public class Pair<L, R> {
      private final L left;
      private final R right;
      public Pair(L left, R right) { this.left = left; this.right = right; }
      public L getLeft()  { return left;  }
      public R getRight() { return right; }
  }
  ```

- **坑**：`ArrayList` 的預設容量是 **`10`**（口述講者說「應該是 8 吧」為猜測，正確值是 10）。`Pair` 的左右對應是依畫面用法推斷（`getLeft()` = text，`getRight()` = runnable），不是口述明講。
- **相關**：見 W14-014

### W06-007　`add(String, Runnable)` 用 `synchronized` + `offer` 收任務

- **關鍵字**：`add` `synchronized` `offer` `LinkedBlockingQueue` `queue.offer`
- **來源**：第九課 32:00–36:00、52:00–53:08｜`L09_第九课_教學筆記.md`
- **要點**：加入任務的簽章是 `(String text, Runnable runnable)`；`offer` 就是往佇列添加。加鎖的理由口述是「它要是並發的往裡面加，加任務的話還不太行」，但也補了一句「加任務的話……這個就不用加鎖了，只會執行一次」。加完全部任務後才呼叫 `execute()` 開始消耗佇列。
- **程式碼**：

  ```java
  public synchronized void add(String text, Runnable runnable){
      queue.offer(new Pair<>(text, runnable));
  }
  ```

- **坑**：`add` 明明 `synchronized`，但 `LinkedBlockingQueue` 本身執行緒安全，等於雙重保護；口述對「要不要加鎖」自相矛盾。另外 `add` 只能加不能移除，**一旦呼叫 `execute()` 佇列就被單向消耗**，要重跑就必須重建 `ProgressLoading`。
- **相關**：見 W14-014

### W06-008　`execute()` 開子執行緒、`poll` 迴圈、`runAndWait` 更新 UI、`CompletableFuture` 執行

- **關鍵字**：`execute` `queue.poll` `PlatformImpl.runAndWait` `CompletableFuture.runAsync` `future.get` `Log.error` `complete(null)` `future.complete`
- **來源**：第九課 36:00–40:00、40:00–44:00、44:00–48:00｜`L09_第九课_教學筆記.md`
- **要點**：`execute()` 一定要自己 `new Thread(...)`，因為 `future.get()` 是阻塞式的，在 UI 執行緒呼叫會讓視窗「未響應」；在子執行緒阻塞沒關係，主線程呼叫完 `execute()` 就啥也不用幹。迴圈終止條件是 `while ((pAll = queue.poll()) != null)`，poll 到 `null` 代表清空。每輪先用 `runAndWait` 更新文字、再用 `CompletableFuture.runAsync(() -> pAll.getRight().run())` 執行、`future.get()` 等它做完。任務失敗時記 `Log.error`，並用 `future.complete(null)` 強行標記完成好繼續跑下一個任務。
- **程式碼**：

  ```java
  public void execute() {
      new Thread(() -> {
          Pair<String, Runnable> pAll;
          while ((pAll = queue.poll()) != null) {
              Pair<String, Runnable> finalPAll = pAll;
              PlatformApp.runAndWait(() -> label.setText(finalPAll.getLeft()));

              CompletableFuture<Void> future = null;
              if (finalPAll.getRight() != null) {
                  try {
                      future = CompletableFuture.runAsync(() -> finalPAll.getRight().run());
                      future.get();
                  } catch (Exception e) {
                      Log.error("加载出错了", e);
                      if (future != null) {
                          future.complete(null);
                      }
                  }
              }
          }
      }).start();
  }
  ```

  ```java
  Log.error(Object msg, Throwable t)   // v010 查 Log.java 確認的簽章
  ```

- **坑**：本課踩到的第二個真錯誤：v009 版本在 Lambda 裡直接用迴圈變數，編譯報
  `Variable used in lambda expression should be final or effectively final`。
  v011 示範的超時寫法 `future.get(1, TimeUnit.SECONDS)` 配 `sleep(3000)`，訊息又寫「map 10秒內未載入完畢」，且 `Log.error` 只傳一個參數與簽章不符——**該段最終正確形式無法從素材確定**。執行緒輔助類名有 `SleepUtil`（v006）與 `ThreadUtil`（v011–v013）兩名，v013 日誌時間戳證明 `ThreadUtil` 可信度較高。FX 執行緒 API 也有 `PlatformImpl`（口述與 v012）與 `PlatformApp`（v010 畫面）兩種寫法，以口述的 `PlatformImpl` 為準。
- **相關**：見 W14-014

### W06-009　`label` 提升為 `final` 類別欄位，Lambda 變數要 effectively final

- **關鍵字**：`label` `private final Label` `effectively final` `finalPAll` `setText` `getLeft`
- **來源**：第九課 36:00–40:00、40:00–44:00｜`L09_第九课_教學筆記.md`
- **要點**：子執行緒要更新 UI，`label` 必須從建構子的區域變數提升成類別欄位；因為是在建構方法裡賦值、類初始化時就會執行，所以可以直接宣告 `final`。同理，`while` 迴圈中被重新賦值的變數不能直接在 Lambda 內使用，要先 `Pair<String, Runnable> finalPAll = pAll;` 再拿 `finalPAll.getLeft()` 更新文字。
- **程式碼**：

  ```java
  // 1. 新增類別欄位
  private final Label label;

  // 2. 建構子中修改 label 初始化方式
  // 原本: Label label = new Label("Loading...");
  label = new Label("Loading...");
  ```

- **坑**：本課的 `execute()` 有兩代版本並存：v009 用 `Platform.runLater`（非同步），v010 改為 `PlatformApp.runAndWait`（要等 UI 更新完才往下走）。口述理由是「我不想讓它異步執行了，我想讓它 UI 更新完了之後，然後再執行下面的代碼」——要照抄就必須用 `runAndWait` 而不是 `runLater`。
- **相關**：見 W14-014

### W06-010　佇列清空後用 `runAndWait(this::close)` 讓彈窗自動消失

- **關鍵字**：`this::close` `PlatformImpl.runAndWait` `Stage.close` `execute` `queue.poll` `null`
- **來源**：第九課 48:00–52:00、52:00–53:08｜`L09_第九课_教學筆記.md`
- **要點**：佇列清空後，Loading 要自己把自己關掉，不要讓使用者操心。做法是在 `while` 迴圈結束之後、`new Thread(...)` 之內呼叫 `PlatformImpl.runAndWait(this::close)`。關閉後模態自動失效，主視窗又可以隨意操作。講者本課三點總結之一就是「執行完了之後就要把這個 loading 自己給我關掉」。
- **程式碼**：

  ```java
  // ⑥ 佇列清空 → 在 FX 執行緒關掉自己（出處：v012，解決「Loading 卡住不消失」）
  PlatformImpl.runAndWait(this::close);
  ```

- **坑**：**漏寫 `this::close` 就會出現「任務全跑完了、轉圈圈還卡在畫面上」**——這是 v012 親手重現並修掉的 bug：第一次執行時指示器與文字都不消失；加上 `this::close` 後重跑，任務完畢才順利消失。另外 `close()` 必須在 FX 執行緒呼叫，背景執行緒直接關視窗不行。
- **相關**：見 W14-014

### W06-011　啟動流程時序：設定任務 → 彈窗鎖主視窗 → 依序等待 → 就緒自動關閉

- **關鍵字**：`MenuStart` `MenuConfig` `loading.execute` `加載wz` `連接數據庫` `啟動伺服器` `正在加载配置` `建立网络连接` `Log.info`
- **來源**：第九課 44:00–48:00、48:00–52:00、52:00–53:08｜`L09_第九课_教學筆記.md`
- **要點**：完整時序為：① 在選單的 `show()` 裡 `new ProgressLoading(primaryStage)`（此時視窗彈出、主視窗被 `WINDOW_MODAL` 鎖住）；② 連續 `add()` 三個「顯示文字 + 要做的事」；③ 全部加完才呼叫 `loading.execute()` 開始依序執行；④ 每輪先更新 `label` 讓使用者看到當前步驟，跑完三步後彈窗自動 `close`、主視窗恢復可點。第九課示範的是三個業務步驟：加載 wz → 連接數據庫 → 啟動伺服器；有日誌佐證的版本則是：正在加载配置 → 加载一些图片资源 → 建立网络连接。
- **程式碼**：

### W06-012　用 `initialized` 旗標 + `ConfigServerDao` 靜態區塊保證資料庫連線就緒

- **關鍵字**：`SQLiteConnection` `initialized` `isInitialized` `ConfigServerDao` `static` `db.dao` `jdbc:mysql`
- **來源**：第十課 35:00–40:00、40:00–45:00｜`L10_第十课_教學筆記.md`
- **要點**：原本資料庫連線要等服務啟動後才取得，但「如果這個時候我服務沒啟動，我是不是也要能正常的去讀啊？」所以在 `SQLiteConnection` 加狀態旗標 `initialized`（預設 `false`），`init()` 開頭若已初始化就直接 `return`，跑完設 `true`，並提供 `isInitialized()` getter。`ConfigServerDao` 用**靜態代碼塊**保證連線就緒：類別一被載入就先檢查，未初始化就初始化，避免每個 DAO 重複初始化。

  ```java

  public static void init() {
      if (initialized) {
          return;
      }
      // ... 原有的連線初始化程式碼 ...
      initialized = true;
  }

  public static boolean isInitialized() {
      return initialized;
  }
  ```

  ```java
  package db.dao;

  import tools.SQLiteConnection;

  public class ConfigServerDao {

      static {
          if (!SQLiteConnection.isInitialized()) {
              SQLiteConnection.init();
          }
      }
  }
  ```


- **坑**：**資料庫種類衝突**——全課口述反覆說配置存在 **SQLite**（「是往我們的 sqlite 數據庫加啊，因為我們它的配置在 SQLite 數據庫，不在別的數據庫」），畫面 Database 面板卻是 MySQL 連線 `jdbc:mysql://127.0.0.1:3306/maple?...`；推測是「Java 端走 SQLite 連線類、維運工具看 MySQL」或錄製中切換過環境，**未經確認**。口述另稱旗標型別是 `AtomicBoolean`，畫面程式碼是 `boolean`，衝突。（連線字串後半段被截斷，完整參數不可得。）

### W06-013　`config_server` 既有七個欄位的意義與建表 SQL

### W06-016　`config_server` 的查詢層 SQL 逐字

- **關鍵字**：`selectPopular` `selectAll` `selectByWorld` `selectSql` `connection_select` `mapToEntity` `MapUtilsTo` `MapToEntity`
- **來源**：第十課 40:00–45:00、65:00–片尾｜`L10_第十课_教學筆記.md`
- **要點**：`select` 查全部、`selectPopular` 查常用（口述：「我們不需要去動這個方法啊，直接複製一下，叫 selectPopular 就好了」）。結果以 `mapList.stream().map(...).collect(...)` 轉成 `ConfigServer` list；口述稱這層工具是 `map to entity`。`update` 先留空殼（`update config_server set popular = 'false'`），講者說「我們後面用到的時候再寫」。空結果的保護已經做過，所以 DAO 層不重複判斷。
- **程式碼**：

  ```java
  public static List<ConfigServer> select() {
      List<Map<String, Object>> mapList = SqliteConnection.selectSql("select * from config_server");
      return mapList.stream().map(map -> MapUtilsTo.mapToEntity(map, ConfigServer.class)).collect(Collectors.toList());
  }

  public static List<ConfigServer> selectPopular() {
      List<Map<String, Object>> mapList = SqliteConnection.selectSql("select * from config_server where popular = 'true'");
      return mapList.stream().map(map -> MapUtilsTo.mapToEntity(map, ConfigServer.class)).collect(Collectors.toList());
  }

  public static void update() {
      SqliteConnection.updateSql("update config_server set popular = 'false'");
  }
  ```

  ```java
  public static List<ConfigServer> selectAll() {
      List<Map<String, Object>> mapList = SqlUtil.connection_select("select * from config_server");
      return mapList.stream().map(map -> MapToEntity.mapToEntity(map, ConfigServer.class)).collect(Collectors.toList());
  }

  public static List<ConfigServer> selectByWorld(int q) {
      // 此處修改了 SQL 字串拼接
      List<Map<String, Object>> mapList = SqlUtil.connection_select("select * from config_server where configWorld = " + q);
      return mapList.stream().map(map -> MapToEntity.mapToEntity(map, ConfigServer.class)).collect(Collectors.toList());
  }
  ```

- **坑**：**查詢層有兩套並存的類別**——`ConfigServerJson`（`moe.msq.tool.msq`，用 `SqliteConnection.selectSql` + `MapUtilsTo`）與 `ConfigServerDao`（`db.dao`），片尾段的 `selectAll`／`selectByWorld` 用的是 `SqlUtil.connection_select` + `MapToEntity`；推測是新舊兩版控制台程式碼並存，本課後半段主要在 `db.dao` 那一套。`selectByWorld` 用字串拼接組 SQL、沒有參數化，**是明顯的 SQL Injection 寫法，不宜照抄**（解析報告註記原本錯寫成 `where question = ?`，後改為 `configWorld`）。

### W06-018　背景執行緒操作 UI 會噴 `Not on FX application thread`

- **關鍵字**：`Not on FX application thread` `Platform.runLater` `RunAndWait` `ForkJoinPool` `ThreadUtil.execute` `ServerManager` `setDisable`
- **來源**：第十課 45:00–50:00、50:00–55:00｜`L10_第十课_教學筆記.md`
- **要點**：用 `ProgressLoading` 在背景執行緒撈資料後，若直接在該執行緒操作 UI 會直接噴 `IllegalStateException`。老師的說法是「如果你操作 UI 不在那個 JavaFX 的線程去操作 UI，因為我們的 loading 是一個異步的……所以我們在改動 UI 的時候一定要切回到那個 JavaFX 線程去更改 UI」。修法是包一層切回 FX 執行緒。伺服器啟動鈕同理：`ThreadUtil.execute` 丟背景執行緒跑 `ServerManager.getInstance().startServer(server)`，再 `Platform.runLater` 回 FX 執行緒切換按鈕可用性。
- **程式碼**：

  ```text
  java.lang.IllegalStateException: Not on FX application thread; currentThread = ForkJoinPool.commonPool-worker-25
  ```

  ```java
  // 修復前
  configServers = ConfigServer.getPopularServers();
  list.getItems().addAll(configServers);
  loading.execute();

  // 修復後
  configServers = ConfigServer.getPopularServers();
  Platform.runLater(() -> {
      list.getItems().addAll(configServers);
      loading.execute();
  });
  ```

  ```java
  startButton.setOnAction(e -> {
      //获取选择的服务器
      ConfigServer server = listConfigServer.getSelectionModel().getSelectedItem();
      if (server == null) {
          return;
      }

      ThreadUtil.execute(() -> {
          //启动服务器
          ServerManager.getInstance().startServer(server);

          Platform.runLater(() -> {
              startButton.setDisable(true);
              stopButton.setDisable(false);
              saveButton.setDisable(true);
          });
      });
  });
  ```

- **坑**：**口述說「我們就再給它包一層。RunAndWait」，但畫面修正後的程式碼是 `Platform.runLater`**——兩者語意不同（`runAndWait` 會阻塞呼叫端執行緒直到 UI 更新完成），實作請以畫面版本為準，但此點需向講者確認。這是本課唯一一個真正的「紅色錯誤」，其它 Bug 都是靜默的畫面不刷新，較難察覺。`ConfigServer.getPopularServers()` 這個方法名在筆記中只出現在修正前後對照片段，**其實作未記錄**。
