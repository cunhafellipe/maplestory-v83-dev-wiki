## 條目

### W09-001　讓每個功能頁 `extends MenuAbstract` 並只重寫 `show()`

- **關鍵字**：`MenuAbstract` `MenuPopular` `show()` `setRoot` `v2.menu` `TilePane`
- **來源**：第十七課 01:30–03:30｜`L17_第十七课_教學筆記.md`
- **要點**：`MenuAbstract` 是第十六課抽出的功能頁共用基底，統一管 `show()` / `destroy()` 這類頁面生命週期。
  新增一個功能頁時，只要 `extends MenuAbstract`、重寫一個 `protected void show()`，並在 `MenuEnum` 中指定
  該頁的列舉值即可，樣式與切換邏輯由基底類別統一處理，不必每頁重寫。
  `MenuPopular` 是第一個走完這個流程的頁面。
- **程式碼**：

  ```java
  package v2.menu;

  public class MenuPopular extends MenuAbstract {
      @Override
      protected void show() {
          // 原本寫了 System.out.println("Popular"); 後來又刪除了
      }
  }
  ```

  ```java
  // 口述定案的頁面骨架（第十七課 3.2 節骨架）
  root.setVgap(10);
  root.setHgap(10);

  setRoot(root);   // L16 沿用：MenuAbstract 提供的根節點設定
  ```

- **坑**：⚠️ `MenuAbstract` **只在第十七課出現**，第十八、十九課筆記完全沒有提到它；
  引用本條時請以第十六課筆記為準，不要把後兩課的畫面檔名當成 `MenuAbstract` 的來源。
  ⚠️ `MenuPopular` 的套件路徑有三種互斥說法：`v2/menu`（v000，有逐字 `package v2.menu;`）、
  `t.t.menu`（v002 推測）、`ui.menu`（v004）；**僅 v000 有可逐字引用的 package 敘述**。
  ⚠️ `show()` 的存取修飾層級在不同切片被記成 `protected` 與 `public` 兩種。
- **相關**：頁級 見 W04（選單系統與視圖切換）；條目 見 W14-012

### W09-002　功能頁用 `TilePane` 當容器，間距靠 `setVgap`／`setHgap`

- **關鍵字**：`TilePane` `setVgap` `setHgap` `setSpacing` `FlowPane` `addAll`
- **來源**：第十七課 08:00–10:30、16:00–19:00｜`L17_第十七课_教學筆記.md`
- **要點**：口述理由是「所有的子組件裡面用 Root，其實都是按照指定的比例去分佈的，
  所以我們用 TilePane 其實是比較好的」；`FlowPane` 是被提到的替代方案但沒採用。
  **`TilePane` 沒有 `setSpacing`**，要製造間距只能用 `setVgap` / `setHgap`。
- **程式碼**：

  ```java
  // 口述 a003：兩者皆為 10；畫面 v004 記為 12
  root.setVgap(10);
  root.setHgap(10);
  ```

  ```java
  // 畫面 v004 記錄的版本
  root.setVgap(12);
  root.setHgap(12);
  ```

  ```java
  root.getChildren().addAll(reloadEventButton, exitGameButton, searchAccountButton,
          banUnbanButton, modifyNxButton, sendGlobalMailButton, searchPlayerButton);
  ```

- **坑**：⚠️ **講者照本能反應寫 `root set spacing(...)`，實測「它沒有 spacing」**——
  照抄 `setSpacing` 會編譯失敗，必須改用 `setVgap` / `setHgap`。
  ⚠️ 間距數值口述 `10`、畫面 `12`，無法定案。
  ⚠️ 第十七課 10:30 的除錯記錄：只 `addAll` 一顆按鈕會導致「沒有給它加進去」，
  其餘按鈕不會出現在頁面上。
- **相關**：條目 見 W09-003、W09-001

### W09-004　用工廠方法 `createPopularButton` 產出功能頁專用按鈕

- **關鍵字**：`createPopularButton` `createAppButton` `ButtonUtils` `ButtonExt` `ButtonBase` `ButtonView`
- **來源**：第十七課 03:30–05:30、05:30–08:00｜`L17_第十七课_教學筆記.md`
- **要點**：功能頁的按鈕不直接 `new Button()`，而是交給一個靜態工廠方法統一產出樣式。
  入參是一個 `String text`。**同一個職責的按鈕工具類在本課被記成四個名字**，
  套件路徑也被記成三種，一律並列如下，無法判定最終類別名。
- **程式碼**：

  ```java
  // ① v001（口述亦稱 button utils / button util / ButtonUtil）
  //    推測路徑 view/menu/ButtonUtils.java
  public static Button createPopularButton(String text) {
      Button button = new Button(text);
  }

  // ② v002 / v003：ButtonExt.java，畫面推測套件 ui.util
  public static Button createPopularButton(String text) {
      region.setStyle("-fx-border-color: rgb(225, 225, 255); -fx-pref-width: 115; -fx-pref-height: 30;");
      button.setGraphic(region);
      return button;
  }

  // ③ v004 / v005：ButtonBase.java，畫面記套件 ui.kit、專案路徑 ui/base/
  public static Button createPopularButton(String text) { ... }

  // ④ v006：src/main/java/tools/ui/ButtonView.java（唯一有完整路徑，但與其他切片衝突）
  public static Button createIconButton(String text) { ... }
  public static Button createColorButton(String text, String color) { ... }
  public static Button createPopularBoardButton(String text) { ... }
  ```

- **坑**：⚠️ **方法名 `createPopularButton` vs `createAppButton`**：口述全程 `createPopularButton`，
  v001 畫面記為 `createAppButton` 且註解自述 `text 暂未用到`，**與口述「把 text 直接傳進去就好了」矛盾**。
  ⚠️ 四種類名（`ButtonUtils` / `ButtonExt` / `ButtonBase` / `ButtonView`）與
  套件路徑（`view/menu`、`ui.util`、`ui.kit`／`ui.menu`、`ui.base`）在本課全部並存，**照抄任一組都可能不符**。
  ⚠️ `ButtonView` 的三個方法出現在本課**最後 2 秒切片**（v006），
  且該切片解析極稀薄（20:34 之後約 3 分鐘畫面無法從素材還原），疑為後續版本。
  ⚠️ 第十九課筆記又記到 `UI.buttonUI.createPopularButton("发送全员信件(弹窗)", 0)`，
  **多了一個 `int` 參數**，是第三種簽名。
- **相關**：條目 見 W09-005、W09-007

### W09-005　`SVGPath` + `Region.setShape()` 做向量圖示，實作後退化成純色方塊

- **關鍵字**：`SVGPath` `setContent` `Region` `setShape` `setPrefSize` `setGraphic`
- **來源**：第十七課 05:30–08:00、10:30–13:00、16:00–19:00｜`L17_第十七课_教學筆記.md`
- **要點**：口述唯一一段方法論：「**為什麼要用 svg 而不用圖片，是因為我們這裡可能會對它的顏色做一些調整**，
  用圖片的話就沒辦法隨心所欲地改變我們的圖片的顏色」，並補一句
  「比較複雜的情況下的話，我們還是得用圖片」。做法是 `SVGPath.setContent()` 載入 `<path d="...">` 座標，
  用透明的 `Region` 包住並 `setShape()`，再 `button.setGraphic(region)`。
  **實作到後段發現 SVG 太麻煩，實際落地退化成一個純色方塊 `Region` 當圖示佔位符。**
- **程式碼**：

  ```java
  SVGPath svgPath = new SVGPath();
  svgPath.setContent("M25.3 104.2c-1.3-1.6-3.8-3.3-6.5-4.5-3.4-1.6... ");

  Region region = new Region();
  region.setShape(svgPath);

  // 口述 a001：依阿里雲盤實測 155 x 85；不給尺寸就「展示不出來」
  region.setPrefSize(155, 85);
  region.setStyle("-fx-pref-width: 155; -fx-pref-height: 85; "
                + "-fx-border-color: red;");        // 紅框僅為除錯用

  button.setGraphic(region);
  return button;
  ```

  ```java
  // 最終定案的純色方塊圖示（第十七課 3.5 節）
  region.setStyle("-fx-background-color: #2F64C0; -fx-pref-width: 25; -fx-pref-height: 25;");
  ```

- **坑**：⚠️ **`Region` 預設沒有大小**——講者明講「不然它 `Region` 默認就是一個沒有大小的一個東西」，
  不呼叫 `setPrefSize` 就永遠「展示不出來」。這是 SVG 按鈕方案最貴的一個坑。
  ⚠️ **`-fx-border-color` ≠ `-fx-background-color`**：想讓圖示著色卻寫成 `border-color`，
  結果 `Region` 整塊透明。講者原話：「**它为什么它是一个透明的呀？……哦，为什么我们设置了一个
  border color，而不是一个 background color 嗎？哎，怪不得，它是一个透明的。**」
  ⚠️ `Region` 尺寸記錄跨越 5 種：`setPrefSize(20,20)` → `115×30` → `15×25` → `15×20` → `25×25`，
  無法區分哪些是定案。
  ⚠️ 口述最後說主色「換成**青色**」，但 v004 記錄的 `#2F64C0` **是藍色不是青色**，
  口述「青色」對應的具體色值未出現在任何切片。
  ⚠️ 量測工具口述 **Snippers**、畫面記 **Snipaste**，兩種名稱並存。
- **相關**：條目 見 W09-006、W09-007

### W09-006　`setStyle` 只影響呼叫它的那個節點，寬高要掛在 `button` 上

- **關鍵字**：`setStyle` `-fx-pref-width` `-fx-pref-height` `region` `button` `setGraphic`
- **來源**：第十七課 08:00–10:30、10:30–13:00｜`L17_第十七课_教學筆記.md`
- **要點**：寬高一度寫在 `region` 上導致按鈕尺寸無效，必須移到 `button` 本身。
  講者當場的說法是「它的寬度和它的高度……不是，它，不是放在這的……是放在我們的 button 裡面的」。
  **JavaFX 的 `setStyle` 只影響呼叫它的那個節點，不會自動向下或向上繼承。**
- **程式碼**：

  ```java
  // 錯：寬高掛在 region 上
  region.setStyle("-fx-border-color: rgb(225, 225, 255); -fx-pref-width: 115; -fx-pref-height: 30;");

  // 對：寬高移到 button
  region.setStyle("-fx-border-color: rgb(225, 225, 255);");
  button.setGraphic(region);
  button.setStyle("-fx-pref-width: 115; -fx-pref-height: 30; -fx-background-color: #ffffff;");
  ```

- **坑**：⚠️ 樣式層級放錯不報錯、只是沒效果，屬於靜默失敗，除錯成本高。
  ⚠️ 按鈕尺寸在畫面層記錄了五種：`115×30`（v002）、`112×82`（v003）、`102×85`（v004）、
  `102×80`（v005）、高度 `40`（v006），部分為中途試作值。
- **相關**：條目 見 W09-005、W09-007

### W09-007　用 `-fx-content-display: top` 做圖文上下排版並定案整套按鈕樣式

- **關鍵字**：`Labeled` `ContentDisplay` `-fx-content-display` `-fx-graphic-text-gap` `-fx-font-size` `-fx-border-radius`
- **來源**：第十七課 13:00–16:00、16:00–19:00｜`L17_第十七课_教學筆記.md`
- **要點**：預設是圖文左右排版，要改成阿里雲盤那種上下排版，講者用 IDE 的 Go to Declaration
  追進 JavaFX 原生原始碼（`Button.java` → `ButtonBase.java` → `Labeled.java` → `ContentDisplay.java`）
  找到 `-fx-content-display`，可設上／右／下／左／中，或只顯示其一。
  逐項微調的順序是：`-fx-content-display: top` → 加大 `-fx-graphic-text-gap` →
  `-fx-font-size` → `-fx-font-weight: bold` → 背景設 `transparent` → 補邊框 → 圓角。
  邊框三參數的講法是「我們的 `border-color` 就是我們邊框的顏色」、「我們的邊框的寬度，
  `border-width`，我們設置成 2。因為它的邊框是比較寬的，**設置成 1 肯定是不行的**」。
- **程式碼**：

  ```java
  // 查閱 Labeled / ContentDisplay 原始碼後定案（v003）
  button.setStyle("-fx-pref-width: 112; -fx-pref-height: 82; -fx-content-display: top; -fx-graphic-text-gap: 12; -fx-font-size: 14;");
  ```

  ```java
  // 最終定案（v004）
  button.setStyle("-fx-pref-width: 102; -fx-pref-height: 85; -fx-content-display: top; -fx-graphic-text-gap: 12; -fx-font-size: 14; -fx-font-weight: bold; -fx-background-color: transparent; -fx-border-color: rgb(220, 227, 232); -fx-border-width: 2; -fx-border-radius: 12;");
  ```

- **坑**：⚠️ **背景設為 `transparent` 會連邊框一起「感覺消失」**，必須再補
  `border-color` / `border-width` / `border-radius`，講者原話是「**這個 style 就加的很長了**」。
  ⚠️ **三組數值衝突**（口述 vs 畫面）：`-fx-graphic-text-gap` `10` / `12`；
  `-fx-border-radius` `10` / `12`；`vGap`/`hGap` `10` / `12`。
  ⚠️ `-fx-font-size` 單位不一致：多數切片寫 `14`，v006 寫 `14px`。
  ⚠️ **主色調不宜全抄**：講者明講「我們學吧又不能全學它的色調」，
  並自嘲「我這糟糕的審美可能不一樣……比如說紫色？基佬紫？或者猛男粉？」——
  按鈕顏色是主觀選項，不是唯一正解。
- **相關**：條目 見 W09-005、W09-008

### W09-010　`InputBox` 以 `textProperty().addListener` 即時回填，`Arrays.fill(inputs, null)` 表示取消

  ```java
      root.getChildren().add(textInput);
      final int index = i;
      textInput.getTextField().textProperty().addListener((observable, oldValue, newValue) -> {
          inputs[index] = newValue;
      });
  }
  ```

  ```java

      return;
  }

      if (input == null) {            // 逐項防呆：使用者按了取消
          return;
      }
  }
  ```

### W09-013　重載事件腳本要先擋服務未啟動，再擋 `eventSM == null` 的競態

- **關鍵字**：`reloadEventButton` `isOnline` `reloadEventScriptManager` `getEventSM` `EventScriptManager` `isShutdown`
- **來源**：第十八課 00:00–03:00、03:00–06:00、06:00–09:00｜`L18_第十八课_教學筆記.md`
- **要點**：本課交付的第一個功能。順序是三段：① `Server.getInstance().isOnline()` 防呆，
  服務沒起來就提示並 `return`；② 用 `ProgressLoading` 走背景執行緒遍歷所有頻道；
  ③ 遇到 `eventSM == null` 的頻道直接跳過——因為服務剛啟動時 `init()` 最後一步正在背景
  初始化事件，此時重載會衝突。
- **程式碼**：

  ```java
  // Server / 主控台類別
  reloadEventButton.setOnAction(event -> {
      // ① 服務沒起來就不讓重載
      if (!Server.getInstance().isOnline()) {
          ConfirmBox.setInfoMessage("提示", "服务器未开启!");   // 點 yes / no 都可
          return;
      }

      ProgressLoading loading = new ProgressLoading(primaryStage);
      loading.add("正在重载事件...", () -> {
          for (Channel ch : Server.getInstance().getAllChannels()) {
              // ② 服務剛啟動時 eventSM 尚未初始化，此時重載會衝突 → 直接跳過
              if (ch.getEventSM() != null) {
                  ch.reloadEventScriptManager();
              }
          }
      });
      loading.execute();
  });
  ```

  ```java
  // 底層方法（Channel，synchronized，約第 290 行）
  public synchronized void reloadEventScriptManager() {
      if (isShutdown()) {
          return;                       // 已關閉 → 什麼都不做
      }

      if (null != eventSM) {
          eventSM.cancel();             // 先取消舊的
          eventSM = null;
      }
      eventSM = new EventScriptManager(this, getEvents());   // 再重新載入
  }
  ```

- **訊息字串**（兩層並存）：`服务器未开启!`（`ConfirmBox.setInfoMessage`）／
  `服务器未开启无法重载！`（`MessageBox.showInfo`）／

  `重载所有频道的事件脚本完成，请查看控制台！`（畫面 v001）。

- **坑**：⚠️ **本課最核心的坑是服務啟動與手動重載的競態**：
  `init()` 會在背景執行緒初始化事件，此時 `eventSM == null`，使用者同時點重載就會衝突，
