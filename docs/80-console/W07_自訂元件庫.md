### W07-001　用 `Rectangle` + `Circle` 手刻 Win11 風格的 `SwitchButton`

- **關鍵字**：`SwitchButton` `StackPane` `Rectangle` `Circle` `ToggleSwitch` `40 20`
- **來源**：第十一課 08:00–12:00、20:00–24:00、24:00–28:00、28:00–32:00｜`L11_第十一课_教學筆記.md`
- **要點**：JavaFX 內建沒有開關元件，老師決定自己刻一個模仿 Windows 11 原生 Toggle Switch
  外觀的自訂元件。做法是 `class SwitchButton extends StackPane`（**明講「它又不是繼承我們的
  button」，是繼承 `stack pane`**），底板用 `Rectangle`、撥桿用 `Circle`。
  建構子一定要傳 `double width` 與 `double height`，理由是「它不會像我們其他的組件一樣會有
  一個自適應，它就會縮成一團」。尺寸由 `50 25` 收到定案 `40 × 20`；因寬高由呼叫端傳入，
  可拉長成 `160` 與上方輸入框對齊。
  講者明講不引第三方 `ToggleSwitch` 依賴：「那個開關按鈕也不是特別好看」且
  「為了（一個開關按鈕）去引一個依賴包進來……成本還是有點大」，加上網路上查不到教學。
- **程式碼**：

  ```java
  public class SwitchButton extends StackPane {

      private final AtomicBoolean on = new AtomicBoolean(true);
      private final Rectangle rectangle;
      private final HBox rectangleBox;
      private final Circle circle;
      private final HBox circleBox;

      public SwitchButton(double width, double height) {
          // ── 底板：膠囊形 Rectangle ──
          rectangle = new Rectangle(width, height);
          rectangle.setStrokeWidth(1);          // 口述：外邊框寬度設為 1
          rectangle.setArcWidth(height);        // 口述推導後的結論：弧度直接用 height
          rectangle.setArcHeight(height);

          // 長方形不動 → 直接置中
          rectangleBox = new HBox(rectangle);
          rectangleBox.setAlignment(Pos.CENTER);

          // ── 撥桿：Circle ──
          circle = new Circle();
          circle.setRadius(height * 0.75 / 2);  // 直徑 = height * 0.75，半徑再除以 2

          circleBox = new HBox(circle);
          // 上 0、右 6、下 0、左 6（口述）
          circleBox.setPadding(new Insets(0, 6, 0, 6));
          circleBox.setAlignment(Pos.CENTER_LEFT);   // 預設關閉＝居左

          getChildren().addAll(rectangleBox, circleBox);

          initStyle();

          // ── 點擊事件：綁在父容器上，內部任何位置都收得到 ──
          setOnMouseClicked(event -> on.set(!on.get()));
      }

      public boolean isOn() {
          return on.get();
      }

      public void setOnOff(boolean onOff) {
          on.set(onOff);
          initStyle();   // 手動設定狀態後必須重繪
      }
  }
  ```

- **測試用主程式**（單獨測元件時）：

  ```java
  // 單獨測 SwitchButton
  HBox root = new HBox();
  SwitchButton switchButton = new SwitchButton(40, 20);   // 口述最終定案尺寸 40×20
  root.getChildren().add(switchButton);

  // 拉長成 160 與上方輸入框對齊
  TextSwitch wide = new TextSwitch("test", 160, 20);
  ```

- **坑**：
  1. **沒有動畫是已知缺陷**，講者明講「它沒有動畫……動畫確實好像有點難實現，然後所以我就放棄了」。
     這是「抄 Windows 11」的複製品，不是原生效果。
  2. **同一個類別在四個畫面切片被記成四個名字**：口述與 `v005` / `v007` 為 `SwitchButton`，
     但 `v002` 記成 `IntroButton`、`v003` 記成 `ItemPane`、`v006` 記成 `SelectButton`。
     套件名同樣分歧（`ms.component` / `mi.component` / `server.ui.component` / `server.console.control`）。
     **筆記疑有誤，待查**：以口述與多數切片一致的 `SwitchButton` 為準，不要照抄異名。
  3. **狀態欄位型別與名稱有五種寫法**：`v002` `AtomicBoolean isHover`、`v003` `AtomicBoolean isOn`、
     `v004`/`v005` `AtomicBoolean on`、`v007` `SimpleBooleanProperty state`；口述全程只提
     `boolean on`（預設 `true`）與 `isOn()` / `setOnOff()`，**未提過 `SimpleBooleanProperty`**。
  4. **同一個「設定開關狀態」動作有五種方法名**：`isOn` / `setOn` / `set` / `setOnOff` / `setSelected`。
     筆記判斷口述的 `setOnOff` 與 `isOn` 配對最穩定。
  5. **`v006` 的 `Color.rgb` 四參數寫法不合法**：`Color.rgb(0, 165, 100, 111)` 這類寫法不是合法的
     `Color.rgb` 呼叫，筆記判為解析誤讀，不可照抄。
- **相關**：見 W07-002、W07-003、W07-004、W07-005、W07-006

### W07-002　`StackPane` 不能對齊子圖形，形狀要各包一層 `HBox`

- **關鍵字**：`StackPane` `HBox` `setAlignment` `Pos.CENTER_RIGHT` `Pos.CENTER_LEFT`
  `getChildren().get(0)` `ClassCastException`
- **來源**：第十一課 20:00–24:00、24:00–28:00｜`L11_第十一课_教學筆記.md`
- **要點**：`SwitchButton` 一開始把 `Rectangle` 與 `Circle` 直接 `getChildren().addAll()` 進
  `StackPane`，結果「它关的时候是不是在最左边？开的时候是不是在最右边？」——圓球永遠卡在正中間，
  開關等於壞掉。原因是 **`StackPane` 只管堆疊，不管你要的對齊**。
  解法是「既然我们的图形，它是没办法设置布局或者对齐方式的，那我们就把它包一层。包成什么？`HBox`」：
  底板與撥桿各包一個 `HBox`，底板固定 `Pos.CENTER`（它不動），撥桿依狀態在
  `Pos.CENTER_LEFT` / `Pos.CENTER_RIGHT` 之間切換。
  改完之後還要解決「怎麼把形狀再拿出來」的問題。
- **程式碼**（`v006` 畫面記到的 `HBox` 包裝 + `Padding` 版本）：

  ```java
  public SelectButton(double width, double height) {
      Rectangle rectangle = new Rectangle(width, height);
      rectangle.setArcWidth(height);
      rectangle.setArcHeight(height);

      HBox circleBox = new HBox();
      circleBox.setPadding(new Insets(0, 5, 0, 5));
      Circle circle = new Circle();
      circle.setRadius(height * 0.75 / 2);

      circleBox.getChildren().add(circle);
      getChildren().addAll(rectangle, circleBox);

      initStyle();
  }
  ```

- **形狀取出方式的兩條路（筆記中先後出現過）**：
  1. **欄位化**（`v005` 重構後）——`private final Rectangle background;` / `private final Circle circle;`，
     之後 `initStyle()` 直接用，不再傳參。口述：「它已经是全局变量了，还传啥呀？」
  2. **`getChildren().get(0)` 強轉取用**——口述：「叫我们的 `rectangle box get children dot get 0`……
     然後就是这个长方形，那我们直接把它获取到，然后强转就完事儿了。」
- **坑**：
  1. **`getChildren().get(0)` 的強轉取用依賴 `addAll` 的加入順序**，一旦有人調整節點順序
     就會 `ClassCastException`。較穩的寫法是把形狀存成類別欄位。**筆記疑有誤，待查**：
     課堂上實際走的順序是先欄位化、後又回退，中間有反覆。
  2. **`circleBox` 的外邊距口述與畫面不一致**：口述是「距離上邊 `0`、右邊 `6`、下邊 `0`、左邊 `6`」，
     `v006` 畫面卻記成 `new Insets(0, 5, 0, 5)`。兩者都保留，筆記建議以口述為準。
  3. **`v006` 整段（類別名、色系、間距）與前後片段全面衝突**，筆記判斷為解析誤讀。
- **相關**：見 W07-001、W07-004

### W07-003　開關幾何常數：弧度直接用 `height`、半徑 `height * 0.75 / 2`

- **關鍵字**：`setArcWidth` `setArcHeight` `setRadius` `setStrokeWidth` `0.75` `height`
- **來源**：第十一課 12:00–16:00、24:00–28:00｜`L11_第十一课_教學筆記.md`
- **要點**：這兩個數字是本課最有價值的推導過程，老師繞了一圈才想通。
  **弧度**先想成「寬除以高，再用寬除以那個倍數」，接著自己推翻：
  「那這樣不就是我們的高嗎？……好傢伙，我這考慮了半天好像直接取我們的高就行了。失誤了。」
  → 結論 `rectangle.setArcWidth(height)` / `rectangle.setArcHeight(height)`，配 `setStrokeWidth(1)`。
  **圓半徑**最初估「直徑差不多 `10` 分之 `6`……半徑 `5` 分之 `3`」，打算用高乘以 `0.6`，
  實際拿畫圖工具量之後改口：「它好像有四分之三那麼大」→ `circle.setRadius(height * 0.75 / 2)`。
- **程式碼**：

  ```java
  rectangle = new Rectangle(width, height);
  rectangle.setStrokeWidth(1);          // 口述：外邊框寬度設為 1
  rectangle.setArcWidth(height);        // 口述推導後的結論：弧度直接用 height
  rectangle.setArcHeight(height);

  circle = new Circle();
  circle.setRadius(height * 0.75 / 2);  // 直徑 = height * 0.75，半徑再除以 2
  ```

- **坑**：
  1. **半徑公式要自己量，不要照抄 `0.6`**：`0.6`（3/5）是口述初估值，本課最終定案是 `0.75`。
     24:00–28:00 口述又說「它的圆好像小一点。小一点，那我们应该是 `3/5`……那就是乘 `0.6`」，
     但程式碼骨架與 04:00–08:00 之後的畫面都維持 `height * 0.75 / 2`。**筆記疑有誤，待查**。
  2. **`setStrokeWidth` 值有出入**：口述與骨架為 `1`，`v002` 畫面曾為 `2`。
  3. 圓半徑在過程中一度被寫成 `height / 2.75 / 2`，隨後修正為 `height * 0.75 / 2`（`v003` 記錄）。
- **相關**：見 W07-001

### W07-004　`initStyle()` 依狀態換色換對齊，手動改狀態後必須重繪

- **關鍵字**：`initStyle()` `setFill` `setStroke` `setAlignment` `Color.rgb` `重繪`
- **來源**：第十一課 16:00–20:00、20:00–24:00｜`L11_第十一课_教學筆記.md`
- **要點**：開關的所有視覺變化（顏色 + 圓的位置）集中在同一個 `private void initStyle()` 裡，
  依 `on.get()` 分成開機／關機兩套。設計的觸發點是「我們在這裡只設置了它的第一個邊框長度，
  第二個它的彎曲程度，第三個它的半徑，但是我們還沒有設置顏色」。
  **關鍵紀律：手動改狀態（`setOnOff`）與滑鼠點擊之後都必須再呼叫一次 `initStyle()`**，
  講者原話：「我们开启关闭完了是不是要 `init` 一下 `style` 呀？让它的 `style` 发生一下变化。
  不然的话不就白开了吗？」
- **程式碼**：

  ```java
  private void initStyle() {
      if (on.get()) {
          // 開啟：藍底藍框 + 白圓，圓靠右
          rectangle.setFill(Color.rgb(0, 103, 192));
          rectangle.setStroke(Color.rgb(0, 103, 192));
          circle.setFill(Color.rgb(255, 255, 255));
          circleBox.setAlignment(Pos.CENTER_RIGHT);
      } else {
          // 關閉：灰底灰框 + 灰圓，圓靠左
          rectangle.setFill(Color.rgb(255, 255, 255));
          // 口述把關閉色念成「939394」又改口成「939393」——應是六位數色碼 #939393
          rectangle.setStroke(Color.rgb(0x93, 0x93, 0x93));
          circle.setFill(Color.rgb(0x93, 0x93, 0x93));
          circleBox.setAlignment(Pos.CENTER_LEFT);
      }
  }
  ```

- **坑**：
  1. **漏呼叫 `initStyle()` 的後果是「狀態變了但顏色不變」**——第一次執行測試時就出現過
     「點擊後圓形滑塊會移動但樣式未到位」的現象。
  2. **配色四套並存，不可照抄任一套**（詳見 W07-006）。
  3. `initStyle` 原本簽章是 `private void initStyle(Rectangle rectangle, Circle circle)`（`v004` 畫面），
     後來因形狀無法在切換時取得，才改成拿全域／類別欄位、不再傳參。
- **相關**：見 W07-006

### W07-005　點擊事件掛在 `StackPane` 上，內部任何位置都收得到

- **關鍵字**：`setOnMouseClicked` `on.set(!on.get())` `initStyle` 事件掛在父容器
- **來源**：第十一課 24:00–28:00、28:00–32:00｜`L11_第十一课_教學筆記.md`
- **要點**：開關的點擊事件**不掛在 `Rectangle` 或 `Circle` 上，而是掛在 `StackPane` 這個父容器上**。
  理由講得很直接：「直接给这个 `stack pane` 一个点击事件就好了。那么这样的话，
  它里面所有的东西都点得到了……只要点到这个容器里面任何位置都会触发这个事件。」
  事件內容就是反轉狀態（`on.set(!on.get())`），之後必須呼叫 `initStyle()` 重繪。
- **程式碼**：

  ```java
  setOnMouseClicked(event -> {
      set(!get());
  });
  ```

  （`v007` 畫面逐字為 `set(!get())`；口述與 `SwitchButton` 骨架為 `setOnMouseClicked(event -> on.set(!on.get()))`。
  兩種寫法都保留，見坑。）

- **坑**：
  1. **事件體的寫法兩處不一致**：口述／骨架是 `on.set(!on.get())`（作用在 `AtomicBoolean` 欄位上），
     `v007` 畫面則是 `set(!get())`（呼叫自己某個 setter／getter）。照抄前要先確認欄位型別是
     `AtomicBoolean` 還是 `SimpleBooleanProperty state`（見 W07-001 坑 3）。
  2. **「點完必須重繪」**：只在事件裡 `on.set(...)` 而不呼叫 `initStyle()`，畫面不會變。
  3. 影片末段曾開始寫 `setOnMouseEntered(event -> { set...`，在自動補全選單中挑選 `setCursor` 時
     即中斷，**hover 效果在本課未完成**（素材未顯示，筆記未確定）。
- **相關**：見 W07-004

### W07-006　開關配色：口述與畫面四套 RGB 並存，不可照抄任一套

- **關鍵字**：`Color.rgb` `setFill` `setStroke` `0 103 192` `0, 120, 215` `#0060A9` `#CCCCCC`
  `吸色器`
- **來源**：第十一課 16:00–20:00、20:00–24:00、24:00–28:00、28:00–32:00｜`L11_第十一课_教學筆記.md`
- **要點**：老師反覆開 Windows 11「藍牙與其他裝置」用吸色器取 Win11 原生開關的真實 RGB，
  再全部填回 `initStyle()`。但**口述與不同畫面切片給出四套互斥的數值**，本筆記無法判定哪一套
  是當下螢幕上的真實值，因此四者全部保留、不得靜默選一邊。
  口述有「我們再看一下。確認一下啊」這種即時覆誦，筆記認為可信度相對較高。
- **四套數值並存**：

  | 出處 | 開啟態 | 關閉態 |
  |---|---|---|
  | 口述吸色 | 底板／邊框 `0 103 192`、白圓 `255 255 255` | 邊框與圓 `939394`（當場改念 `939393`） |
  | 畫面 `v004` 吸色工具 | `RGB (0, 120, 215)` | 邊框 `RGB (208, 208, 208)`、背景 `RGB (235, 235, 235)` |
  | 畫面 `v007` 執行結果 | `#0060A9` | `#CCCCCC` |
  | 畫面 `v006` | 綠色系 `Color.rgb(0, 165, 100, 111)` | 灰 `Color.rgb(92, 99, 106, 111)` / `Color.rgb(243, 244, 245, 111)` |

- **坑**：
  1. **四套數值互斥，不得自行合併或挑一套寫死**。要重做這一段，先自己在目標 OS 上重新吸色。
  2. **`v006` 的四參數 `Color.rgb(0, 165, 100, 111)` 不合法**，`Color.rgb` 不接受第 4 個參數，
     筆記判為解析誤讀。
  3. 關閉色的 `939394` / `939393` 在口述中是「六位數色碼」被唸成三位分組，骨架寫成
     `Color.rgb(0x93, 0x93, 0x93)`。
  4. 目標 OS 參照是 Windows 11；講者說自己那台筆本是 Win10，「既然這個是 Win11 的話，
     我們就按 Win11 的樣式來」。

### W07-007　`TextChoose`（`Label` + `ToggleGroup` 單選）與被 `TextSwitch` 取代的理由

- **關鍵字**：`TextChoose` `RadioButton` `ToggleGroup` `getChoose()` `select(int)` `可變參數`
- **來源**：第十一課 00:00–04:00、04:00–08:00、36:00–38:49｜`L11_第十一课_教學筆記.md`
- **要點**：這是本課的**第一版方案**，用一組綁在同一個 `ToggleGroup` 的 `RadioButton`
  取代手打 `true` / `false` 字串。`class TextChoose extends HBox`，左邊 `Label`、右邊
  可變參數 `String... btnTexts` 決定有幾個選項；另補 `getChoose()` 讀值與 `select(int index)` 回填預設。
  跑起來確認可用後，講者自己說「苦思冥想了一天，上班摸了不少魚」，覺得 `RadioButton` 太醜，
  決定改做開關，結尾正式宣佈棄用。
- **程式碼**：

  ```java
  public class TextChoose extends HBox {

      private final Label label;
      private final List<RadioButton> radioButtonList = new ArrayList<>();

      public TextChoose(String text, String... btnTexts) {
          // 1. 初始化標籤並加入 HBox
          label = new Label(text);
          getChildren().add(label);

          // 2. 建立 ToggleGroup 確保單選行為
          ToggleGroup toggleGroup = new ToggleGroup();

          // 3. 迴圈處理傳入的按鈕文字
          for (String btnText : btnTexts) {
              RadioButton radioButton = new RadioButton(btnText);
              radioButton.setToggleGroup(toggleGroup); // 綁定 ToggleGroup
              radioButtonList.add(radioButton);        // ← 口述要求：也要存進 List，getChoose() 要用
              getChildren().add(radioButton);
          }

          // 4. 設定 HBox 內部元件的間距與對齊方式
          setSpacing(5);
          setAlignment(Pos.CENTER);
      }

      // 獲取目前選中的 RadioButton
      public RadioButton getChoose() {
          return radioButtonList.stream()
                  .filter(radioButton -> radioButton.isSelected())
                  .findFirst()
                  .orElse(null);
      }

      // 根據索引值設定 RadioButton 為選中狀態
      public void select(int index) {
          radioButtonList.get(index).setSelected(true);
      }

      public Label getLabel() {
          return label;
      }
  }
  ```

- **坑**：
  1. **`radioButtonList.add(radioButton)` 不可漏**：`getChoose()` 是 `stream().filter()` 出來的，
     迴圈裡若只 `getChildren().add()` 而沒存進 `List`，`getChoose()` 永遠是空的。
  2. **元件取名講者口誤為 `text true`**，實際寫的是 `TextChoose`（畫面確認）。
  3. `getChoose()` 找不到被選中者時 `orElse(null)` 回 `null`，呼叫端必須自行處理。
- **相關**：見 W07-008

### W07-011　`showAndWait()` + `AtomicBoolean result` 讓呼叫端等使用者選完

- **關鍵字**：`showAndWait` `AtomicBoolean` `result` `yes` `no` `yesAndNo` `阻塞` `void`
- **來源**：第十三課 15:00–20:00、40:00–45:00｜`L13_第十三课_教學筆記.md`
- **要點**：這是第十三課最關鍵的一段設計解釋。要回傳「使用者是點確認還是取消」，
  就不能回傳 `void`：「它不能返回一個 void，它要返回一個 Boolean……
  我們在這裡我們就可以來一個 AtomicBoolean，叫 result。默認是 false。」
  點 yes → `result.set(true)` 並 `stage.close()`；點 no → `result.set(false)` 並關窗。
  接著 `stage.showAndWait()` 讓主執行緒停在這裡等使用者選完，再 `return result.get()`。
  另兩個方法 `yes(...)` / `no(...)` 只有一顆按鈕，點了必定是那一顆，所以回傳 `void` 就好。
- **程式碼**：

  ```java
  AtomicBoolean result = new AtomicBoolean(false);

  if (type == 1) {
      Button subButton = ButtonUtil.createBaseButton("确认");
      subButton.setOnAction(event -> {
          result.set(true);
          stage.close();
      });
      Button canButton = ButtonUtil.createBaseButton("取消");
      canButton.setOnAction(event -> {
          result.set(false);
          stage.close();
      });
  }

  stage.showAndWait();
  return result.get();
  ```

  三個對外方法與便利重載：

  ```java
  /** 只有「確認」一顆，點了就是確認，所以回傳 void */
  public static void yes(Stage primaryStage, String text) {
      yesAndNo(primaryStage, text, YES);
  }

  /** 只有「取消」一顆，點了就是取消，所以回傳 void */
  public static void no(Stage primaryStage, String text) {
      yesAndNo(primaryStage, text, NO);
  }

  /** 兩個按鈕都有，需要知道使用者選了哪一個 → 回傳 boolean */
  public static boolean yesAndNo(Stage primaryStage, String text) {
      return yesAndNo(primaryStage, text, BOTH);
  }
  ```

  呼叫端（接在存檔按鈕上）：

  ```java
  saveButton.setOnAction(event -> {
      // 放在最前面，任何後續邏輯前都先確認
      if (!ConfirmBox.yesAndNo(primaryStage, "确认修改并保存吗？", ConfirmBox.BOTH)) {
          return;                       // 取消 → 不往下走
      }
      try {
          ConfigServerDao.update(configList);
          MessageBox.showInfo(primaryStage, "保存成功");
      } catch (Exception e) {
          MessageBox.showError(primaryStage, "保存失败");
          log.error("保存常用配置异常", e);
      }
  });
  ```

- **坑**：
  1. **`showAndWait()` 會阻塞呼叫端**——這正是 `ConfirmBox` 要的效果；但 `MessageBox` 若也用它，
     UI 執行緒會卡住，**絕對不可沿用**（見 W07-013）。
  2. **`showAndWait` 必須放在 UI 執行緒上呼叫**；`ConfirmBox` 的呼叫點位於 `setOnAction` 內。
  3. **影片中 `showAndWait` 被口述誤念成「show 亦和」**，逐字稿已修正；遇到此誤聽以
     `showAndWait` 為準。
  4. **實測後發現外觀有問題**：口述「好，那我們剛剛看到這個界面是，有問題的。所以我們還要，
     美化一下這個確認窗口」——功能可用但外觀未完成美化（見 W07-015）。
  5. 存檔處的 `try-catch` 要**包住整個存檔動作**，順序寫反會出現「明明存失敗卻提示成功」。

### W07-013　`LinkedBlockingQueue` 排隊顯示提示框，避免疊在一起

- **關鍵字**：`LinkedBlockingQueue` `offer` `peek` `poll` `Platform.runLater` `waitAndShow`
  `Thread.sleep` `ViewUtil.sleep` `100` `3000`
- **來源**：第十三課 35:00–40:00、40:00–45:00、45:00–50:00｜`L13_第十三课_教學筆記.md`
- **要點**：`show` 可能被連續多次呼叫，提示框會疊在一起，所以要「跟 progress loading 一樣，
  我們得來個隊列」。佇列 API 的教學口徑：「它是一個先進先出嘛，所以我們往後塞，
  但是我們拿的時候是拿第一個……我們隊列還有一個 `peek` 的方法，它拿到以後它不會把這個隊列刪除。」
  等待條件寫成「還沒輪到我（`nowStage != stage`）」，每 `100` 毫秒睡一次；
  輪到時 `Platform.runLater` 顯示、停 `3000` 毫秒、`Platform.runLater` 關閉、然後 `poll()` 移出。
  為什麼要開子執行緒：「我們不能讓，讓我們得 UI 線程調完 showAndWait 卡在這裡對不對？
  那我們要在子線程裡面去做。」
- **程式碼**：

  ```java
  import java.util.concurrent.LinkedBlockingQueue;
  private static final LinkedBlockingQueue<Stage> queue = new LinkedBlockingQueue<>();
  ```

  ```java
  private static void waitShow(Stage stage) {
      // 將新的提示視窗加入佇列
      queue.offer(stage);

      // 啟動新執行緒處理佇列
      new Thread(() -> {
          try {
              Stage outStage;
              // 使用 peek() 檢查佇列頂端元素，不為空則進入迴圈
              while ((outStage = queue.peek()) != null) {
                  Thread.sleep(100);      // 顯示前稍微等待

                  // 必須透過 Platform.runLater 在 JavaFX 主執行緒更新 UI
                  Platform.runLater(outStage::show);

                  Thread.sleep(3000);      // 讓提示訊息停留 3 秒

                  // 關閉視窗
                  Platform.runLater(outStage::close);

                  // 將已處理完的視窗移出佇列
                  queue.poll();
              }
          } catch (Exception e) {
              // 畫面中未詳細寫出 catch 處理邏輯，僅保留 IDE 生成的預設結構
          }
      }).start();
  }
  ```

  口述敘述的定案版本（方法名取第一次出現的 `WaitAndShow`；等待條件明確寫成「還沒輪到我」）：

  ```java
  /** 依佇列順序逐一顯示：每則停 3 秒後自動關閉 */
  private static void waitAndShow(Stage stage) {
      queue.offer(stage);
      new Thread(() -> {
          try {
              Stage nowStage;
              // 還沒輪到我 → 每 100ms 睡一次
              while ((nowStage = queue.peek()) != null && nowStage != stage) {
                  ViewUtil.sleep(100);
              }
              Platform.runLater(nowStage::show);     // 子執行緒不能直接動 UI
              ViewUtil.sleep(3000);                  // 停留 3 秒
              Platform.runLater(nowStage::close);
              queue.poll();                           // 處理完才移出
          } catch (Exception e) {
              e.printStackTrace();
          }
      }).start();
  }
  ```

  配套的 sleep 包裝（口述提及「我們 viewutil 寫了一個，封裝了一個 sleep 方法，等 100 毫秒」，
  **畫面層未捕捉到實作**）：

  ```java
  /** 佇列等待用的 sleep 包裝（口述提及，等 100 毫秒；畫面層未捕捉到實作） */
  public static void sleep(long millis) {
      try {
          Thread.sleep(millis);
      } catch (InterruptedException e) {
          Thread.currentThread().interrupt();
      }
  }
  ```

- **坑**：
  1. **`peek()` 不會移除元素**，所以等待條件必須寫成「還沒輪到我（`nowStage != stage`）」
     並在真正顯示完後才 `poll()`，否則會無限重複顯示同一則。
  2. **從非 FX 執行緒操作 UI 會拋例外**：`queue.peek()` / `Thread.sleep()` 只能在子執行緒做，
     `show()` / `close()` 必須包在 `Platform.runLater(...)` 裡。
  3. **絕對不能用 `showAndWait()`**（會卡住 UI 執行緒），見 W07-011。
  4. **有一版邏輯有誤的過渡程式被畫面層記到，列出以免誤抄**：

     ```java
     while ((stage = queue.peek()) != stage) { // 這裡邏輯有誤，作者後續發現
         Thread.sleep(100);
     }
     ```

     畫面層自己也註明「這裡邏輯有誤，作者後續發現」，且「這裡欠缺等待視窗關閉的機制」。
  5. **不要 `show()` 後就直接 `stage.show()`**——骨架註明「不要直接 show()，交給佇列排隊」。
  6. **方法名在口述中出現三種語序**（`WaitAndShow` / `ShowAndWait` / `WaitAndShow`），
     筆記取第一次出現的 `WaitAndShow`。
  7. **修飾符順序**：講者口述強調「`private final...` `static final` 吧，把 static 放前面」。
  8. `show` 三參數版曾在 `v007` 被記成用 `VBox root`（與口述的 `HBox` 不符），以口述為準。
  9. **實機驗收通過**：「我們點一下，再點一下，再點一下，它要觸發三次……它會等前面一個執行完，
     它才執行。」這是本課最核心的功能驗收點。

### W07-014　非 Modal 提示框要自己跟主視窗跑：`xProperty()` / `yProperty()` listener

- **關鍵字**：`xProperty` `yProperty` `addListener` `doubleValue` `位移差` `不跟隨` `initModality`
- **來源**：第十三課 45:00–50:00、50:00–52:00｜`L13_第十三课_教學筆記.md`
- **要點**：`MessageBox` 不設 `initModality` 讓主視窗仍可拖曳，**副作用就是提示框不會跟著跑**——
  「我們這個時候移動……它不會隨著我們窗口進行移動。它就會有一個問題，就是我們窗口在移動的時候，
  誒。它還在原位置。」原因診斷講得很清楚：因為它不控制主視窗，主視窗還能動。
  修法是監聽主視窗的座標 Property，用**相對位移差**更新子視窗座標：
  「我們當前窗口的 x 座標加上 newValue 減去 oldValue」。
- **程式碼**：

  ```java
  // 讓提示框跟著主視窗一起移動
  primaryStage.xProperty().addListener((observable, oldValue, newValue) ->
          stage.setX(stage.getX() + newValue.doubleValue() - oldValue.doubleValue()));
  primaryStage.yProperty().addListener((observable, oldValue, newValue) ->
          stage.setY(stage.getY() + newValue.doubleValue() - oldValue.doubleValue()));
  ```

- **坑**：
  1. **Modal 與跟隨定位是取捨關係，不能同時免費取得**——要用 `WINDOW_MODAL` 讓主視窗不能動，
     就不會有這個問題；不設 Modal 讓主視窗能拖曳，就必須自己補 listener。
  2. **算的是相對位移不是絕對座標**：「就是我們主窗口新的座標減去我們主窗口老的座標，
     得到了它的一個偏移差。它向右偏……那麼這個偏移差就正的。它向左拉的話，這個偏移差是負的。」
     寫成絕對座標會跳動。
  3. **`newValue` / `oldValue` 是 `Number` 類型**，要 `.doubleValue()` 才能運算。
  4. **Property 綁定／監聽 API 只能作用在 FX 執行緒**。
  5. **不要在 `show` 的測試碼裡把 `primaryStage` 傳成 `null`**：畫面層記到過
     `Toast.showError(null, "测试");`，與本做法方向相反，筆記判斷是過渡期測試碼。
  6. **多視窗聯動已實測驗收**：「兩個、三個、四個，可以看到，它都是會所有的子窗口都會隨著一起
     一起去動，動這個 X 座標。」
  7. 畫面層另記到一條**口述從未提及的支線**：`primaryStage.showingProperty().addListener(...)`
     用來監聽視窗關閉以推進佇列。筆記判定為**被放棄的過渡嘗試**，不是本課最終實作。
- **相關**：見 W07-012、W07-013
